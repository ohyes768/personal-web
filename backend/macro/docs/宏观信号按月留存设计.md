# 宏观信号按月留存设计

> 状态：设计稿（待评审）
> 日期：2026-08-17
> 关联文档：[MACRO_SIGNAL_API.md](./MACRO_SIGNAL_API.md)、[数据字典.md](./数据字典.md)

---

## 1. 背景与问题

### 1.1 现状数据流

```
macro-fin-skill agent（每月跑 run_all.py）
  → POST /api/signal/upload ×6（X-Upload-Token 鉴权）
  → save_skill_json() 落盘 {DATA_DIR}/<skill>/<file>   ← 每次推送覆盖同一文件
  → GET /api/signal、/api/months 读这 6 份最新文件
  → 前端 MacroSignalTab 月份切换
```

### 1.2 问题

| # | 问题 | 根因 |
|---|------|------|
| P1 | 历史月份数据丢失 | `save_skill_json` 覆盖式写入，磁盘上永远只有最新一份 |
| P2 | `GET /api/months` 恒返回 1 个月 | 月份列表从 6 份最新文件的 `data_date` 推断，无历史来源 |
| P3 | 历史月查询 404 | `get_snapshot` 的 `any_match` 检查只可能命中最新数据所属月 |
| P4 | 前端月份切换形同虚设 | P2+P3 的直接后果——只有一个月可切 |

### 1.3 目标

- G1 agent 推送的数据**按月归档留存**，跨月推送不丢历史
- G2 `GET /api/signal?month=<历史月>` 返回该月真实快照
- G3 `GET /api/months` 返回全部留存月份
- G4 前端**零改动**（月份列表丰富后切换自然生效）
- G5 API 契约只增不改、旧数据零丢失（部署后首推自动迁移存量）
- G6 兼容本地开发（直读 macro-fin-skill 仓库、无归档目录的场景）

## 2. 存储结构设计

```
{MACRO_SIGNAL_DATA_DIR}/
├── monetary-policy-skill/macro_signal.json      # 平铺最新快照（保留，兼容层）
├── money-supply-skill/macro_signal.json
├── entity-economy-skill/macro_signal.json
├── inflation-skill/macro_signal.json
├── exchange-rate-skill/macro_signal.json
├── risk-appetite-skill/risk_data.json
└── archive/                                      # ★ 新增：按月归档（生产真源）
    ├── 2026-05/
    │   ├── monetary-policy-skill.json
    │   ├── money-supply-skill.json
    │   ├── entity-economy-skill.json
    │   ├── inflation-skill.json
    │   ├── exchange-rate-skill.json
    │   └── risk-appetite-skill.json
    └── 2026-06/
        └── ...
```

设计要点：

1. **归档文件名 = `<skill 目录名>.json`**（如 `monetary-policy-skill.json`），月目录内平铺一层，每个 skill 一个文件。skill 名来自现有白名单 `ALLOWED_SKILLS`，天然防路径穿越。
2. **平铺最新文件保留**，理由：
   - 本地开发直读 macro-fin-skill 仓库产出，该仓库无 archive 目录 → 兼容层保证行为不退化；
   - 已有部署/排查习惯、文档均基于该结构，不做破坏性变更。
3. **归档内容 = skill 原始 JSON 原样快照**（与推送 data 一致），不做格式转换——读取时的转换逻辑（`_convert_dimension_from_macro_signal` / `_convert_risk_appetite`）对最新文件和归档文件完全复用。

## 3. 写入流程改造（`save_skill_json`）

```
save_skill_json(skill, file, data):
  1. 白名单校验（skill ∈ ALLOWED_SKILLS、file ∈ ALLOWED_FILES）        ← 不变
  2. ★ 抢救归档：若平铺最新文件已存在
       读取旧内容 → 提取旧月份 m_old → 原子写 archive/<m_old>/<skill>.json
       （旧文件缺失/损坏/提取不到月份 → warning 跳过，不阻塞）
  3. 原子写平铺最新文件 {DATA_DIR}/<skill>/<file>                      ← 不变
  4. ★ 归档当月：提取本次 data 的月份 m_new → 原子写 archive/<m_new>/<skill>.json
       （提取失败 → warning 跳过；最新文件仍有效，接口不报错）
  5. 返回 (path, m_new)  → routes 层 clear_cache()                     ← 不变
```

**步骤 2（覆盖前抢救）是本设计的关键**，同时解决三件事：

| 场景 | 步骤 2 的作用 |
|------|--------------|
| 日常跨月推送（05 → 06） | 05 数据在被 06 覆盖前自动归档留存 |
| 部署本版本后 agent 首次推送 | NAS 上存量的 2026-05 手工推送数据自动迁移入归档，**无需迁移脚本** |
| 乱序/补推 | 各月数据各自归档到各自月目录，互不干扰 |

**步骤 4（当月归档）** 让归档目录始终包含当前月，读取逻辑统一以 archive 为准（见 §5），平铺文件退化为兼容层。

同月重复推送的幂等性：步骤 2 写入旧内容 → 步骤 4 覆盖为新内容 → 归档最终为本月最新，正确。

## 4. 归档月份提取

新增 `_extract_archive_month(skill, data) -> Optional[str]`，返回 `'YYYY-MM'`，失败返回 `None`：

| 数据类型 | 提取来源 |
|----------|----------|
| `macro_signal.json` | 顶层 `data_date` 前 7 位 |
| `risk_data.json` | `data.{volume,turnover,margin}.date` 三者取**最大值**的前 7 位（三子块正常同月，取最大保证确定性） |

统一校验 `^\d{4}-\d{2}$`，不合法视为提取失败（`None`）。

> 兜底说明：月份提取自 skill 自报的 `data_date`/`date`，这些字段在现有 skill 输出契约中必有；缺失说明 skill 输出异常，跳过归档仅写最新文件并 warning，不影响接口成功率。

---

## 5. 读取流程改造

### 5.1 `get_snapshot(month)`

```
1. ★ month 格式校验 ^\d{4}-\d{2}$                  ← 新增（month 将拼入路径，必须防穿越）
     非法 → 返回 None（HTTP 404）
2. ★ archive/<month>/ 目录存在 →
     逐 skill 读归档文件 → 复用现有转换函数组装 group
     （某 skill 归档缺失 → 该维度空 group，与现有「维度缺失」语义一致）
     → 返回 snapshot（缓存 key 不变：snapshot:<month>）
3. archive/<month>/ 不存在 → 现有逻辑兜底：
     读平铺最新 6 文件 + any_match 检查
     （覆盖场景：本地开发直读 skill 仓库；生产部署后尚未发生任何推送的存量月）
```

归档文件的 `analyzed_at` mtime 兜底逻辑不变——归档文件 mtime = 归档（推送）时间，语义正确。

### 5.2 `get_available_months()`

```
months = { archive/ 下子目录名（仅保留 ^\d{4}-\d{2}$ 合法者） }    ← 新增来源
       ∪ { 平铺最新 6 文件提取的月份（现有逻辑） }                  ← 保留（存量未归档月兜底）
降序返回
```

### 5.3 缓存

- 缓存 key、TTL（5 分钟）不变；归档读取结果同样入缓存。
- upload 成功后 `clear_cache()` 现有逻辑已覆盖归档场景，无需调整。

## 6. 安全

| 风险点 | 防护 |
|--------|------|
| `month` 参数路径穿越（`month=../../etc`） | §5.1 步骤 1 严格格式校验，非法直接 404 |
| 归档写入路径穿越 | 归档文件名仅由白名单 `ALLOWED_SKILLS` 成员 + 月份格式校验值拼接，无外部自由字符串 |
| 半写状态 | 所有写入复用现有 tmp + replace 原子写模式（抽取为 `_atomic_write_json(path, data)` 供三处复用） |
| 鉴权 | upload 接口 token 校验不变 |

## 7. API 变化

| 接口 | 变化 |
|------|------|
| `GET /api/macro/signal?month=` | 契约不变；行为增强（历史月返回 200） |
| `GET /api/macro/months` | 契约不变；行为增强（返回全部留存月份） |
| `POST /api/macro/signal/upload` | 请求不变；**响应新增 `archived_month` 字段**（本次归档到的月份，提取失败为 `null`），供 agent 推送后自检 |

upload 响应示例：

```json
{
  "success": true,
  "skill": "inflation-skill",
  "file": "macro_signal.json",
  "path": "/app/data/macro-signals/inflation-skill/macro_signal.json",
  "bytes": 1834,
  "archived_month": "2026-08"
}
```

**前端零改动**：`MacroSignalTab` 已按 `availableMonths` 渲染月份切换，月份增多后自动生效。

## 8. 场景与行为对照表

| 场景 | 行为 |
|------|------|
| 同月多次推送 | 归档覆盖（幂等），平铺最新文件覆盖 |
| 跨月推送（05 → 06） | 05 自动归档（步骤 2），06 写最新 + 归档（步骤 3/4） |
| 乱序推送（先 08 后 07） | 各自归档各自月目录；平铺最新文件以后推者为准（现状行为，不额外处理） |
| skill 输出缺 `data_date`/`date` | 仅写平铺最新文件，跳过归档 + warning |
| 归档月部分 skill 缺失 | 该维度空 group（「数据缺失」卡片态，现状语义） |
| 本地开发（skill 仓库无 archive） | §5.1 步骤 3 兜底，行为与现状完全一致 |
| 部署前 NAS 存量数据 | 首次推送时步骤 2 自动归档迁移 |
| 容量 | 每 skill JSON 数 KB × 6 × 12 月 ≈ 数百 KB/年，**默认永久保留**；预留可选配置 `macro_signal_archive_keep_months`（默认 0 = 不清理），本期不实现 |
| 日频 skill 日度推送（B 方案） | 同月重推幂等：当月归档与平铺最新文件每日覆盖，当月卡片自动跟进最新值；跨月首推时旧月最后一次推送自动定格为该月归档（步骤 2 抢救归档），历史月零丢失 |

## 11. 推送调度约定（B 方案，macro-fin-skill 侧）

按数据频率分层推送，后端按月留存机制天然兼容（同月重推幂等）：

| skill | 频率重 | 推送节奏 |
|-------|-------|----------|
| monetary-policy-skill（DR007 日频 + LPR/MLF 月频混合） | 日频 | 交易日盘后推送（B 方案改动对象） |
| exchange-rate-skill（美元指数/汇率/TED 全日频） | 日频 | 交易日盘后推送 |
| risk-appetite-skill（成交额/换手/融资余额全日频） | 日频 | 交易日盘后推送 |
| money-supply-skill（M2/社融月频） | 月频 | 月度推送（照旧，数据发布后） |
| entity-economy-skill（PMI/工业增加值等月频） | 月频 | 月度推送（照旧） |
| inflation-skill（CPI/PPI 月频） | 月频 | 月度推送（照旧） |

效果：当月卡片跟随每日推送显示最新日度值；历史月在跨月首推时自动定格为该月
最后一次推送的归档快照。日频指标历史月展示 `month_avg`（月均，见
MACRO_SIGNAL_API.md 契约），由 skill 在日度推送时随 `value` 一并输出。

**跨月口径注意**：归档月份提取以 `data_date` 为准。交易日盘后推送时
`data_date` 应为**当日**（而非前一交易日），否则 9 月 1 日推 8 月 31 日数据
会把读数归到 8 月归档、当月卡片反而不更新。

## 10. 验收标准

- [ ] AC1 本地连续推送 2 个不同月份的同一 skill JSON 后，`GET /api/months` 返回 2 个月（降序）
- [ ] AC2 两个月份分别 `GET /api/signal?month=` 均返回 200，且 conclusion/details 为各自月份的真实数据
- [ ] AC3 同月重复推送 → 归档文件内容更新为最新一次，`months` 数量不变（幂等）
- [ ] AC4 `month=../../etc` 等非法格式返回 404，不触碰文件系统
- [ ] AC5 预置平铺存量文件（无 archive）→ 首次推送另一月数据后，存量月自动出现在 `months` 并可查询（自动迁移）
- [ ] AC6 upload 响应含正确的 `archived_month`
- [ ] AC7 线上部署 + agent 推送后，前端月份切换可浏览历史月卡片（前端无代码改动）
