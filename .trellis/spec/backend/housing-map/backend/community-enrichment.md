# New residential projects and source enrichment

> After explicit `tmsf-directory-v1` migration, [TMSF directory workflow](./directory-flow.md) supersedes multi-source admission/review and defines task eligibility. Stored history and pre-migration behavior remain readable.


## 1. Scope / Trigger
Use for `tmsf_property_type`, `community_enrichment`, directory collection, residential classification, map coordinates, price isolation and management source details. Existing newhouse projects are eligible residential candidates even without ESF listings; this does not promise discovery of every new project.

## 2. Signatures
- `fetch_community_facts(client, community_id, names, *, timeout=15)` validates ESF name identity and extracts type, actual address, separately observed `address_district` and listing count.
- `parse_project_index(script)`, `find_project(rows,names,district)`, `project_identity(project)`, `fetch_project_facts(client,names,district,*,projects=None,timeout=15)` read the public project index and independently validate newhouse detail.
- `fetch_property_facts(...)` remains the CLI-compatible ESF-first/newhouse-fallback wrapper.
- `enrich_source(store,data_dir,rid,*,tmsf_client=None,amap_client=None)` repairs one unignored TMSF source. POST `/api/directory/sources/{rid}/enrich` (external `/api/map/directory/...`) accepts no body and returns `success/data={source_id,errors,updated_at}`.
- Evidence is additive JSON in existing source payloads; no table migration or startup network calls. `source_enrichment` records the update and per-stage errors.

## 3. Contracts
- ESF IDs and newhouse project IDs are independent. Match the public `data_auto` index using complete marketing/legal aliases (explicit parentheses), same district, and one unique project; preserve phase suffixes. Store project ID/name/aliases and source URLs. Never splice an ESF ID into a newhouse URL.
- Project identity evidence from the index establishes `market_state=new_house` only for explicit 在售/尾盘/待售 status; 售完 is second_hand and unknown status grants no newhouse exemption; it cannot establish residential use. Newhouse details must independently match name/district and provide explicit property type plus actual address. WAF/challenge/wrong-project/ambiguous/missing fields are errors, never empty successful facts.
- Save `market_state_url`, `market_state_captured_at`, `project_sale_status`, optional `project_property_type` and its URL independently of ESF type. Sold-out projects retain project metadata but use second-hand market classification and listing thresholds. `effective_market_state` also corrects legacy sold-out/new_house payloads at read time, without rewriting historical decisions. Unknown market evidence stays unknown; zero ESF listings alone never establishes newhouse identity. A confirmed project identity survives a later lookup failure.
- Collection falls back to newhouse on ESF failure. Low ESF listings also trigger project identity lookup, so a project with an ESF page and zero listings is not misclassified. Cache the project index once per collection, retain pauses/cancellation/ignored checks. Only effective newhouse identities retain the existing 30-day type/address cache; sold-out legacy entries must refresh; ESF listing counts must still follow the listing-threshold freshness contract.
- Failed type attempts retain the last effective property type and expose `property_type_error`. Historical standalone facts are copied by enrichment using the TMSF source ID, never a local master ID. Explicit mixed/unknown/conflicting types remain pending. Simultaneously conflicting ESF/project types save both facts and `property_type_conflict=true`; a failed project refresh cannot erase a prior conflict.
- Historical addresses come only from same-ID/name TMSF snapshot metadata, independently of the snapshot's price eligibility. Geocoder `formatted_address` is geographic context, not actual-address evidence. History coordinates require same source ID/name, district, finite GCJ02 values and shared coverage checks. Label their provenance `historical_amap`; do not claim fresh POI verification.
- If position is absent, make one bounded Amap text query. Keep exact complete name/alias, district, residential-area category and shared boundary; exclude sale offices, entrances and attached buildings. Known different actual addresses veto matching. Multiple candidates/truncation/transport failure remain explained manual-review issues. Never expose keys or secret-bearing URLs.
- Network requests precede the registry writer transaction. Compare the complete source record before publication; changed/ignored/unlinked records reject stale results. Reuse `_correct_source_address` so only marked legacy geocoder master addresses are corrected; manual edits, admission locks, exclusions and associations stay intact. Source enrichment never auto-admits or enables automatic review.
- `community_views` can project coordinates from current matched sources when master coordinates are absent; invalid/conflicting positions yield `check_coordinates`, not arbitrary or fabricated coordinates. An actual street address with separately parsed matching district can qualify map address validation. `load_coordinates` uses the same projection, avoiding directory/map disagreement after creation of a local master.
- Market state, residential admission and map status are separate UI fields. `new_house` requires an explicit 在售/尾盘/待售 project status; a historical project record alone does not qualify. Missing coordinates do not prevent directory admission. Show project/coordinate provenance and preserve partial-failure notices after the action closes the panel.
- Newhouse prices (`market_state=new_house` or a `/newhouse/` source URL) cannot enter ESF price metrics even with an ESF-looking price type. Keep historical ESF prices as ESF; do not rewrite them just because a community has project evidence. This task adds no newhouse price collection.
- Automatic rule is `community-auto-v5`; old enablement requires a fresh preview/re-enable. Snapshots and admission evidence include project identity, district, type and coordinate provenance. Verified newhouse sources are exempt from the separate ESF listing threshold.

## 4. Validation & Error Matrix
Unknown/ignored/non-TMSF/out-of-scope source or stale publication returns409. SQLite/filesystem failures use503. Upstream stage failures return200 with `data.errors` and saved per-source notices; successfully obtained evidence remains usable. Property conflicts remain pending; manual admissions stay authoritative with a conflict warning. Corrupt local files are not silently replaced with empty evidence.

## 5. Good / Base / Bad Cases
Good: ESF `3017629894` → public alias index identifies project `2313460053` → proven residential type + real street + matching historical GCJ02 position → review → map. Base: project page challenge → identity and previous valid use retained, error visible; no coordinates → directory entry remains, map hides it. Bad: use a project name alone as residential-use evidence, merge phases by substring, apply zero-listing ESF exclusion to a confirmed newhouse source, or treat BD09 map values as GCJ02.

## 7. Wrong vs Correct
Wrong: `property_33_{community_id}_infoUpgrade.htm` or infer newhouse from `listing_count==0`. Correct: resolve independently through the public index, preserve its evidence, and separately verify residential use. Wrong: a failed request clears previous residential evidence. Correct: retain the last fact, record the failed attempt, and reserve pending for missing/ambiguous/conflicting use.
