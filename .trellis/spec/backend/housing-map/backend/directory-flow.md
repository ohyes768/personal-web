# TMSF directory and independent collection workflow

For explicitly activated collection-pipeline-v2 instances, [the unified pipeline contract](./collection-pipeline.md) supersedes the v1 admission-before-position order and independent text-search use review below. Unmigrated instances retain this document's v1 behavior.

## Scope and rollout
The new management page is DirectoryFlowWorkspace. `directory_flow_version=tmsf-directory-v1` in registry meta is an explicit migration boundary, not a user-configurable auto-review toggle. Until offline migration is applied, the new page reports inactive and disables its tasks; existing map/admission behavior remains unchanged. Never silently enable this flag on startup, ordinary GETs, or a deployment. The old multi-source review implementation remains for historical records and pre-migration reads; its decision/auto-execute paths reject writes after activation.

## Single qualification rule
`directory_policy.eligibility(master,records,facts,admission)` is pure. Use current effective TMSF sources and same-ID legacy property facts only; Fang rental types and auction titles never admit/veto residential use. Amap categories are a second source of evidence: they may raise a pending-review conflict (`use_conflict`/`use_uncertain`, incomplete) and support a human confirmation, but they never admit or exclude a community by themselves — see [Amap use-category review](./use-review.md). Require reliable full-name/alias and district, explicit residential type, actual address (geocoder address cannot qualify; under `admission_address_policy=amap-subject-address-v1` the shared `admission_address` projection may also qualify via a reliable same-district Amap subject address — see [admission contract](./community-admission.md)), and valid ESF listing gate (0..2 excluded, unknown/error incomplete, >=3 eligible). Proven newhouse evidence retains its listing exemption. No coordinates are needed for catalog admission.
Return `admission_state=admitted|excluded`, `qualification` reason code, `exclusion_reason`, `facts_state=complete|incomplete` and effective type. Manual exclusions/review locks and deleted/merged masters remain authoritative. Do not rewrite stored migration/manual admissions merely to refresh this projection. Preserve old initialization reasons in events/admission history, never use them as business reasons.
`directory_workflow.synchronize` materializes only eligible unbound TMSF sources with no identity duplicate, manual candidate lock or rejected association. New master IDs are deterministic local UUIDs from source identity/rule. Existing source/master IDs, names and rejected pairs are retained. Incomplete/unbound TMSF entries appear as virtual source rows in catalog; non-TMSF orphans remain historical and belong to their own business queues.
All map views, rental start/discovery/publication membership and auction associations use current eligibility after activation. Never use source status=matched alone as residential admission. Legacy manual-admit and source-create APIs must not bypass the new rule.

## APIs
External prefix `/api/map`, backend `/api`; all return success/data. New base `/directory/workflow`:
- GET `/summary?q&district` → active/admitted/excluded/auction_pending. Inactive is readable; other new endpoints reject409 until migration.
- GET `/catalog?state=admitted|excluded&q&district&page&page_size&market&property_type&use&operation` → items,total,page,property_types; page>=1,size<=100. Market is empty/new_house/second_hand; property_type matches exact current TMSF uses (same-ID legacy type fallback only before any attempt), `__missing__` selects absent use facts. `use` is the Amap use-review perspective: conflict/uncertain/pending_retry/agree/none/skipped. `operation` is empty or `position|use|facts`; unknown values are 422. It keeps only `workflow_state=pending` rows whose `pending_operation_bucket` matches, before total and pagination. property_types lists available uses for the state/search/district before classification/position/operation filtering and paging. Market/use/position/operation filters all apply before total and pagination. Admitted UI shows 全部/新房/二手房; excluded UI shows actual use choices plus common 住宅/其他/写字楼 and 用途资料缺失. The pending tab sends operation instead of property_type/position. Changing filters resets page1; filters affect browsing only, not admission or collection targets.
- GET `/catalog/{cid}` → full catalog row, sources without raw rental samples, historical events.
- POST `/catalog/{cid}/retry` → TMSF-only evidence update, errors and reclassification; never calls Amap. Refuses active directory collection; full-source stale publish check remains in enrich_source.
- GET/POST/DELETE `/positions` → persistent high-level job/start202/cancel. Error or conflicting startup409, storage503. Status may be null before first run.
- GET `/auctions?q&include_skipped&page&page_size` → source-level unresolved Laipai assets/rounds, fingerprint revision, currently eligible suggestions and source links. Includes matched sources whose targets lost eligibility; historical associations are not destroyed.
- POST `/auctions/{rid}` `{revision:sha256,action:bind|skip|reopen,community_id?}`: verify source and target inside one writer transaction. Bind only to a current admitted target; no master creation or residential-use mutation. Skip metadata stores source fingerprint, changed evidence reopens it. Same-source stale revision409; deleted/ignored records are absent.

## Five jobs / UI
TMSF `/directory/collection` remains a single-source job; its completion calls synchronize instead of old auto-review after activation. High-level independent buttons also call existing `/rentals/refresh` and `/auctions/refresh`, so header and management share task state and locks. Amap batch owns `/directory/workflow/positions`, not `/directory/collection` or a polygon scan. The Amap use-category review owns `/directory/workflow/use-reviews`: it reviews every catalog community with TMSF data, produces conflicts for human review and never admits or excludes on its own (see [Amap use-category review](./use-review.md)).
PositionJob snapshots current admitted IDs, queries pending/error POI states and skips matched/manual/review/not_found states (see [position status](./directory-position.md)); historical coordinates alone do not complete POI matching, lazily creates its client, limits256 name requests with2s pauses, reports per-target ambiguity/errors and budget truncation, supports cancel/restart-interrupted/shutdown. Network work precedes DB transaction; compare complete master/source/admission snapshot and recheck eligibility before publishing. Cancellation after HTTP response must prevent write. Store POI ID/url/time/GCJ02 coordinates and geographic_address separately from actual address. Automatic queries preserve manual edits, other valid coordinates and associations; explicit human position confirmation may replace coordinates. Empty/all-positioned runs need no upstream key or requests.
Job units remain distinct: TMSF source counts, Amap processed/total targets, use-review updated/conflict/not_found/uncertain/error/skipped counts plus the request count, rental processed_communities/total_communities and nested errors, auction scanned/returned records. Frontend normalizes shapes; task completion invalidates catalog even for short runs. Same page has admitted/excluded/auction-association tabs and independent rental review section. Excluded distinguishes missing facts from failed conditions; it has retry and a controlled manual-use confirmation (residential type or a non-residential reason required; evidence link optional, audited, never overwritten by a refresh). Auction target search only returns admitted catalog entries, permits skip/reopen and never creates a residential master.

## Offline migration
CLI: `scripts/migrate_directory_flow.py --data-dir ... --plan ... --action preview|apply|rollback` (preview default). Keep plan/backup outside data-dir. Preview opens SQLite mode=ro, backs up into memory, hashes all business tables/schema and JSON/JSONL/GeoJSON/other SQLite files, then simulates materialization/projection in memory only. No prepare_directory or write-refresh on production. Reports old/new states, actual reasons, manual conflicts/protection, source identities, map changes and rental/auction association impact, including historical-only non-TMSF masters hidden from catalog.
Apply requires `--maintenance` (operator has stopped backend, schedulers and CLI writers), matching reviewed snapshot/rule, no active persisted directory/position/rental task, and a new external backup directory. Back up registry with SQLite backup API and business files/other SQLite DBs, recheck file fingerprints, then activate the flow, disable old auto-review and materialize identities in one writer transaction. Do not clear events, old admission reasons, price/rental snapshots, auction rounds, rejects/deletions or other source associations. A second preview+apply is idempotent.
Receipt contains after_snapshot. Offline rollback restores registry tables transactionally only if DB and files still match that receipt; refuse whole-DB rollback after any new writes, requiring directed audit recovery instead. Migration does not change business files, so historical files need no replay on rollback. Never apply/rollback against production without user approval of its concrete plan.

## Newhouse independent discovery (2026-10-23)
`directory_collection.tmsf_names` appends an independent newhouse pass after the ESF name loop. It scans the public `data_auto` index for 滨江 projects with propertystateid 在售/尾盘/待售 only (sold-out projects keep being tracked through their existing community entries); a project whose any name/alias hits the current discovered list or an existing tmsf community source is skipped — those keep flowing through the existing enrichment fallback. Candidates are stored as `source_kind='project'` with `sid=propertyid`; ESF and project sources sharing a numeric ID stay isolated because the collection `existing` cache is keyed by `(source_kind, source_id)` and every legacy-fact fallback (eligibility, effective_type, classify_sources, catalog_property_types, source_view, review member facts, historical_evidence) skips project sources. The name row publishes before its detail; a failed detail never drops the candidate and records a coded error (`challenge`/`identity_mismatch`/`missing_facts` via `ProjectDetailError`, transport type name otherwise). Details fetch directly by `fetch_project_facts_by_id(siteid, propertyid)` — never an ESF URL — and a 30-day cache requires property type plus a complete address with no errors. A truncated (ellipsis) address never lands on the row: it records `address_error`, leaves `address_checked_at` unset, and stays 资料待补 per Q1. `enrich_source` on a project source uses the same direct path with no Amap position work. `listing_gate` exempts stored `new_house` evidence (write paths are already gated); sold-out falls back to ESF rules through `effective_market_state`, and project sources without listing fields never contribute unknown counts. `community_views` projects `new_house` when any record proves it (conflict flag preserved), source-only inventory rows carry `market_state`, and the price refresh target check matches `source_kind='community'` only. Disabling conditions: an index failure yields an errors-only row (stage `newhouse_index`) without failing the TMSF run. Tests: `test_newhouse_collection.py` covers discovery, idempotence/ignore/cache, numeric-ID isolation, truncation, gate exemption, mixed-market projection, materialization, project enrich and refresh isolation; live read-only probe in `scripts/verify_newhouse_live.py` (index OK over HTTP, detail pages challenge → browser worker required).

## Catalog data coverage (2026-10-19)

### Scope / Trigger
Admitted management rows show data coverage. Keep the read-only projection in `directory_coverage.attach_coverage`, called only by catalog/detail routes, outside inventory/admitted to avoid recursive business membership queries.

### Signatures
`GET /catalog` adds `auction=''|has|none`, `rental=''|data|pending|unmapped|source_missing|no_samples|failed`. Apply to admitted rows before total/paging; excluded rows ignore these filters. Detail adds `auction_records` (whitelisted public facts, no full upstream announcement).

### Contracts
`coverage.auction={property_count,round_count,unidentified_round_count}` counts all statuses and dates under current registry associations. Same source+asset counts once; missing asset only counts unidentified rounds, never a known property. Current asset decision precedes round decision; ignored on either identity vetoes. No name guessing or persisted old community_id fallback. `auction=has` includes unidentified rounds.

`coverage.rental={state,sample_count,captured_at,stale,update_failed,error}` uses shared select_valid and is_stale. Match published snapshots to the current matched Fang source ID, including legacy community IDs with that same source. No mapping/rebound old source means no current samples. Data with valid samples takes precedence over latest error. Empty published snapshot is no_samples; mapped but unpublished is pending. Review needs_selection/skipped→unmapped, missing→source_missing, search_failed→failed, no review/deferred→pending. Only job errors for this community with job.started_at >= source.associated_at can mark a mapped source failed; never assign a whole-job failure to every community.

### Validation / Error Matrix
Invalid filter→422. Business read errors propagate through the existing directory result envelope rather than fabricate zero. Existing load_current corruption fallback remains unchanged. Missing coverage on old frontend payloads displays 状态未知. No admission/collection/association mutation on GET.

### Good / Base / Bad
Good: two rounds of asset A count one property; old valid rentals plus per-community failure remain data with update_failed. Base: no snapshot is pending, a verified empty snapshot is no_samples. Bad: count rounds as 套, use another source's snapshot after rebinding, or label all communities failed from global job status.

### Tests Required
test_directory_flow covers actual registry + raw rounds + publish_run, sample dedup/exclusion, legacy ID source reuse, rebinding isolation, review states and filtered paging/422. directory-flow.test.cjs covers SSR columns, missing coverage, failed/stale alongside data, escaped public records and safe links. Browser checks use intercepted examples on desktop/390px, page2→filter page1, combined filters, detail and excluded tab.

### Wrong vs Correct
Wrong: `property_count=len(auction_rounds)` or `sample_count=source.sample_count`. Correct: unique known asset identity; missing-asset rounds separate; rental count from select_valid on the current confirmed source snapshot.

## Failed-only collection retry (2026-10-27)

### Scope / Trigger
TMSF source collection controls distinguish whole-directory updates from repairing failed existing identities. Reuse the existing DirectoryJob and completion classification pipeline.

### Signatures
POST `/directory/collection` accepts `mode: 'all' | 'retry_failed'` (default `all`) beside existing `sources: ['tmsf']`. GET returns job state with `retryable: number`; before the first run it returns `{running:false,phase:'idle',retryable:N}`. Reports persist `mode`.

### Contracts
`retryable_sources(records)` counts unignored Binjiang TMSF community/project identities whose `source_collection_state.collection_resolution` is retryable, once per identity: current property_type/listing_count/market_state transport errors, plus address errors only for community-kind second-hand records. New-house/project `address_pending` (basic mode skips the certificate/address page via `supplement_address=False`, so no request is issued and missing address is not a transport failure) resolves to `position_pending`; `identity_mismatch`/`invalid_target` resolve to `identity_conflict` and `missing_facts` to `facts_pending` — none of them are browser-retry targets; literal non-residential types resolve to `non_residential` and stop address supplements. The per-identity `collection_error_code` persists alongside historical error text for deterministic resolution; legacy `address_error` stays diagnostic only. Counts derive from current durable source facts, surviving restart, ignore and individual corrections. Retry bypasses the 30-day cache, reconstructs known identities from stored sources and never scans name lists or discovers projects. A community detail fallback may fetch the shared newhouse index; known project details use their stored siteid/propertyid directly. Keep community/project kinds isolated even for equal numeric IDs. Retain aliases, source identity and valid prior facts; success clears corresponding errors, failure/cancellation retains retry eligibility. The collection report carries per-stage resolutions (`ready`/`position_pending`/`identity_conflict`/`retryable`/`non_residential`/`facts_pending`, summing to processed new-house identities) plus `evidence_issues` for identity review; on success `after_collect` starts the shared singleton PositionJob followup for fact-changed candidates instead of a second Amap job. No new admission behavior.

### Validation & Error Matrix
Unknown mode ->422 at API / ValueError for direct service use. Retry of unsupported source list ->ValueError. Empty retry ->409 before report mutation/thread creation. Running full/retry job ->409 via the shared worker lock. Storage errors ->503. Detail errors ->partial_failed, cancellation ->cancelled, preserving old successful facts. Source-level discovery errors without a known identity require whole-directory update, not failed-only retry.

### Good / Base / Bad
Good: 3 failures among 200 successful sources ->3 detail targets and no name-list request. Base: a target fails again ->prior facts and error remain available after restart. Bad: retry all 203 details, infer failures from the latest report only, or count multiple errors on one identity multiple times.

### Tests Required
`test_directory_collection.py`: actual DirectoryJob mode forwarding, no discovery/healthy-source requests, same-ID kind separation, ignored/other-source/unattempted preservation, successful error clearing, repeat failure, cancellation, restart counts and empty/invalid start rejection. `test_directory_api.py`: default mode compatibility, retry mode/422, durable counts and empty409. Frontend directory-flow tests: button action payload, counts, disabled conditions and stop wording; desktop/mobile preview checks wrapping without overflow.

### Wrong vs Correct
Wrong: count `last_report.errors` and call the normal full collection endpoint again. Correct: derive current failed source identities from persisted facts and pass `mode='retry_failed'` through the existing shared job.

## Unified manual pending workspace (2026-10-30)

### Scope / Trigger
Management consolidates admission, rental-source exceptions and auction associations into 已收录 / 待处理 / 不收录. This supersedes the separate rental and auction navigation above; stored business states and original mutation endpoints stay unchanged.

### Signatures
GET `/directory/workflow/pending?q&district&kind&rental_status&include_skipped&operation&use&page&page_size` returns `items,total,page,page_size,counts,default_pending_total`. `kind=''|admission|auction|rental`; `rental_status=''|needs_selection|search_failed|missing|skipped`; operation/use use catalog enums. Summary adds `unified_pending`; existing `pending` retains its pipeline meaning.

### Contracts
`directory_pending.project/load/query` is read-only. Rows use `community:<community_id>` for identified communities and `auction:<source_record_id>` for unresolved assets (including stale old target associations). Never merge by name. Each row has name/address/district and independently actionable issues. Rental defaults include needs_selection/search_failed and only proven homepage_not_found for missing: legacy source_reviews labels an idle/unqueried probe as missing, which must not inflate this manual queue. Deferred/running/unqueried work stays in collection tasks. Skipped issues are hidden by default and opt-in through include_skipped.
Search/region filter before counts; counts are per-kind row counts before kind/status/operation/use and paging; all deduplicates identities and need not equal the category sum. `default_pending_total` is global, independent of temporary search/region/include_skipped. Filter issues before sorting and 30-row paging; stable sort uses priority/name/key. Clamp out-of-range pages. No known district means only all-region searches include that asset. Hidden operation/use filters do not affect other kinds. Non-pipeline instances still expose rental/auction work after directory activation.
Frontend keeps a single filter toolbar and reusable dialogs. `initialSource=laipai` opens pending with kind=auction. Rental skip/reopen reuse the association API; homepage confirmation uses XingfuliProbe, never the retired bind endpoint. Mutation success and task completion refresh rows/counts; a row with remaining issues stays visible. Mobile uses existing review-table card CSS.

### Validation & Error Matrix
Inactive directory →409 for pending, readable inactive summary. Invalid kind/status/filter/page or page_size>100 →422. Registry read failures use the existing directory error envelope, not a fabricated empty list. Writes retain original revision and refresh/edit exclusion checks.

### Good / Base / Bad Cases
Good: one community with two issues is one row with two operations. Base: an unassociated auction remains a separate source record. Bad: joining similarly named sources, adding already paged lists, counting idle rental probes as missing, or treating rental work as an admission change.

### Tests Required
`test_directory_pending.py`: real API activation/validation, identity separation, remaining issues, skip exclusion, deferred exclusion, stable multi-page ordering, districts and idle-vs-not-found projection. Frontend `pending-workspace.test.cjs`, catalog-filters and community-review assert three navigation entries, dropdown-based filtering, independent row actions and Laipai entry. Desktop/390px browser QA uses disposable fixtures; never send live collection requests just to check layout.

### Wrong vs Correct
Wrong: `catalog_page + rental_page + auction_page`, then count; `missing` always means searched-and-not-found. Correct: load complete current projections, require stored not-found evidence, group by verified identity, filter/sort and then paginate.
