# 宽基趋势观察：技术设计草案

状态：planning。以prd.md为需求来源，未进入实现。

## 1. 当前方案与旧草案差异

此前study草案默认当前页面沿用最后一个固定步进窗口（2014-04—2024-03），用户随后提出“回溯+当前页，并在当前页选择成立以来/近10年”。本任务按后一方案设计：

- 历史：固定120月/36月步进，另加全样本总览。
- 当前：`trailing_120m`与`since_inception`两模型，随完整月份月度重算。
- 不把两种“10年”混为同一个模型；旧草案不能直接当作本任务当前页的实现依据。
- 页面临时选项与周报持久配置分开。

## 2. 集成边界与现有规范

- 建议前端`apps/index-trends`，包名`index-trends-frontend`；后端`backend/index-trends`，FastAPI+uv。
- 遵守 `.trellis/spec/guides/new-service-onboarding.md`：默认纯前端无BFF，页面basePath `/index-trends`；外部API `/api/index-trends/*` 经Nginx/rewrite转内部 `/api/*`。
- 新端口须检查当前Compose/Nginx，不能照旧文档“下一个3008/8097”直接占用。
- 接入包括导航、Nginx静态/页面/API、Compose服务与卷、deploy-nas.sh映射、开发启动脚本和部署文档。不能只建业务目录。
- 不直接跨进程导入其他后端内部包。调度和钉钉复用已有实现模式，字段、错误处理和生命周期按项目规范落位。
- 后端新目录是否独立子仓库应按当前仓库实际布局确认，不在建任务时创建子仓库或注册错误的default_package。

## 3. 数据与计算

数据适配器统一输出字符串指数代码、交易日期与OHLC。主月K来自腾讯，新浪日线可用于周收盘及交叉检查；供应商来源、获取时间和哈希保存为快照。
先验证日期唯一、月份连续、完整月截止和OHLC，再计算模型。

算法版本`lrc-ltb-port-v1`：等间距月份x，月收盘y，OLS中线a+b*x；deviation为`sqrt(mean((y-(a+b*(x+1)))**2))`，上下轨为中线±2*deviation。
当前图保留公开移植公式的前移一根K线细节；如改为标准残差RMSE，必须另升算法版本并展示差异。
纯计算层不依赖网络、FastAPI、trendln或ZigZag。

模型种类：

| key | 训练范围 | 更新 |
|---|---|---|
| historical_fixed_120m | 从2005-04起120月窗口，36月步进 | 新完整窗口出现后增加，不覆盖旧窗口 |
| trailing_120m | 最近120个完整月 | 新完整月到来后生成新版本 |
| since_inception | 2005-04至最近完整月 | 新完整月到来后生成新版本 |

模型ID至少包含指数、种类、训练起止、算法版本和数据哈希。历史周报保留原模型ID。
全历史回溯和当前成立以来模型在同一数据版本/截止月份时复用模型，避免重复且不一致的计算。

当前未完成月份的轨道按所属自然月整数序号投影，保持本月参考值稳定；月内只更新收盘位置。拟合与图展示的时间坐标口径要一致。

## 4. 页面与交互

建议查询状态：`tab=history|current`、历史`window=<stable-id>|all`、当前`model=trailing_120m|since_inception`。选项是否放URL及具体命名在实施时遵循项目路由习惯；刷新和返回不能悄悄换图。

历史Tab：选择器→区间说明→主图→拟合/后续观察说明。桌面展示紧凑窗口选择，移动端下拉或横向可滚动选择；默认一次一图。并排比较为可选增强，先不阻塞核心切换。

当前Tab：模型切换→收盘/区域/位置摘要→主图→上下轨与模型信息→每周提醒配置和历史入口。临时切换无需触发任务，也不写周报模型。
推荐ECharts，先检查macro等现有组件；复用日期、tooltip、懒加载与resize处理，不能直接照搬仅注册LineChart的组件而假定已支持CandlestickChart。
无数据、缺完整120月、供应商失败、过期快照、图表失败分别展示；旧数据可读但明确日期。

不把图表的显示范围选择当作训练范围；dataZoom只缩放画面，不重新拟合。

## 5. 后端合同

建议内部 `/api` 路由，外部前缀由项目标准映射：

- GET indices：支持指数及可用模型。
- GET indices/000300/history：固定窗口和全历史元数据。
- GET indices/000300/chart：按模型ID返回价格、轨道、拟合边界与观察区。
- GET indices/000300/status：按选定当前模型返回最近收盘和区域。
- GET/PATCH report-settings：独立周报模型/时间/启用状态，密钥不回传。
- GET reports：可追溯周报和发送状态。
- POST refresh/report jobs：按现有任务与互斥规范运行，GET不能发消息。

字段含`price_as_of`、`data_cutoff_month`、`fit_start/end`、`model_id`、`model_kind`、`algorithm_version`、`upper/mid/lower`、`position_pct`、`region`、`calculated_at`、数据新鲜度状态。
模型/数据日期必须参与缓存键，切Tab/模型不能读取另一模型的轨道。

建议SQLite保存快照索引、模型、报告配置、周报和发送记录，原始大快照可落后端持久卷。最终存储约定应在实施前同现有服务对齐。

## 6. 每周摘要与运维

建议周五19:00 Asia/Shanghai，每周都发；周报模型使用持久化配置，默认近10年尚待用户确认。
周五休市取当周最后交易日；整周休市明确无新交易；缺少应有收盘则异常摘要而非伪新数据。
周报先解析所选模型版本，再生成位置和摘要；同一条报告所有轨道、区域、日期来自同一原子快照。
月度新模型造成区域变化要与价格涨跌区分。展示前后周位置时注明模型是否改变。
发送幂等键建议指数+自然周+报告类型，模型切换/刷新不自动多发同一周报告；显式修订或人工重发必须有独立审计字段。
APScheduler沿用3.x、Asia/Shanghai、单实例执行、显式weekday名。手动刷新与计划任务共用锁；关闭遵守有界drain规范，不假定shutdown(wait=True)足以等待全部工作。
推送渠道未配置时保存报告并显示未配置，不发送；实际目标待确认。密钥不写任务材料、前端或Git。
