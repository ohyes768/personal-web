# service-manager 标签体系：可维护可筛选

## 目标

让 NAS 服务管理台的**标签**像 skill-manager 那样真正能用起来：每条服务能就地打标签（勾选现成的、或新造一个），列表页能按标签一键筛选，快速定位「哪些是同一类东西」。

## 背景

- service-manager 后端早就有 `services.tags`（JSON 数组），也能按单个 tag 过滤、能搜到标签；但**前端从没给过任何交互**——列表页只把标签渲染成一行纯文本，详情页要手打逗号分隔字符串才能改。
- skill-manager 已经跑通一整套标签体系（候选并集、药丸多选筛选、卡片铅笔弹窗编辑），本任务照搬它的**交互形态**，落到 service-manager 的台账上。
- 台账里另两个正交字段：`ownership`（我维护的 / 别人的，决定列表分组）**保留不动**；`category`（单选大类）**本轮退役**，语义全部并入标签。

## 需求

| ID | 需求 |
|----|------|
| R1 标签看得见 | 列表页每条服务显示自己的标签（药丸样式），一眼能看出这条被怎么分类过 |
| R2 标签能维护 | 列表页每条服务旁有「编辑标签」入口：弹窗里勾选已有标签 + 输入框新建标签，保存即生效，不用进详情页 |
| R3 标签能筛选 | 列表页工具栏有一排标签药丸，点一下选中/取消；选中后列表只保留**同时具备全部选中标签**的服务 |
| R4 词表统一 | 可勾选的候选来自**全库标签并集**（外加本条已有与当前选中），避免同一个意思写成两种词 |
| R5 详情页一致 | 详情页能看到标签并能改；现有「编辑信息」表单里的标签字段保留可用 |
| R6 一键清空 | 筛选栏能一键清空全部标签筛选 |
| R7 边界不动 | 标签只影响**筛选与展示**：不改归属分组、不改任何检查口径、不碰 Docker 只读边界；不新增后端写 Docker 的路径 |
| R8 分类退役 | `category`（分类）**下线**：<br>① 现有 24 条服务的分类值（工具 9 / 生活 6 / 金融 5 / 内容 3 / 媒体 1）**转成标签**，信息不丢；<br>② 界面上不再有「分类」入口——列表页的「全部分类」下拉、详情页的分类输入框、发现导入的分类输入框全部移除；<br>③ 后端不再接受也不再返回 `category`，人工表里该列退役 |

## 不在范围

- 独立标签表、标签重命名 / 合并 / 删除、标签使用计数与「孤儿标签」清理
- 筛选状态进 URL（分享链接时带上筛选）
- 标签层级 / 前缀体系（如 `infra/db`、`media/reader`）
- 分类的**反向恢复**（退役后若要恢复分类，只能从标签里人工挑出来重建）

## 约束

- **复用现有 `services.tags` 字段**，不引入新表、不改标签数据模型（归属 `ownership` 已在本轮刚落地，不再加第三个维度）
- 沿用既有标签契约：单个标签 ≤32 字符、每条服务 ≤20 个、后端 PATCH 为**全量替换**语义
- 候选标签在前端算（列表已整份拉回，`page_size=100`），不新增「标签字典」接口
- 多标签筛选语义与 skill-manager 保持一致：**AND**（同时具备）；筛选在**前端**做
- 标签保存时**去重 + 按字典序排序**（与 skill-manager 一致）
- **分类退役的不可逆性**：删除 `services.category` 列后，原分类值只以标签形式存在（可从标签反推，但不再是独立字段）。迁移必须**先转标签、后删列**，中途失败不得丢数据
- 375px 视口不得出现横向滚动；键盘可达；状态变化要有文字说明，不能只靠颜色
- 后端是 Docker 只读 + 人工表两层，标签属于人工表，**不产生任何 Docker 写操作**

| ID | 可验证结果 | 关联需求 |
|----|------------|----------|

| A2 | 点「编辑标签」弹出弹窗：已有标签点一下可勾选/取消，输入新标签回车或点「添加」可加入；重复标签、空白、超长都有明确提示 | R2 R4 |
| A3 | 弹窗保存后列表页该行的标签立即更新，无需刷新页面 | R2 |
| A4 | 工具栏出现全库标签药丸；点选后列表只剩同时具备全部选中标签的服务；再点取消即恢复 | R3 |
| A5 | 「清除标签」一键回到未筛选状态；筛选与搜索、分类、归属分组叠加时行为符合预期（互相不打架） | R3 R6 |
| A6 | 候选标签 = 全库并集 ∪ 本条已有 ∪ 当前选中；库里没有标签时筛选栏不出现空药丸 | R4 |
| A7 | 详情页能显示并修改标签，改完列表页同步可见 | R5 |
| A8 | 标签改动只写人工表：Docker 容器不受影响；服务的运行 / 健康 / URL / 证书 / 发布五个状态维度口径完全不变 | R7 |
| A9 | 375px 下列表页、详情页无横向滚动；标签弹窗可键盘操作与关闭 | 全局约束 |
| A10 | 既有 e2e 全部仍通过；新增标签维护与筛选用例；后端 pytest 全绿 | 全局约束 |

| A12 | 备份导出不再含 `category`；用升级前导出的旧备份恢复，流程正常（旧备份里的 `category` 被忽略，不报错） | R8 |

## 已确认的决策（2026-11-13）

| # | 问题 | 结论 |
|---|------|------|
| Q1 | 多选标签筛选是 AND 还是 OR？ | **AND**（同时具备才算命中），与 skill-manager 一致 |
| Q2 | 筛选在前端还是后端？ | **前端**（数据已整份在手，后端单 tag 参数够用） |
| Q3 | 标签保存时是否排序？ | **排序去重**，与 skill-manager 一致（属行为变更，spec 要记） |
| Q4 | `category` 分类还留吗？ | **砍掉，只用标签**；原分类值迁移为标签 |
