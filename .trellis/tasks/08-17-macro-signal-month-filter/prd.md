# PRD:宏观信号按月过滤——非当月数据显示「暂未获取 + 预期发布时间」

## 背景

宏观信号 Tab 按 `month=YYYY-MM` 查询快照。当前后端 `get_snapshot` 的兜底路径存在问题:

```
archive/<month>/ 不存在 → 读平铺最新 6 个 skill JSON →
只要【任一】指标 data_date 落在请求月 → 6 个维度【全部】原样返回
```

结果:切到 2026-08(只要有日频指标如 DR007 落在 8 月),7 月甚至更早的月频指标
(CPI/社融/经济运行)会全部混进 8 月视图展示,用户误以为这些是 8 月数据。

用户诉求:**数据是哪个月的就展示在哪个月**。8 月还没发布的月频指标显示
「暂未获取」+ 预期发布时间,不显示旧月数值。

## 需求

### R1 后端:指标按月过滤

`get_snapshot(month)` 兜底路径(archive 不存在、读平铺最新文件时)中,
每个指标必须 `data_date` 落在请求月内才保留;不在请求月的指标从返回中剔除
(archive 路径不动——归档即该月真源,全量保留)。

### R2 后端:缺失指标的「暂未获取」信息透出

被 R1 創除的指标不是静默消失,而是以占位形态透出:后端在指标级输出
`next_release_at`(预期发布日,自报优先、规则表兜底——复用现有
`release_rules.get_next_release`,已有能力,无需新规则)。前端据此渲染
「暂未获取 · 预计 ≈09-09 发布」。

实现口径:后端返回该分组的**全量指标清单**(含当月有数值的 + 当月无数据的),
无数据指标 `value=null`、`data_date=null`,但带 `next_release_at/note/frequency`。
前端把 `value=null 且 frequency='monthly'` 的行渲染为暂未获取态。

> 全量清单来源:各 skill macro_signal.json `details` 里出现过的 key(即 skill
> 正常会输出的指标),按指标规则表 `INDICATOR_RELEASE_RULES` 补出发布预期。
> skill 本次未输出某指标(如数据源故障)不造数,不进清单。

### R3 前端:指标行「暂未获取」态

`IndicatorRow` 中 `value` 为 null 的月频指标行:
- 数值位置显示 `—`
- 时间行显示「暂未获取 · 预计 ≈09-09 发布」(next_release_at 截取 MM-DD,
  title 悬停显示完整日期+note)
- 「数据偏旧」黄色提示不适用(该行无数据时间,不存在偏旧问题)

### R4 前端:月份切换器包含当前自然月

`availableMonths` 不含 8 月时(8 月无任何归档+平铺数据),用户无法切到 8 月
查看「暂未获取」态。`MonthSwitcher` 的可选月份 = 后端 months ∪ {当前自然月},
当前自然月始终可选,即便当月尚无任何数据。

### R5 组头/结论展示(明确不做)

组头 conclusion、total_score、档位刻度维持现状——用户已确认仅做指标行层,
组头继续显示 skill 最近一次的结论(可能反映 7 月数据)。

## 验收标准

1. 后端:请求 `month=2026-08`(archive 无 2026-08),返回的每个指标
   `data_date` 均以 `2026-08` 开头;7 月的 CPI/社融等月频指标 value=null 且
   `next_release_at` 非空(如 CPI → 2026-09-09)。
2. 后端:请求 `month=2026-07` 归档月,行为与现状完全一致(全量返回)。
3. 后端:请求无数据月(如 2026-06,既无归档也无平铺数据)→ 404 语义不变
   (返回 null,前端展示数据缺失)。
4. 前端:切到 8 月,月频指标行显示「暂未获取 · 预计 ≈09-09 发布」,
   数值显示 `—`;日频指标(DR007/汇率/成交额,数据在 8 月)正常显示数值。
5. 剔除/占位逻辑只影响兜底路径;归档月查询不受影响。
6. 后端 pytest 全绿(新增过滤与占位逻辑的测试);前端 `pnpm build` 通过。

## 非目标

- 日历色点改为真实数据驱动(维持规则推算,是后续独立需求)
- 法定节假日顺延(维持周末校正近似)
- 组头 conclusion/评分在新月未出数据时的降级展示
- skill 侧 indicator_meta 自报字段补齐(维持可选)
