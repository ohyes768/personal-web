# 来源匹配：全量与增量两个按钮

状态：历史草案，已被`10-29-housing-rental-matching-speed`的PRD及实现取代。最终规则允许增量重试失败项，以下保留原始讨论记录。

## 操作语义

- 全量匹配：重新检查当前符合资格且缺少幸福里来源的小区，包括以前待选择、未找到和查询失败的项目。已有有效关联与人工跳过、拒绝决定继续保留。
- 继续匹配（增量）：处理上次剩余的未查询小区，并补入后来新增的未查询小区；已完成检查的待选择、未找到、失败项不自动重查。
- 两个按钮在空闲时同时显示；没有增量目标时继续按钮禁用。运行时显示停止匹配，禁用其他启动操作；继续保持与租金更新、单小区探查互斥。

## 前后端边界

- POST /rentals/source-matching 接受显式模式，区分全量与增量，不再由一个按钮根据任务状态猜测意图。
- 保留旧调用与服务启动恢复的兼容行为；自动恢复仍只处理未完成队列。
- GET 返回增量可处理数量，供按钮禁用和文案展示使用。统计总数只计算本次目标；上次已完成的关联、候选及人工决定不因重置本次统计而删除。
- 本次不调整请求间隔、身份核验或租金采集逻辑。

## 验证

- 服务测试：全量重新处理未关联的已查项；增量跳过已查项并包含新增项；保留人工决定与已有来源；停止、恢复、互斥行为保持正确。
- API 测试：两种模式路由正确，非法模式拒绝，旧调用兼容。
- 前端测试：两个按钮始终可辨、发送不同模式、空增量禁用、运行时互斥与停止行为正确。

## 取舍

推荐显式全量与增量模式。只拆前端按钮但仍调用同一种自动判断行为，无法保证实际范围；增加第三个失败重试按钮超出此次请求。
