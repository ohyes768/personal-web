# 股息率页面加载提速与存储方案评估

## 目标

缩短股息率页面，尤其 `/dividend/?tab=alerts` 的有效内容和现价出现时间，减少重复请求、重复组装与接口相互阻塞。根据性能证据判断 SQLite 是否必要。

用户本轮授权创建任务及规划，保持 planning，尚未授权实施或部署。

## 已确认背景

2026-11-02 NAS 只读测量：单独股票列表约 380–400 ms，M120 约 480 ms，挡位状态约 2 ms；一批混合读请求并发时最高约 1.56 s，health 也等待约 1.04 s。主 CSV 首次读取约 7 ms、缓存读取约 0.04 ms，股东/财务解析约 10/4 ms。详见 research/baseline.md；这些是少量采样，不是统计 p95。

## 需求及验收

| ID | 需求与证据锚点 | 验收 |
|---|---|---|
| R1 | 监控首屏按需加载。`apps/dividend/src/app/page.tsx:337,475,484,495,605` | alerts 不加载无关全量 stocks/M120；只获取收藏/监控所需资料和现价；Tab 切换、后退及深链接正常。 |
| R2 | 复用重复组装结果。`backend/dividend-select/src/api/routes.py:491` | 同一源版本的股东/财务索引只构建一次；源文件更新后下一次成功读取返回新结果；输出字段、数值、排序保持一致。 |
| R3 | 避免同步计算堵住事件循环。`backend/dividend-select/src/api/routes.py:447,645` | 混合列表请求并发时 NAS 内网 health/alerts p95 ≤100 ms；保留单 worker 下的任务互斥和调度唯一性。 |
| R4 | 收藏与监控独立于股息率筛选。`apps/dividend/src/app/page.tsx:506,592` | 阈值外、缺主表资料的收藏仍展示；无 M120 时仍可显示现价；资料失败只影响相关区域；保留配置和真实更新时间。 |
| R5 | 可复测的提速结果 | 同数据、同硬件冷/热各至少 30 次，记录 p50/p95、大小及错误率。拟定目标：热 stocks/M120 p95 ≤150 ms；NAS 代理下监控首屏关键数据完成 ≤500 ms。 |
| R6 | 解释用户实际慢加载 | 采集用户访问环境瀑布，分离 DNS/TLS、静态资源、API 排队和渲染；无法复现的公网问题明确留档，不用 NAS 回环数据替代公网结论。 |

## 范围与约束

- 优先监控关键路径，兼顾共享股票/M120 读取；全量、筛选、fav=1、旧 watchlist 链接做兼容回归。
- 缓存覆盖文件替换、新月/周/季度、缺失后补齐；不能仅靠固定 TTL。
- 保留六位字符串股票代码、财务及 TTM 口径、空值、排序和真实更新时间。
- 本期提议保留 CSV/JSON；若优化后证据仍指向存储瓶颈，再单独设计 SQLite 迁移，不作为本期前置条件。
- 不通过增加 workers 解决阻塞，避免重复调度器和写入任务。
- 不改变采集、通知、评级队列行为；测试不触发真实推送和收费行情请求。

## 非目标

界面重设计、历史数据库建设、评级报告改造、未经测量的公网基础设施改动，以及本轮实施/提交/部署。
