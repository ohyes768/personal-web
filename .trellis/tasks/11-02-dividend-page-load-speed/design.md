# 技术设计（待评审）

## 前端请求边界

根据 URL Tab 决定数据需求，用 enabled 或拆分数据容器控制 effects，保持 hooks 调用顺序稳定。

监控首屏：收藏/挡位 → 目标代码集合 → 精确股票资料和 prices。现价直接依赖挡位代码，不等待财务或 M120。全量列表/M120 和更新抽屉非关键状态按需加载；保留在跑刷新任务发现能力。去除重复 financial/status 请求，处理旧响应覆盖新筛选/Tab 的竞态。

计划给股票查询增加可选 codes 精确过滤，不传保持原行为；明确与原过滤参数组合语义。缺失主表资料的收藏仍保留占位。prices 已支持代码过滤，沿用现有接口。

## 后端快照与执行模型

先 profile CSV、股东索引、财务转换、模型构建、TTM、序列化，再决定缓存粒度。优先复用按代码索引的只读快照，避免每次扫描 5253 条股东记录。缓存有界，不按任意查询无限增长。

源版本使用实际文件路径、mtime_ns、size，最新文件选择沿用 helper；必须发现新季度文件、原子替换和缺失后补齐。读取前后复查签名，变化时有界重试；构建去重、快照发布加锁，消费者不得修改共享 DataFrame。读取失败不能永久缓存成正常空快照。M120/TTM 缓存同时依赖主表、M120、现价版本。

保留单 worker，把同步重计算放在线程池执行边界。stocks/screen 和 quality 有直接 await get_stocks 的内部调用，需先提取复用服务，不能仅修改 async def。线程隔离不等于提高 CPU 吞吐，必须配合减少重复计算，并实测并发延迟。保留刷新任务/调度器唯一性及原子发布语义。

## 存储决策

本期保留 CSV/JSON。数据池仅 202 只，读文件为数毫秒，迁移 SQLite 不能自动消除模型组装和 TTM 的 Python 计算。若优化后持久化读取/关联仍为主耗时，或新增历史及复杂索引查询，再另行规划表、索引、回填、校验和回滚。

## 兼容与回滚

API 增量扩展，保留代码类型、财务季度、TTM、空值、排序和真实更新时间。缓存随重启重建，无持久化迁移。前端按需加载、后端快照和计算隔离分开形成可回滚改动；不覆盖评级队列任务改动。部署另行授权，回滚不修改数据文件。
