# 导出目标管理设计

## 已确认范围
只管理 ZIP 导出目标。用户选择此范围并要求开始实施。

## 方案比较与选择
1. SQLite 动态目标表（采用）：持久化，与现有部署台账同库，支持改名与停用。
2. 配置文件：需要修改配置并重新加载，不满足界面管理。
3. 统一管理 NAS 与导出目标：涉及挂载及发布目录，超出已确认范围。

## 后端
新增 export_target 表：id（稳定唯一标识），name，install_path（仅说明文字），notes，enabled。初始化时插入两个旧 Windows 目标且不覆盖用户修改；删除初始目标后不能因重启自动重建，需一次性迁移标记或等价机制。
GET /api/export-targets 返回所有目标及当前台账数量；POST 新增；PATCH /{id} 编辑名称/说明/备注/启停；DELETE /{id} 无记录才可删除（409）。配置操作与已有导出台账免密边界一致。
保留固定 link 目标的类型与密码边界；export 请求使用受验证字符串 ID 并从目标表查询；未知目标拒绝，停用拒绝新导出。ID 不可与 openclaw/hermes 冲突。
列表与启动流程必须按 link 固定集合识别，禁止将自定义 export ID 强制转为固定枚举。检查迁移、删除登记、重发布、审计和计划各调用点。
目标改名不修改台账主键；有任何 deployment 记录拒绝删除。历史审计保留。清除停用目标的导出记录仍可操作。

## 前端
新增一级“导出目标”导航视图，沿用现有 URL view 契约与样式。目标列表展示名称、目录说明、备注、启停、记录数，新增/编辑表单与删除确认。
page 层统一加载目标并下传给来源工作区、技能卡片和导出弹窗。不保留第二份静态 export 名称源。LINK_TARGETS 保持固定。
弹窗仅可选启用目标，展示目录说明；没有启用目标时提示去管理目标并禁用提交。停用目标历史记录仍显示标签并允许清除；重新导出禁用。请求失败不关闭表单，刷新目标失败有错误提示，不默认为无目标。

## 验证与风险
以旧 SQLite 台账和自定义目标验证列表、改名、重启、stale、ZIP、清除、删除与 link 拒绝。新迁移不得反复补回被删除的默认目标。
目录说明不访问文件系统，不改变 ZIP 内容。完成前执行前后端检查及浏览器验收。NAS 部署另行执行，不自动提交或推送。
