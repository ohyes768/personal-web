# 幸福里租金来源试点接入

## 目标与授权
用户在免费替代来源调研、幸福里实测后明确回复“可以，继续”，批准先接入两个已验证小区的试点。交付可用采集链路及明确启用方式，不自动部署或修改生产来源关联。

## 已确认事实
2026-10-23 从 NAS 无登录/Cookie 完整取得风雅钱塘52条（42整租标记）、欣盛东方郡73条（69整租标记），分页无重复且同一 neighborhood_id。列表 URL 的数字为种子房源 ID，非小区 ID；首次 HTML 含 pia-ssr-data，后续使用网页 GET 分页接口。关键词搜索未验证成功，不可导入全市推荐。

## 要求
- R1：复用现有更新租金入口、目录住宅资格、互斥/取消/原子发布和统计口径；仅已有明确幸福里关联的小区使用新来源，其他保持房天下流程。
- R2：关联以现有 CommunityRegistry 为唯一权威，幸福里 identity 为真实 neighborhood_id，另存种子房源 ID。每来源每小区最多一个有效关联；幸福里优先但不与房天下混算，人工删除/解除/拒绝不得被自动恢复。
- R3：实现低频、有界、可取消的 HTTP 列表和详情核验，校验城市、种子、每条小区 ID、分页游标及重复页；异常、截断、详情失败不可作为完整新快照发布。
- R4：保留合租及质量标记供排除明细；整租仍需实际详情核验。住宅用途取当前权威目录，不用幸福里营销小区卡片的“元/月起”或年份覆盖目录。
- R5：所有缓存、失败沿用、查询和覆盖率匹配 source+source_community_id；不同来源同数字 ID 不可串用；前后端允许精确的幸福里安全来源链接。
- R6：提供两个实测入口的显式试点导入工具，默认只预览，匹配当前已收录住宅的唯一完整名/别名并校验地址/位置，不创建住宅，不改售价/法拍/住宅资格。导入幂等且尊重已有人工决定。

## 验收
- AC1：离线测试证明分页完整、wrong-community/验证页/停滞游标/详情失败/取消/页上限均不误发布。
- AC2：同一刷新中幸福里与房天下各自采集并共同原子发布，缓存和旧样本不会跨来源复用。
- AC3：API、管理覆盖率和前端链接支持幸福里；无幸福里关联的现有测试保持通过。
- AC4：试点导入默认为只读预览，显式 apply 后现有刷新入口可采集；重跑不复活拒绝或解除关系。
- AC5：完成相关后端/前端回归，记录验证范围及长期稳定性限制。

## 范围外
自动关键词发现、全区覆盖保证、验证码自动化、混合来源均价、定时采集、生产自动部署或未经审阅的生产写入。
