# 理杏仁估值独立每日采集

## Goal
让宽基趋势页面每天展示最近已收盘交易日的沪深300估值，并在周五19:00周报前独立采集，避免依赖行情刷新时机。

## Background
- 当前 main.py 的 daily_job 在16:30行情刷新后采集估值；启动初始化与手动刷新也能触发采集。
- valuation_service.py 的 resolve_page_target_date 当前选择最近完整自然周最后交易日；仅调整 cron 不会变成每日估值。
- report_service.py 已在生成周报前按 bar.date 采集估值，已发送报告保持幂等；休市周有只读沿用逻辑。
- 关联既有任务：../11-02-index-trends-pe-percentile；本任务调整其页面周度目标日契约，周报周度口径继续保留。

## Requirements
- R1：增加独立估值定时任务，北京时间每周一至周五18:30执行；交易日历确认当日休市时跳过定时网络采集，日历不可用时明确异常，不猜测交易日。
- R2：页面及默认采集目标为最近已收盘交易日；沿用15:05收盘安全阈值，当日阈值前取上个交易日，之后可取当日；周末、节假日沿用最近已收盘交易日，不引用未来数据。
- R3：16:30行情定时刷新不再联动估值。保留启动估值初始化及现有手动刷新能力；GET状态接口仍只读缓存。
- R4：估值状态对外可见且可解释：采集失败时保留既有缓存值并写明实际数据日期与失败原因，
  查询接口只读缓存。简报生成与投递由 Hermes 负责（读本服务的查询 API），本服务不再生成周报；
  已发送/已存档的周报不因后续估值更新而重发。
- R5：保持沪深300、PE-TTM总市值加权、近10年供应商分位与现有API字段/格式；缺Token不发网络请求，凭据不泄露。采集任务与行情、周报共用估值缓存，重叠执行不能重复发布或破坏状态。
- R6：采集时间可通过后端环境变量配置，NAS compose透传，README说明默认时间、交易日规则、每日页面与周度周报的差异。

## Out of Scope
不改周报19:00时间、行情16:30时间、趋势模型/周线口径、通知渠道；不新增估值图表/历史补采、数据源或持续轮询。不承诺供应商18:30已经更新，不自动购买权限。

## Acceptance Criteria
- [ ] AC1（R1、R3、R6）：独立估值job默认18:30 Asia/Shanghai，配置覆盖有效；16:30行情任务不请求理杏仁，节假日定时采集不发请求。
- [ ] AC2（R2）：周中、周五15:05前后、周末、长假、跨年、日历覆盖不足都有可验证目标日或明确错误；页面不受完整周限制。
- [ ] AC3（R4）：18:30成功后19:00复用；18:30失败/滞后时19:00允许按原缓存与冷却规则重试；失败保留缓存与实际日期。历史报告绝不采用报告收盘日之后的数据，已发送报告不重发。
- [ ] AC4（R3、R5）：启动/手动刷新、无Token、状态GET只读、冷却、并发采集、关闭任务清理均有脱网验证，原行情与周报失败隔离保持有效。
- [ ] AC5（R5、R6）：后端全量测试通过，文档与估值契约同步，compose结构检查通过。若前端需调整文案，完成类型检查和构建。
- [ ] AC6：部署后核对18:30任务注册、实际数据日期及周五周报快照；没有真实运行证据时明确标记未验证，不宣称供应商更新时点已核实。
