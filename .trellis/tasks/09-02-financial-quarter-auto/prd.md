# PRD：财务指标季度口径自动切换

## 背景

dividend-select 的财务指标链路中，"最新季度扣非" 存在两处按季度手改的硬编码：

1. 后端 `financial_fetcher.py` 固定 `QUARTERLY_YOY_REPORT_DATE = 2026-03-31`，
   永远算 2026Q1 vs 2025Q1；
2. 前端 `DividendTable.tsx` 弹层标题写死 "2026Q1 扣非同比 / vs 2025Q1"。

另外 CSV 里的 `数据季度` 列写的是 `current_quarter()`（抓取那一刻的日历季度），
与报表实际所属季度无关，导致同一份 CSV 混有 2026Q2/Q3，语义误导。

现在已是 2026-09，2026Q2 财报已全部披露，页面却仍展示滞后的 Q1 数据。
每次季度切换都要手改 4+ 处代码，容易漏改。

## 需求（用户已确认口径）

1. **「最新季度」按每只股票各自最新已披露报告期确定**（不再全市场固定同一季度）。
2. **扣非同比按"单季度"口径**：半年报/三季报的扣非是累计值，需减去上一累计期
   还原单季值，再与去年同期单季值比较。Q1 本身累计=单季，规则统一。
3. **「数据季度」真正反映该行扣非数据所属的报告期**（如 `2026Q2`），
   不再是抓取时的日历季度。
4. **前端弹层文字从后端字段取**：标题显示实际报告期（如 `2026Q2 扣非同比`），
   副标题 `vs 2025Q2`，不再写死，以后季度切换零手改。
5. 新股/未披露最新季报的股票：该股最新可得季报仍照常计算（口径 1 的自然结果），
   缺去年同期时同比为 None（现状行为保留）。

## 明确不做

- 不改"扣非净利润同比/3年复合增长率"（年报口径）的算法。
- 不改股东户数/申万行业等其他 aux 数据的季度语义。
- 不改 CSV 文件名规则（`财务指标汇总_YYYYQn.csv` 按抓取季度分文件的机制保留）。
- 存量旧 CSV 不迁移；下次刷新自然写入新列。（`数据季度` 列含义变化，
  旧值（日历季度）与新值（报告期）混在同一列，过渡期以新刷新为准，可接受。）

## 验收标准

1. `fetch_one` 对含 2026-06-30 数据的股票返回
   `数据季度=2026Q2`、单季扣非 = H1累计 − Q1累计、同比 = 单季 vs 2025 同期单季。
2. `fetch_one` 对只有 2026Q1 数据的股票返回 `数据季度=2026Q1`（各自最新期）。
3. API `DividendStock` 新增 `latest_quarter_label`（如 `"2026Q2"`），
   前端弹层标题/副标题/hover title 全部使用该字段，无写死的 "2026Q1" 字样。
4. 全链路（fetcher 单测 + 现有回归测试）通过；前端 `pnpm build` 通过。
5. 代码中不再存在按季度手改的日期常量（`QUARTERLY_YOY_REPORT_DATE` 等删除）。
