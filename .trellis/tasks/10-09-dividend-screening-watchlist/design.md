# 技术设计（已实施）

## 页面与边界
在 apps/dividend/src/app/page.tsx 新增 tab=screening（显示名「选股关注」），复用现有 URL 同步逻辑；旧 tab=watchlist、fav=1、tab=alerts 链接保持兼容。筛选面板与候选列表独立组件、独立数据状态，避免修改现有全部列表查询条件。
收藏入口继续复用现有收藏服务。使收藏视图按收藏代码加载数据，而不是只过滤当前候选/股息率阈值内的数据；缺基础资料时保留代码行并展示数据不足。

## 数据链路
财务源 → financial_fetcher → 财务 CSV → FinancialReader → API 模型 → 新筛选服务/API → 前端。沿用现有最新季度契约，由每只股票自身最新已披露期确定季度。
新增前一季度标签/扣非同比，以及 ROE 对应年度；用户已确认三年平均 + 最近年度组合口径，需增加三年年度值和平均值。每个值附报告期，历史不足不能用当前值复制填充。年报 ROE 用加权净资产收益率，不混用季度 ROE。
新字段对旧缓存兼容为 null；刷新后才具备完整判定能力。不在请求筛选时逐只触发外部采集。

## 筛选契约（建议）
新增只读筛选端点，例如 POST /stocks/screen，使用请求模型描述条件，避免污染 /stocks 原有默认行为。路由名称实施前检查静态/动态路由冲突。
服务对已采集全量股票先合并分红和财务，再统一评估。不能从已被旧 min_yield 截断的前端列表继续筛。
结果分为 eligible / excluded / insufficient_data，返回 counts、条件快照、股票代码、指标/报告期、原因码及更新时间。确定不满足任意条件即 excluded；没有明确不满足但必需值不足则 insufficient_data；所有必需条件满足才 eligible。缺失项仍单独返回。
两季规则为 previous_yoy < 0 AND latest_yoy < 0；Q1 的相邻期是上一年 Q4。累计转单季和同比计算遵守 financial-quarterly-contract.md。

## 收藏（建议）
增加收藏批量入口，复用存储服务的同步/写入机制，避免并发逐条读改写丢失数据。校验六位字符串代码、请求数量，去重并保留旧备注和 alerts，返回逐项 added/already_exists/failed。检查静态 batch 路由与 /favorites/{code} 顺序。
点击「收藏全部」绑定本次已展示结果快照；查询变化后清理勾选。调用成功后刷新 watchlist，使其他 Tab 状态一致。

## 兼容与回退
新增字段均可空；不改旧筛选契约与 favorites.json schema，除非实施检查证明必要。上线先刷新财务数据，旧数据明确显示待补。关闭/移除新 Tab 可回退页面；已添加收藏是用户数据，回退不删除。

## 最终决策
ROE 两个默认阈值均 10%，浏览器保存单套条件；筛选服务统一评估，历史完整性由缺失状态保护。用户已批准实施。
