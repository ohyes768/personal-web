# 住宅目录支持新房项目与证据位置补全

## 目标
新房住宅项目也纳入住宅目录；住宅用途确认后收录，位置核实后上地图。避免新盘因缺少二手房详情长期待审。

## 背景与证据
- 用户明确确认：也收录新房住宅项目；已授权创建 Trellis 任务并明确批准实施。
- 当前用途抓取仅访问二手房详情：backend/housing-map/src/services/tmsf_property_type.py 的 fetch_property_facts。
- 名称采集与用途详情分阶段执行：backend/housing-map/src/services/directory_collection.py 的 tmsf_names；当前无独立位置补全链路。
- 最新用途错误会使分类待审：backend/housing-map/src/services/residential_classifier.py 的 classify_sources。
- 主档地图坐标按主档 ID 读取历史文件：backend/housing-map/src/services/community_admission.py 的 community_views；来源 ID 与主档 ID 衔接需核查。
- 万科朗拾滨屿府历史透明售房网 ID 为 3017629894；property_types.json 记录住宅；price_snapshots.jsonl 记录地址“信诚南路与博研弄交叉口西侧(硅谷小学北)”；binjiang_coordinates.json 记录 120.176013, 30.162944。上述为历史线索，尚未验证运行服务当前记录及位置正确性。

## 需求
R1：支持新房项目住宅用途证据，保留项目身份、证据链接和核验时间；没有二手房记录不等于非住宅。
R2：用途更新请求失败保留历史有效证据，展示更新失败；明确用途冲突进入待审。人工决定保持有效。
R3：独立补全地址与坐标，优先核对同一来源身份的历史信息，再查询高德；结合名称、别名、区域、地址及分期核对，排除售楼处和附属设施误匹配。歧义保留人工确认。
R4：住宅用途、市场状态、地图状态独立展示；无证据时市场状态为未知，不凭零挂牌量推断新房。
R5：新房与二手房价格分别保存、展示，不能混作同一种价格口径。

## 验收标准
- AC1 / R1：没有二手房详情但有可靠新房住宅证据的项目可收录；缺少证据仍待核实。
- AC2 / R2：请求失败不抹去历史证据；用途冲突可见且进入待审；人工锁、忽略和排除决定不被自动覆盖。
- AC3 / R3：历史来源 ID 与当前主档关联经核对后可复用地址坐标；同名不同分期、售楼处、区外及坐标系不明不能自动定位。
- AC4 / R4：支持“住宅已确认、新房、坐标待补”；缺坐标不妨碍住宅目录收录，但不在地图显示。市场状态没有证据时为未知。
- AC5 / R5：新房价格不进入二手房价格指标。
- AC6：万科朗拾滨屿府能够关联可追溯用途和地址证据；位置经核实后可在地图显示，不能直接把历史坐标当作已验证事实。

## 不在范围内
不扩展新房价格采集，不承诺全量新盘覆盖，不凭名称强行合并，不覆盖其他任务正在进行的租金与法拍流程。

## 已确定的技术边界与限制
ESF 小区 ID 与新房项目 ID 不同，通过公开索引的明确别名和区域独立关联。新房索引只证明项目身份，不单独证明住宅用途。详情验证页独立报告失败，已有用途证据保留；没有有效用途时仍待核实。
本机没有高德服务端 Key，真实案例使用标明来源的历史地理编码；实时 POI 路径以离线回归验收。运行服务数据库未修改，生产部署不在本次授权范围。完整证据与检查记录见 qa.md。
