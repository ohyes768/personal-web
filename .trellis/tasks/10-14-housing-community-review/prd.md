# Housing Map 住宅小区与待审核小区管理重构

## 目标
把管理页变成两个按小区组织的名单：住宅小区是聚合去重、确认住宅后的正式名单，地图从这里取数据；待审核小区处理需要人工判断的候选。网站来源作为详情，不再用来源条数代表小区数。

## 背景与确认决定
- 当前主档398、待关联来源405是本聊天只读核对快照，不是重构后目标数，详见findings.md。
- 已关联来源不代表确认住宅；旧主档用途未知也应待审，同一小区多来源/多套法拍房不应重复占行。
- 用户确认明确住宅、证据充分且无重复疑点的新小区自动收录；其余有疑问的人工审核。
- 用户确认来拍 ya 未关联小区纳入统一审核，同小区房产聚合，保留资产及轮次。
- 本轮仅规划，状态planning，不实施、提交或迁移线上数据。

## 拆分与责任
本任务只维护总需求与最终验收，不是第四个实施任务。三个子任务按1→2→3实施：

| 顺序 | 子任务 | 负责范围 |
|---|---|---|
| 1 | 10-14-housing-residential-admission | 住宅状态、人工锁/撤销/恢复、地图同源、最小操作入口 |
| 2 | 10-14-housing-review-workspace | 来源/来拍候选聚合、两个完整列表、统一人工审核与计数 |
| 3 | 10-14-housing-auto-review | 自动规则、只读预演、启用/执行、可解释决定及集成验证 |

## 需求

### R1 名单与住宅准入
- tab为「住宅小区」「待审核小区」；默认滨江，保留萧山/全部区域、搜索和来源筛选。
- 住宅名单仅有效、去重且已确认住宅的小区（含住宅/别墅/排屋）。明确用途且无重复疑点自动收录；只有高德标签、法拍标题或同名缺身份位置证据不能自动收录。
- 公寓/其他/混合/未知/来源冲突待审核；明确非住宅、附属设施/区外记录排除并保留理由，可恢复。有争议不自动排除。
- 人工确认保存依据并优先于自动推断；后续新证据冲突提示，不能静默覆盖人工决定。
- 人工移回待审核/排除建立自动处理锁；重启/重采集/用途更新/新轮次不自动重新收录。恢复只回待审核且保锁，主动确认或显式允许自动审核才解除。

### R2 住宅小区列表
| 列 | 内容 |
|---|---|
| 小区名称 | 标准名，下方别名 |
| 区域 / 地址 | 区、街道、地址，缺失标注 |
| 物业类型 | 住宅/别墅/排屋及自动/人工确认 |
| 数据来源 | 去重的来源网站标签 |
| 地图状态 | 已显示 / 待补坐标 / 坐标待核对，范围限制说明 |
| 操作 | 查看详情、编辑、更多 |
- 更多：合并重复小区、移回待审核、排除收录；操作显示影响范围并确认。
- 详情查看来源、用途证据、法拍房产/轮次与历史；不加价格/租金/评分列。

### R3 待审核小区列表
| 列 | 内容 |
|---|---|
| 候选小区名称 | 原始名与已确认别名，按小区聚合 |
| 区域 / 地址 | 用于核对位置和分期 |
| 类型线索 | 按来源展示原始类型及冲突 |
| 数据来源 | 网站标签，来拍附房产/拍卖记录数量 |
| 待审核原因 | 类型不明、疑似重复、来源冲突、缺小区名等 |
| 疑似已有小区 | 推荐目标及证据，没有时标未找到 |
| 操作 | 审核 |
- 默认待审；已排除在该tab状态筛选中查看/恢复，不新增第三主tab。
- 同名或名称相似但证据不足分行，不误合并分期。缺小区名法拍显示名称待核实及房产标题，标题不冒充小区名。
- 旧主档用途未知/冲突也待审，不能只筛sources.pending。

### R4 审核操作
- 收录为住宅小区：确认住宅、标准名、区域/地址、分期与独立身份，建立/复用主档并一次绑定所选成员。缺坐标可收录，标待补坐标。
- 合并到已有小区：目标为有效已收录住宅；补来源/别名/法拍绑定，住宅数不增加，既有冲突必须显式处理。
- 排除收录：选择/填写原因，从待审消失且不进地图；原始来源、法拍记录和轮次保留，不等同删除法拍记录。
- 恢复排除回待审；住宅移回待审即撤出地图名单。成员可选择/拆分，已证实同小区成员默认一起处理。
- 成员关联、住宅确认、候选状态一次保存；失败全部回滚，重复提交不新建重复主档。

### R5 法拍与租金入口
- 已保存历史与后续未关联来拍小区进入统一队列；同步失败可重试，不漏掉已发布房产。
- 同一asset多轮只计一处房产；缺asset时展示独立拍卖记录及身份未明确提示，不虚构去重房产数。
- 收录/合并后相关资产及已保存轮次绑定同一cid，新轮次复用。已关联且住宅已确认不再排队；人工解绑重新待审且不自动回绑。
- 法拍页旧待关联入口改指向统一审核并预选来拍；独立法拍采集入口保持。
- 已有未关联Fang小区来源纳入候选；住宅缺租金来源的业务任务保留独立入口，不当成新小区候选。

### R6 地图与统计
- 地图和看板小区入口仅来自住宅收录名单，使用同一住宅确认与身份规则。
- 收录后合法坐标且范围内才显示，缺坐标仍在住宅列表；管理地图状态必须解释点数差异，不要求住宅总数等于点数。
- 库存按住宅N个/待审核M个/已排除候选K个展示；过滤分页按聚合小区候选计数，不能按来源/法拍套数计数。
- 最近采集单独显示时间与来源记录单位，保留用途失败/复用/截断/高德覆盖，不能与库存混加。

### R7 保护与迁移
- 保留小区ID、人工名称/别名、关联/拒绝/解绑、删除/合并历史、价格/租金快照及法拍原记录。
- 幂等迁移，可审计/回滚；旧398主档按证据重算，不能全部直接收录。
- 重启/重复采集/新轮次保留排除决定；来源改ID只提示历史排除，不做全局名称黑名单。
- 更新旧全量展示spec与本次住宅收录要求的冲突，不无意缩小独立采集范围或修改节奏。

## 验收
- AC1（R1/R2）：多来源同住宅一行；明确住宅无疑点自动收录；高德/法拍弱线索不自动确认。
- AC2（R1/R3）：同名异址/不同分期不误聚合；已关联但类型未知旧主档待审且不进地图。
- AC3（R4/R6）：相同筛选下新增收录住宅+1、待审-1；合并不增加住宅；排除待审-1可恢复；住宅移回即撤出地图。
- AC4（R4/R7）：成员冲突全部回滚，重复提交不重复创建，拆分可以分别处理，人工确认不被重算覆盖。
- AC5（R5）：2处资产、3轮同小区显示1候选“2处房产/3条记录”，决定后所有轮次正确关联；缺名/旧轮次冲突保持待审。
- AC6（R5/R7）：同步重试、身份提升、新轮次不重复建候选；排除保留法拍原记录；人工解绑不回绑。
- AC7（R6）：地图入口与住宅准入共用规则，少显示点可逐条解释；local-ID不请求TMSF，价格/租金/法拍历史身份关系不损坏。
- AC8（R7）：旧副本两次迁移/重启结果相同，身份/来源成员有完整去向账目，旧删除/人工决定不复活，原资产/轮次不丢失。
- AC9（R2/R3/R5）：桌面/手机可查列与证据、审核/恢复及法拍旧入口跳转；租金业务任务不重复算小区待审。

- AC10（R1/R4/R7）：江汉路小区人工撤销后重采集仍不收录，恢复仍待审保锁；只读预演不写业务，执行重查锁/版本；自动决定展示时间/规则版本/依据。

## 范围外与开放问题
不新增网络来源、不处理高德采全、不重建轮廓、不改法拍统计规则、不加价格/租金列、不做无证据AI自动判断。本轮不部署或生产迁移。无阻塞产品问题；技术方案见design.md，实施前由用户审阅并明确开始。
