# 修复高德定位 review 空候选死角

## 背景

小区"银泰国际"(别名"银泰国际商务中心")在生产环境高德定位显示:待确认(review)+ 无下拉候选 + "暂无可确认的候选位置"。人工无任何可确认手段,只能手动输坐标。

实测复现(2026-10-18):高德搜 `银泰国际`(city=杭州, types=120300|120203)返回 count=42 > 25 单页上限,结果截断。第一页 25 条中唯一落在滨江区、通过 normalize_poi 的是"银泰·海威国际"(坐标与该小区历史坐标基本重合,即同一栋楼),但 `_name_matches` 扁平化包含匹配失败("银泰国际"不是"银泰海威国际"的子串),匹配数为 0。

代码走 `directory_position.py` 的 `candidates 为空 且 count > 25` 分支 → `state='review'` + `candidates=[]`。前端 `PositionPanel` 对 review+空候选只渲染"暂无可确认的候选位置"。

**本质**:后端把"结果截断、不可信"留给人工核对,但唯一可能的候选在名称匹配时被静默丢弃,人工看不到它。

## 需求

1. 落在目标区(滨江/萧山边界内)、通过 `normalize_poi` 过滤、但名称不匹配的 POI,作为**疑似候选**进入 `candidates`,人工在下拉中可见、可确认。
2. 疑似候选永不自动绑定(不触发 `matched`),必须人工确认。
3. 名称完全匹配候选的现有行为不变:单候选且 count ≤ 25 仍自动 `matched`;多候选仍 review 按相似度排序展示。
4. 区域内确实无任何 POI 且 count > 25 时,前端给出明确引导(使用手动定位),不再只显示"暂无可确认的候选位置"。

## 约束

- **红线**:单候选自动绑定规则不变,且只适用于名称匹配的候选;疑似候选一律 review。
- 不做地址质检(用户已有决策:绑错反馈出现时再捡起)。
- 不引入翻页:疑似候选仅取第一页(≤25 条)过滤结果,数量天然有限。
- 不改动萧山边界逻辑、不改 admission 流程。

## 验收标准

- [ ] 银泰国际场景重新定位后:`state='review'`,`candidates` 包含"银泰·海威国际",带"名称不匹配"标记;前端下拉可见并可确认。
- [ ] 单测覆盖:count>25 + 区域内有疑似候选 → review 且候选非空、标记正确;疑似候选不触发自动绑定。
- [ ] 既有测试(`tests/test_position_status.py` 等)全部通过,单候选自动绑定行为无回归。
- [ ] 区域内无 POI 且 count>25 → 前端展示手动定位引导文案。
- [ ] 确认疑似候选后走既有 `confirm_position` 流程,写入 manual 定位,无需新增接口。
