# 设计：地点确认与分层筛选

## 架构与边界
只改前端，沿用 PositionPoint / Position、PositionDecision 和目录查询参数，不做数据迁移。阅读现有 directory-position.md、collection-pipeline.md、use-review.md。地点确认仍由 PositionPanel 管理；新建 CatalogFilters.tsx 承担筛选呈现，DirectoryFlowWorkspace 保持查询及详情状态管理。

## 地点确认区
1. 标题保留状态徽标，下一行给出一条具体结果说明。缺地址、多主体、名称待核对属于警示；接口失败属于错误。旧的泛化错误文案不强行推断成缺地址。
2. 替换重复类型段和候选 select。卡片分行显示名称、地址或“高德未提供地址”、末级类型；完整类型放入可展开详情，不从收录状态推测类型。
3. 单个有 source_id 和有效坐标的候选初始化为当前核对对象，只改变本地选择，不触发接口或勾选；多个候选默认不选，用原生 radio、fieldset/legend 和 label 卡片。
4. 当前候选显示精确 GCJ02 marker 链接，坐标放在“查看坐标”折叠项。无地址时说明需先查看地图，再勾选已核对。有地址沿用直接确认。
5. “确认此地点”置于核对内容之后；紧邻按钮显示具体禁用原因。busy 禁用选择、勾选和提交。提交成功仍完整刷新详情，不乐观伪造成功。
6. 选择和核对标记绑定 revision + POI ID；候选或 revision 变化清除勾选。单候选可重新展开，但不能重新自动勾选。
7. reference_candidates 用 details/summary 默认折叠并展示数量。无主体但有参考时明确“未找到可确认主体”，参考不能成为候选。已匹配、人工确认、未找到和查询失败保留各自状态呈现。

## 筛选结构
| 标签页 | 常驻 | 更多筛选 |
|---|---|---|
| 已收录 | 搜索、区域、新房/二手房、定位状态 | 用途核对、法拍、租金 |
| 待处理 | 搜索、区域、来源用途、定位状态 | 用途核对 |
| 不收录 | 搜索、区域、来源用途 | 用途核对 |

法拍待关联保留其搜索、包含已跳过、同步操作；租金待关联保留独立工作区，不套入住宅目录筛选。

所有 select 配可见 label，缺省项写清“全部房源类型”“全部定位状态”等。更多筛选使用原生 details，折叠态显示生效数量。摘要只包括实际发往当前页的条件；不为未知维度编造分项数量。

## 状态与数据流
- DirectoryFlowWorkspace 持有受控值、total/loading 与请求生命周期；CatalogFilters 接收值、选项及 onChange/onClear，负责布局和摘要。适用范围、请求和摘要共享定义，防止隐藏筛选仍影响结果。
- 首次打开沿用默认滨江，摘要显示该限制；“清空筛选”将 q、district、position、market、property_type、use、auction、rental 置空并 page=1。删除一项摘要只清对应字段。
- 切换目录页签保留搜索和区域，清除页签专属筛选，关闭详情并使旧请求失效。刷新保留全部当前条件；不新增 URL 持久化或 localStorage。
- 保留现有 200ms 节流、AbortController、分页回退及旧响应保护。加载期间显示“更新中”，不把旧 total 表述为新条件的最终数量。
- 不传入新 query 参数；确认保持原 revision/poi_id，只有无地址核对通过时传 coordinates_verified:true。空高德地址保持为空，不用实际来源地址替代。

## 视觉与响应式
沿用暖色主按钮、现有字体和表面色；卡片以边框和单选状态表示选中，避免把每个属性做成徽标。桌面用 grid 对齐筛选；手机搜索满行、筛选两列、地点操作纵向排布，长名称及地址换行。不增加第二套 sticky footer 与现有不收录页脚竞争。

## 验证及回滚
主用例为鸿雁苑 address=[]，补充多候选、有地址、缺坐标、无主体只有参考、已确认及错误。独立假数据浏览器拦截请求，验证 payload、核对重置及筛选参数，不提交线上真实记录。1440px/390px 一轮检查，集中修正后最多再确认一轮。

无后端及数据库改动，回滚前端组件与对应局部 CSS 即可恢复旧界面；已保存人工证据继续有效。
