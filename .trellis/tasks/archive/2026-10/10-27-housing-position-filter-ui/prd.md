# Housing-map 地点确认与列表筛选体验优化

## 目标与已确认范围
让用户快速看懂候选地点、完成地图核对，并明确列表筛选条件与结果范围。2026-10-27 用户确认候选卡片、确认区重排和分层筛选方案，要求先规划 Trellis 任务。本轮仅规划，保持 planning。

## 背景证据
- PositionPanel.tsx 重复列出主体类型，候选 select 将名称、地址、完整类型挤在单行；确认按钮位于地图入口与核对勾选之前。
- DirectoryFlowWorkspace.tsx 平铺多个筛选控件；多数只有 aria-label，没有可见标签；新房/二手房的缺省选项仅写“全部”，没有统一清空与生效条件摘要。
- globals.css 使用 flex 自动换行，手机端控件布局缺少固定层次。
- 前置修复 ae71e51 已支持无地址候选经 coordinates_verified=true 人工确认，不能因呈现优化削弱该保护或再次阻断流程。

## 需求与验收
| ID | 需求 | 验收标准 |
|---|---|---|
| R1 / AC1 | 信息去重与状态层级 | 顶部一条说明解释当前结果；候选主体信息集中显示，不重复完整类型列表。待确认使用警示色，查询失败使用错误色。 |
| R2 / AC2 | 可比较的候选 | 单个有效候选直接展开核对信息但不提交；多个候选使用可键盘操作的单选卡片。名称、地址、末级类型分行显示，完整类型可展开；无效坐标不能确认。 |
| R3 / AC3 | 核对后确认 | 顺序为选候选、查看精确坐标地图、无地址时勾选、确认此地点。切换候选或 revision 清除核对标记。忙碌、无版本、无效候选及未勾选时禁用并说明原因；有地址无需新增勾选。 |
| R4 / AC4 | 参考地点分层 | 公交站等放入默认折叠的“相关地点，仅供参考（数量）”，展开可读名称、类型及地址，不能选择为主体。 |
| R5 / AC5 | 筛选可理解 | 搜索、区域、适用的定位状态常驻；已收录显示新房/二手房，待处理/不收录显示来源用途；用途核对及适用的法拍、租金放入更多筛选。全部控件有可见字段标签，普通筛选沿用原生 select。 |
| R6 / AC6 | 条件可见与可清除 | 生效条件显示可移除摘要，更多筛选折叠后仍显示已启用数量。默认滨江属于生效条件；清空后搜索、区域及其他筛选恢复全部并回第一页。刷新保留条件，切换页签不携带不适用条件。 |
| R7 / AC7 | 响应式与可访问性 | 桌面对齐紧凑；390px 手机搜索独占一行、筛选两列、候选及确认纵向排列，无横向溢出。键盘可操作选择、展开、核对和确认，焦点及禁用原因可辨认。 |
| R8 / AC8 | 业务兼容 | 沿用 revision/poi_id/coordinates_verified 和既有筛选参数，不改变主体、区域、用途、收录及人工保护规则，不写生产数据。 |

## 不包含
内嵌地图 SDK、新增高德调用、后端筛选维度或数量接口、候选距离评分、列表表格全面重设计、其他服务界面、上线部署。

## 规划结论
沿用现有暖色、字体和弹窗风格，按局部优化实施。无阻塞产品问题；详细设计与执行验证分别见 design.md、implement.md。用户后续要求开发后再激活本任务。
