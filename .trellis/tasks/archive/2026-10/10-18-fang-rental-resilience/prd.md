# 房天下租金采集降频、缓存与风控冷却优化

## 目标

减少重复请求和验证后的无效访问，提高房天下间歇可用时的租金采集成功率，准确区分新数据、缓存和旧快照。

## 背景

- 2026-10-16 NAS 最近一轮 8 个小区全部失败、成功页面数为 0；当前快照发布于当天北京时间 14:05。2026-10-18 同一 NAS 低频探测成功解析 5 条列表和 1 条住宅详情，来源并非永久失效。
- refresh.py 默认间隔 2 秒、最多 10 页且全部取详情；来源发现先于已有来源采集。
- fang_rentals.py 只有本轮房源去重；连续两次列表滑块才暂停，详情滑块会被当作普通失败继续请求。
- discover 与 directory_collection.fang_names 各有独立客户端，缺少共同缓存和跨轮冷却。

## 需求

- R1：同源单并发，所有房天下入口共享至少 5 秒的请求间隔，等待可取消。先更新已关联来源，再补查缺失来源；自动搜索预算每轮最多 5 次。
- R2：成功验证的详情字段缓存 7 天，按房源 ID 和来源小区隔离。只复用地址、物业类型和独立详情验证时间；租金、面积、户型与成员集合仍取新列表。失败及验证页不入缓存。
- R3：完整成功且来源仍一致的小区快照 6 小时内复用，不改采集时间。失败、分页截断、详情不完整、解除或更换来源不满足复用条件。
- R4：列表、详情、发现任一阶段首次滑块即停止后续请求。冷却持久化并跨入口、重启生效，连续触发采用 1 小时、6 小时、24 小时；完整成功的真实更新后重置等级。
- R5：普通超时最多延迟重试一次，连续超时暂停本轮；与验证、非法跳转分别记录，继续保持 URL 白名单。
- R6：区分真实请求、详情缓存命中、快照复用、未尝试和失败，展示冷却截止时间；旧任务缺新字段仍兼容。新绑定来源可留待下一轮采集，状态需说明。
- R7：维持完整性和原子发布规则，失败保留旧数据及原时间；全部复用不产生新快照、不更新 last_success_at；混合发布不能丢失复用小区。

## 验收标准

- [x] 两轮相同列表中，有效详情不重复请求；新增、过期、来源不一致的详情重新验证。
- [x] 新列表的价格变化能生效，消失房源不因缓存复活；缓存不覆盖动态字段。
- [x] 详情或列表滑块发生后没有后续网络访问；重启、重复点击与其他入口遵守冷却，退避等级可用假时钟验证。
- [x] 取消可打断限速和重试等待；共享限速覆盖发现、列表、详情和重定向。
- [x] 快照复用不改变原时间，来源变更立即失效；混合发布保留复用/失败小区，全部跳过不伪造新发布。
- [x] 超时有限重试，跳转仍拒绝未知域名；诊断不泄露 Cookie、完整 HTML 或敏感查询参数。
- [x] 离线测试覆盖策略、缓存、刷新、发布、来源隔离及 API/前端兼容；真实验证仅少量烟测。
