# 地图页无数据小区补齐(父任务)

> 2026-10-16 规划。本任务为父任务:持有需求背景、子任务地图与跨子验收,不直接承载实现。

## Goal

补齐线上地图(https://web.duomi77.cn:9443/map)12 个"有定位无轮廓"小区的小区轮廓,形成可重跑的补齐手段,全程含人工确认。

## 结论演进(为什么是脚本方案)

初版设想为"后端估算服务 + API + 管理页批量 + 地图页一键交互"。摸底(research/overpass-recon.md)后证伪:

- 线上缺口仅 12/154 个小区,0 个无定位 → 不值得养服务;定位重查管理页已有入口,前端交互整个砍掉
- Overpass 限流严重(并行 11 请求 7 个 429)+ 本机出口直连被 406 拦 → 必须串行/间隔/缓存/镜像 fallback
- 轮廓落盘后地图自然渲染 → 不需要任何同步机制
