# 已收录小区多选合并

## Goal

在小区目录「已收录」页支持勾选多条重复小区、一键合并到保留方，替代当前「先移到待审核、再到审核详情搜目标合并」的绕路。首个真实场景：水晶城水晶澜轩 / 钱江水晶城 / 钱江水晶澜轩 三条重复记录归一（水晶湾城市雅苑在滨安路口，是另一项目，不属于该组）。

## Background / Constraints

- 后端已有直接合并接口 `POST /api/map/directory/communities/{cid}/merge`（body `{community_id: 目标id}`，`community_registry.py:_merge`），前端从未接入。本次不改后端。
- 合并语义（已由后端保证）：被并方名称与别名并入保留方 aliases；保留方已有地址/坐标不覆盖，仅补空；来源记录（含法拍轮次、租金关联）全部迁移；`merged_to` 软链兜底；写入操作事件。
- 后端已有保护：双方都有租金来源（fang/xingfuli matched）时拒绝合并，返回错误。
- 市场状态（新房/二手房）不在合并字段处理范围内，合并后跟保留方走——UI 必须把差异亮出来让用户确认，不得静默取默认。
- 已收录表格为 `table-layout:fixed` + `.catalog-admitted` nth-child 百分比列宽；加 checkbox 列必须同步列宽规则并限定作用范围，否则新列塌 0 宽、其他模式（待处理/不收录）列错位。

## Requirements

1. 仅新版目录页（DirectoryFlowWorkspace）「已收录」Tab 提供；待处理/不收录/法拍/租金 Tab 不加；老审核台（CommunityWorkspace）不动。
2. 已收录表格每行加 checkbox 多选；选择仅限本页，翻页或刷新筛选时清空（与现有「移除所选」行为一致）。
3. 选中 ≥2 条时底部出现批量操作条：「合并所选（N）」；<2 条不出现。
4. 点合并打开弹框：
   - 列出所选 N 条（名称、地址、来源数、定位状态、租金/法拍记录数、市场状态）；
   - 单选保留方，默认预选规则：有定位坐标者优先 → 来源记录多者优先 → 列表顺序靠前者；
   - 展示合并预览：被并方名称将进入保留方别名、地址/坐标差异（保留方已有值不覆盖）、租金/法拍记录将迁移；
   - 所选含新房与二手房混合时，高亮市场状态差异并要求确认（确认按钮文案明确提示）。
5. 确认后逐条调用合并接口（N-1 次，全部指向保留方）：某条失败（如租金来源冲突）不回滚已成功项，逐条展示成功/失败结果。
6. 完成后刷新列表，被并方消失，保留方详情可见并入的别名与来源。

## Out of Scope

- 后端 batch 合并端点（前端循环调用现有端点即可，规模为个位数）。
- 撤销合并 UI（事件 payload 已含 previous 数据，需要时人工恢复）。
- 老审核台 CommunityWorkspace 的合并入口改造。
- 对生产真实重复数据的合并执行——实施期只在开发库造数据验证，线上三条由用户自行操作或另行安排。

## Acceptance Criteria

- [x] 已收录表格每行有 checkbox，选中 ≥2 条时出现「合并所选（N）」；翻页后选择清空。
- [x] 合并弹框可单选保留方，默认预选有定位坐标且来源最多的一条。
- [x] 新房/二手房混合时弹框高亮差异，确认文案提示保留方市场状态将生效。
- [x] 确认合并后列表刷新只剩保留方，保留方别名含被并方名称，来源/法拍/租金随迁。
- [x] 某条失败时已成功项保留，失败原因逐条可见。
- [x] checkbox 列在宽屏不塌宽，待处理/不收录模式表格不受影响；窄屏卡片态下多选列不破坏布局。
- [x] `cd apps/housing-map && pnpm build` 通过。
