# PRD：前端双区化 — 区筛选、围栏、默认视野与文案

> Parent: [10-02-housing-expand-xs-border](../10-02-housing-expand-xs-border/prd.md) · 子任务 3/3 · 依赖采集扩展（子任务 2）的数据

## 需求

前端从"滨江区购房地图"升级为"滨江 + 萧山接壤板块"双区视图，小区量级上升后保持可用性。

### 改动点

1. **双围栏 POI 绘制**：`src/lib/binjiang-boundary.ts` 同步后端多围栏（滨江 + 萧山板块），`isInBinjiang` 对应升级为围栏集合判断，POI 绘制围栏跟随。
2. **区筛选**：新增区维度筛选 chips（全部 / 滨江 / 萧山），与现有物业类型筛选并存；URL query 状态跟随（沿现有筛选状态管理模式）。
3. **默认视野**：地图默认中心/zoom 调整为覆盖双围栏（fit 双多边形 bounds），不空白过大。
4. **文案**：标题"滨江区购房地图"→ 双区表述；`types.ts` 中 3 处 `district: '滨江区'` mock 硬编码修正。
5. **market_reference 看板**：`scope: '滨江区'` 展示双区（配合子任务 2 的数据扩展）。
6. **小区看板**：列表/筛选增加区列或区标识（数据看板与地图数据源一致）。
7. **性能观察**：小区从 ~200 → 400-500 量级后，地图点位/轮廓渲染与看板分页是否仍流畅；不流畅再议聚合/缩放分级渲染（本任务只观察记录，不预做优化）。

## 验收标准

1. `/map` 默认视图覆盖滨江 + 萧山板块，POI/小区点位不越双围栏。
2. 区筛选生效：切"萧山"只见萧山板块小区，切"滨江"与现状一致。
3. 文案、图例、看板 scope 均为双区表述，无残留"仅滨江区"字样误导。
4. `pnpm build` 通过；桌面 + 移动端宽度基本可用（移动端可只验证不阻塞）。

## 不做

- 地图聚合/缩放分级渲染优化（先观察）
- 后端任何改动
