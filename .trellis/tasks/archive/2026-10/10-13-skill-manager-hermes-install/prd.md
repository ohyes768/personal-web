# Hermes 单目标与 Skill 安装流程简化

## Goal
用户只使用 Hermes，不再向 NAS OpenClaw 发布。简化 GitHub 与自研 Skill 的安装流程，并移除当前产品及部署配置中的 OpenClaw 支持。本轮仅规划，实施须经过规划审阅。

## Confirmed requirements
- Hermes 是唯一软链接安装目标；GitHub 与自研均覆盖。
- GitHub：输入仓库地址并扫描 → 选择候选 → 一次确认安装；登记、计划与发布由系统串联，不要求用户跨页面操作队列。
- 自研：保留源库发现与自动对账，单项或多选 → 一次确认安装；已安装可直接更新。
- OpenClaw 的界面、运行支持、配置、挂载、现行部署文档及相关测试全部退出。

## Requirements
R1. 无目标选择和 Agent 切换；旧 OpenClaw 页面链接落到 Hermes。普通用户流程不展示发布队列，也不要求另点生成计划。
R2. GitHub 扫描后默认全选候选，可调整；共享资源沿用现有扫描建议并排除候选祖先，详情归高级选项。扫描与登记复用仓库缓存。
R3. 确认安装前同一弹窗显示数量和逐项新增/更新/跳过/冲突原因；一次密码确认，安装时自动登记。没有确认不写登记、不安装。
R4. 自研卡片提供安装/更新操作，多选安装复用同一确认与结果流程。已自动登记不再次要求登记。来源缺失不可安装。
R5. 同仓库合集支持一键安装已登记全部成员；搜索筛选不能悄悄缩减“全部”范围。添加远端新成员使用重新扫描。
R6. 后台显示扫描、准备、登记、安装等阶段与逐项结果；防重复提交。部分成功不回滚成功项，失败可单独重试。登记成功安装失败必须明确显示“已登记、未安装”，重试不得重复创建记录。
R7. 既有条目安装/更新不重复登记；相同内容跳过。更新必须确认具体版本，检查更新本身不能自动安装；旧计划因候选、资源、源内容或版本变化失效。
R8. Hermes 安装状态准确反映实际链接。下架从安装看板操作，密码验证保留；不可覆盖用户自己的文件或不受管理的链接。
R9. 删除 OpenClaw 运行入口与部署依赖后，不配 OpenClaw 环境变量、不挂载其目录即可启动。旧数据中 OpenClaw 不得变成导出目标、阻止删除 Skill，或污染 Hermes 计数。
R10. 迁移保留备份与审计，可重复执行；Hermes 与 GitHub 注册、缓存和既有安装保持完整。旧 OpenClaw 已安装链接提供受限清理流程，不能递归删除目标目录或删源仓库。
R11. 文案统一为“安装到 Hermes”“更新”“下架”；不把登记/下载成功称为安装成功。静态导出 Codex/Claude 功能保持独立，不随移除 OpenClaw 删除。

## Acceptance
- GitHub 从扫描结果到安装完成，只需一个确认安装动作和一次密码；自研从选中到安装同样如此，无目标选择/队列中转。
- 单项、多项、合集全部、部分失败、重复提交、重试、刷新/服务重启、缓存缺失均有明确反馈。
- 计划确认版本与安装版本一致；过期计划不执行，错误密码无登记/安装副作用。
- 旧库含 active/removed OpenClaw 记录可启动迁移；既有 Hermes 安装不变，旧 OpenClaw 请求被拒绝且不写盘，不被归为导出。
- 未配置/未挂载 OpenClaw 的 compose 校验和服务启动通过；目标目录普通文件及外部链接不会误删/覆盖。
- 前后端测试、类型检查、lint/构建按实际项目脚本执行；桌面/移动浏览器验证两来源完整流程。

## Out of scope
本轮业务实施、真实 NAS 操作、自动更新安装、整仓直链或 repo-pack 模型、多 Agent 安装、聊天密码持久保存、删除历史 Trellis 归档、删除 OpenClaw 程序或其用户数据。
