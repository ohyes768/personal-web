# 基金经理维度评价与筛选

## Goal

在 `fund-select` 中建立**以基金经理为主体**的评价能力：能按「从业年限 + 任职年化收益 + 风险控制」等经理维度筛选和排名，替代当前只有「基金行上附带一个经理姓名/年限」的附属形态。

**首版范围：仅股票基金（主动权益）**。债基经理不在本次范围，阈值只按股票口径设定。

## Confirmed Decisions

| 决策 | 结论 | 依据 |
|---|---|---|
| 落地位置 | 在 `fund-select` 内新增经理 tab | 复用现有 FastAPI + SQLite + scheduler，不新增部署单元 |
| 基金范围 | **只做股票基金**，不做债基 | 本轮只关心股票基金；避免债股阈值混用 |
| 采集范围 | 只采库内股票基金涉及的经理 | 首次即可用，无需全量扇出 4384×N 请求 |
| 评价阈值 | 只设股票口径一套 | 与基金范围一致，不拆分债/股 |

### 首版覆盖规模（已核实库内数据）

| 口径 | 基金数 | 涉及经理（去重姓名） |
|---|---|---|
| 主动权益（股票型 + 混合型-偏股） | 6759 | **1799 人** |
| 含指数型-股票 | 12365 | 2140 人 |

首版按**主动权益 1799 人**建池。指数型基金经理评价口径不同（跟踪误差 vs 超额收益），单列后续。

## Background

### 现状（已核实）

`fund-select` v1 是**债基筛选平台**，经理信息只是 `funds` 表上的附属字段：

| 字段 | 含义 | 出处 |
|---|---|---|
| `mgr_name` | 现任经理姓名，`、` 拼接 | `market_universe_refresh.py` |
| `mgr_company` | 第一位经理所属公司 | 同上 |
| `mgr_days` / `mgr_experience_years` | 共管**取最短**（min，保守） | 同上 |
| `mgr_days_max` / `mgr_experience_years_max` | 共管**取最长**（max，筛选口径） | 本次修复新增 |

已完成的缺陷修复（提交 `5a8a4f97`）：共管取 min 导致「22 年老将 + 3 年新人」被记成 3 年，`min_mgr_exp=5` 误杀。修复后债基可选 2485→3943 只。

### 缺口（本任务要解决）

1. **没有经理实体**。经理只是基金行上的字符串，无法「按经理聚合」。且只存姓名不存 ID —— 全市场 4384 人中有 **118 组重名**（如工银瑞信两个「陈涵」，7.4 年 / 1.6 年），做经理排行会串号。
2. **没有任职年化**。现有收益率全是**基金**口径（`ret_1y/3y/5y`），无法回答「这个经理自己任期内赚了多少」。累计收益必须除任职天数折算年化，否则排名由入职时点主导。
3. **没有历任记录**。`mgr_name` 只记在管，经理离任/跳槽/管理过几只查不到，而这是判断稳定性的关键。

### 数据源（已实测可用，无需付费）

| 用途 | 接口 | 关键字段 | 备注 |
|---|---|---|---|
| 全市场经理表 | 东财 `FundDataPortfolio_Interface.aspx?dt=14` | **经理ID**、姓名、公司、现任基金、累计从业天数、最佳回报、现任规模 | 4384 人 @9 页；akshare `fund_manager_em()` 已封装但**丢弃了 ID 列** |
| 经理档案 | `fund.eastmoney.com/manager/<经理ID>.html` | 历任基金表：代码/名称/类型/规模/**任职起止/任职天数/任职回报**（含已离任） | 服务端直出，无需翻页；UTF-8 带 BOM |
| 复权业绩 | `fund.eastmoney.com/pingzhongdata/<code>.js` | `equityReturn`（复权日增长率）、`Data_currentFundManager`（五维评分、任期收益 vs 同类 vs 沪深300） | 单请求 ~690KB；**算收益/回撤必须用这个** |
| 净值序列 | `ak.fund_open_fund_info_em(code, "累计净值走势")` | 全历史累计净值 | 仅用于取日期轴，**不可直接算收益**（不复权，见陷阱 1）|

### 已知陷阱（已实测验证）

1. **累计净值不复权**。富国天惠：单位净值涨幅 157.8%、累计净值 462.6%，真实复权 1500.33%（16 次分红）。算回撤/夏普必须用 `equityReturn` 连乘重建复权曲线（实测 1498.6%，与官方吻合）。
2. **从业年限 ≠ 任职年限**。`累计从业天数` 是职业生涯总长（含研究员期），评价单只产品须用档案页的单只任职天数。
3. **多经理共管**。`funds.mgr_experience_years` 取 min 会误伤老将（本次已修，新增 max 字段）。
4. **幸存者偏差**。`dt=14` 的「最佳回报」只统计在管基金，已离任的糟糕战绩被隐藏。

## Requirements

### R1 经理实体与身份唯一性

- 新增 `managers` 表，以**东财经理 ID** 为主键（不是姓名）。
- 字段至少含：经理 ID、姓名、所属公司、累计从业天数/年、现任基金数、累计管理只数、在管只数、在管总规模。
- 采集时保留 `dt=14` 原始返回的**第一列经理 ID**（现有 `manager_fetcher.py` 丢弃了它）。
- 重名经理必须落在不同主键行上。
- **仅收录库内主动权益基金（股票型 + 混合型-偏股）涉及的经理**，约 1799 人。

### R2 任职业绩（经理口径）

- 从经理档案页采集历任基金：基金代码、任职起止日、任职天数、任职回报。
- 计算**任职年化**：`(1+任职回报)^(365/任职天数)-1`。
- 计算**管理时长加权年化**：按各段管理天数加权，避免经理自选代表作。
- 区分在管（`至今`）与已离任记录。

### R3 风险指标（经理口径）

- 至少支持最大回撤、年化波动、夏普、卡玛。
- 必须基于**复权净值**（`equityReturn` 连乘或等价方法），不得直接用累计净值。
- 指标口径需标注样本区间与算法版本。

### R4 筛选与排序

- 新增独立的经理筛选接口（`/api/funds/managers/screen`），以**经理为主体**聚合排序，不复用现有 `/screen`。
- 支持按：从业年限、任职加权年化、最大回撤、在管规模筛选；结果分页。
- **不改动**现有 `/screen` 系列接口及其 `min_mgr_exp` 语义，四个 tab 行为保持不变。
- **筛选阈值只按股票口径设定**：任职加权年化 ≥10%（沪深300 同期年化 7.7%、同类平均 11.8%），最大回撤劣于 -60% 否决。

### R5 数据刷新

- 首次建库覆盖约 **1799 名主动权益经理**，每人 1 次档案页请求 + 代表基金净值请求，需限速与断点续采。
- 日常刷新仅覆盖候选池（100–200 人），避免频繁全量触发限流。
- 复用现有 `RefreshRun` 进度记录与 scheduler 体系。

## Acceptance Criteria

- [ ] `managers` 表以经理 ID 为主键；重名经理各自独立成行，可按 ID 查到唯一档案。
- [ ] 覆盖库内主动权益基金涉及的经理（约 1799 人），采集成功率可统计。
- [ ] 对给定经理（如张坤 `30189744`），系统返回其历任基金列表，含已离任记录，并可算出任职年化。
- [ ] 经理「管理时长加权年化」与其「最长任期单只基金年化」不同，且加权口径可复现（张坤实测：最长任期 10.53% vs 全段加权 6.78%，排除债基/货币/FOF 后按管理天数加权）。
- [ ] 风险指标基于复权净值；富国天惠 `161005` 全历史复权收益 ≈1500%（非 462%）。
- [ ] 可按「从业 ≥5 年 + 任职加权年化 ≥X% + 最大回撤 ≤Y%」筛出经理列表，结果可分页。
- [ ] 新增经理 tab 不影响现有四个 tab；516 项后端测试全部保持通过。
- [ ] 数据采集支持失败重试与断点续采，单次全量采集有明确耗时与限流策略。

## Out of Scope

- **债基经理评价**（本轮只做股票基金）。
- **指数型基金经理**（跟踪误差/超额口径不同，单列后续）。
- 不做基金经理的定性评价（投资风格标签、访谈文本分析）。
- 不做实时盘中净值。
- 不改动 `index-trends` 服务（其边界是沪深300 指数趋势与估值）。
- 首版不做经理历史持仓穿透分析。
