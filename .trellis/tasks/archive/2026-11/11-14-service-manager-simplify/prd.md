# service-manager 瘦身：砍掉详情页与未用能力

## 目标

把 NAS 服务管理台收回到它真正被使用的范围：**一份 Docker 服务清单 + 说明文字 + 标签**。
砍掉从未被使用的详情页与其附属功能，让「看状态、写说明、打标签」三件事在**列表页一处**就能做完。

## 背景（真实使用数据，2026-11-14 统计）

24 条服务、42 个组件、55 个容器。逐项查了台账里每张人工表的实际占用：

| 能力 | 实际数据 | 结论 |
|---|---|---|
| 用途 description | 24/24 条有 | 在用 |
| 归属 ownership | 已由另一任务退役 → 交给 `personal-web` 标签 | — |
| 标签 tags | 28 个词 | 在用 |
| 入口 endpoints | 20 条，每服务 1 个 | **数据在用，但维护入口在详情页** |
| 入口的 probe_url / 期望状态码 / 续期备注 | **各 0 条** | 从没用过 |
| 人工端口 port_notes | **0 条** | 从没用过 |
| GitHub 仓库 release_sources | **0 个** | 从没用过 |
| 未读发布 release_reads | **0 条** | 从没用过 |
| 组件覆盖 component_overrides | **0 条** | 从没用过 |
| 备注 notes | **0 条** | 从没用过 |

详情页因此有 1000 行代码，其中真正带数据的只有 3 块（组件明细、入口 URL、头部说明），
**人工端口区与发布动态区是原 PRD 要求做、但一次都没用过的两整块**。

## 需求

| ID | 需求 |
|----|------|
| S1 详情页下线 | 删除 `/service/[id]` 页面；列表页与发现导入页不再有指向它的链接；直接访问该路由应 404 |
| S2 列表页自足 | 名称、用途、标签的维护**全部在列表页完成**，不需要进二级页面 |
| S3 行内编辑 | 每条服务可在列表行内编辑**名称**与**用途**（不进详情页） |
| S4 删除服务 | 列表页可移除台账条目（confirm 提示「只影响台账，容器照常运行」） |
| S4b 归属已退役 | 「归属」字段与两个分组 tab 已由另一任务（`ownership-retirement`）退役：列表平铺，归属由 `personal-web` 标签表达。本任务**不再涉及**归属 |
| S5 状态维度收敛 | 列表只显示**运行**与**健康**两个维度；URL / 证书 / 发布三个徽章不再出现（入口与发布下线） |
| S6 入口与发布下线 | 列表不再有「主入口」列、「打开」按钮、「巡检」按钮（巡检查的就是入口的 URL 与证书） |
| S7 资源总览收敛 | 只保留**端口**视图（Docker 侧）；**域名**与**证书**视图下线（依赖入口数据） |
| S8 发现导入收敛 | 候选表保留导入 / 追加 / 忽略；「查看服务」链接（指向详情页）下线；**解绑组件暂不做** |
| S9 后端保留 | 后端接口、表、数据**一律保留不删**：入口/端口/发布/检查的实现与 20 条入口数据都留着，只是前端不再调用。spec 里标明「功能已下线，实现暂留」 |
| S10 备份不变 | 导出/恢复照旧包含全部人工表（入口数据不丢） |

## 不在范围

- 后端代码、接口、数据库表与数据的删除或迁移（S9）
- 解绑组件、换绑组件（S8；用户明确「先想清楚再加」）
- 组件明细（镜像 / 部署路径 / 数据卷）——要去 Docker 那边看
- 单条服务的定时/手动检查（只保留全局「扫描容器」，且后台本来每 60 秒自动扫一次）
- 独立标签表、标签重命名 / 合并

## 约束

- 后端不动 → API 契约、备份格式、数据库结构全部不变；**不做任何迁移**
- 前端不再调用被下线功能的接口，但类型与封装可以删（调用点没了就删干净）
- 「状态展示铁律」继续成立：分维度、颜色之外有文字、不写只有内行懂的缩写
- 375px 不得横向滚动；键盘可达；行内编辑要能提交与取消
- 搜索与标签筛选继续可用；列表保持平铺（无分组 tab）

## 验收标准

| ID | 可验证结果 | 关联需求 |
|----|------------|----------|
| B1 | `/service/任意id` 返回 404；页面里没有指向详情页的链接 | S1 |
| B2 | 列表页能改名称与用途（行内编辑，保存后立即生效）、能改标签、能删除服务 | S2 S3 S4 |
| B3 | 列表只出现「运行」「健康」两个状态徽章；没有主入口列、没有「打开」按钮、没有「巡检」按钮 | S5 S6 |
| B4 | 资源总览只剩端口视图；域名/证书 tab 不可见 | S7 |
| B5 | 发现导入页无「查看服务」链接；导入 / 追加 / 忽略照常可用 | S8 |
| B6 | 后端 `GET /api/services/{id}`、入口/端口/发布接口仍返回 200（实现没删）；导出 JSON 仍含 endpoints | S9 S10 |
| B7 | 台账条数与标签词表不变（24 条 / 28 个词） | S9 |
| B8 | 后端 pytest 全绿；前端 tsc/eslint 0 问题；e2e 全绿并覆盖行内编辑 | 全局 |

## 已确认的决策（2026-11-14）

| # | 问题 | 结论 |
|---|------|------|
| Q1 | 入口功能怎么办 | **整个下线**（维护入口、URL/证书检查、域名/证书总览都没了） |
| Q2 | 组件明细怎么办 | **不做**，去 Docker 看 |
| Q3 | 解绑组件放哪 | **先不做**，以后想清楚再加 |
| Q4 | 单服务手动检查 | **下线**，只留全局「扫描容器」 |
| Q5 | 后端动到什么程度 | **只下线前端**：后端代码、接口、表、数据全留 |
| Q6 | PRD 怎么处理 | 原 PRD 的 R3/R4/R5/R6(部分)/R7 标为**已下线**，写进 spec |
| Q7 | 归属字段怎么办 | **已退役**（另一任务）：列表平铺，归属交给 `personal-web` 标签。本任务在此基线上做 |
