# service-manager 恢复主入口与证书监控

## 目标

把**证书监控**捡回来：列表页每条服务能看到「主入口 URL + 证书状态 + 距到期天数」，URL 能在列表行里直接改。
入口与证书的检查能力后端一直都在（`check_results` 里 14 个 https 入口的证书全部 `valid`），
这一轮只补**界面**与**一个写入入口**。

## 背景

上一轮按「入口功能整个下线」砍掉了详情页、主入口列与证书徽章。砍的时候按「人工表用量为 0」判断
（入口维护 0 条、证书总览从没被打开），但**证书检查本身一直有价值**：

- 后端仍在定期检查：20 个入口全有 URL 检查结果，14 个 https 入口的 TLS 检查全部 `success`；
- 14 个证书当前状态都是 `valid`，数据完好；
- 用户反馈：证书列不该消失。

同时确认了入口数据的规律（20 条无一例外）：

| URL 形态 | kind | tls_check |
|---|---|---|
| `https://…`（公网） | external | 是 |
| `http://192.168.x.x:…`（内网直连） | internal | 否 |

→ 判定规则可以自动做，不必让用户手填类型。

## 需求

| ID | 需求 |
|----|------|
| E1 主入口列 | 列表页有「主入口」列，显示 URL（可点开）与一条「无对外入口」的中性文案 |
| E2 行内编辑 URL | 直接在主入口列改 URL：点一下变输入框 → 回车/失焦保存 → 立即生效；取消则放弃 |
| E3 自动判定类型 | 保存时按 URL 自动判：内网 IP（192.168/10./172.16-31.）→ internal，其余 → external；`https` 才查证书 |
| E4 证书列 | 列表页有「证书」列：状态徽章（有效 / 即将到期 / 已过期 / 无效 / 未检查）+ 距到期天数；无效要写原因 |
| E5 新服务也能被检查 | 新登记的 URL 会被纳入检查（后端按 endpoint 维度查），证书列在首次检查后有状态 |
| E6 后端补齐 | 列表项带 `primary_endpoint`（url/label/kind/tls_check + 证书状态与到期天数）；新增 `PUT /services/{id}/primary-endpoint` 做 upsert（只收 url，规则在后端） |
| E7 检查触发 | 保存 URL 后触发一次该服务的证书检查，前端提示「已保存，证书状态稍后更新」 |
| E8 不越界 | 后端既有检查口径、Docker 只读边界、备份格式都不动；本次只加读字段与一个写接口 |

## 不在范围

- 域名 / 证书**总览页**（横向视图）——仍不恢复，要看全部证书逐条看列表即可
- 入口的标签 / 备注 / 探测 URL / 期望状态码 / 续期备注（全部 0 使用，不恢复）
- 人工端口、发布动态、组件明细（仍下线）
- 证书的自动续期、签发（不在产品范围）

## 约束

- 主入口**每服务一个**：沿用既有模型（一服务一入口）；后端按 external 优先挑主入口
- URL 编辑是**行内**的，不弹窗（列表页已经有一个标签弹窗，再加一个会乱）
- 证书状态必须**颜色之外有文字**（spec 的状态展示铁律）；无效证书要写原因（自签 / 域名不符 / 链过期 / 不受信）
- 保存失败（409 revision 冲突、URL 非法）要明确提示，不能静默失败
- 375px 不横向滚动

## 验收标准

| ID | 可验证结果 |
|----|------------|
| C1 | 列表页有「主入口」「证书」两列；主入口显示 URL，「无对外入口」的中性文案也还在 |
| C2 | 行内改 URL → 保存后列表立即显示新 URL；证书列在首次检查后出现状态 |
| C3 | 填 http://192.168.x.x:1234/ → 自动判为 internal（不查证书）；填 https://… → external 且查证书 |
| C4 | 证书列显示状态徽章 + 到期天数；14 个存量 https 入口显示「有效」 |
| C5 | 后端 `GET /api/services` 每项带 `primary_endpoint`；`PUT /api/services/{id}/primary-endpoint` 只收 url 即可 upsert |
| C6 | 后端 pytest 全绿；前端 tsc/eslint 0 问题；e2e 全绿并覆盖行内改 URL |
