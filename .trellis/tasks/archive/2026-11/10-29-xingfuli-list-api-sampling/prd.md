# 幸福里租金列表 API 抽样

## 目标与已定范围
采用用户选择的方案二：直接请求幸福里同小区列表 API，从列表筛选最多10套统计有效整租，不逐套查详情。沿用此前要求，幸福里共享请求间隔改为3秒。

## 已验证事实
- 线上取消批次：37个目标、18个已处理、19页列表、144次详情、163次请求，未发布。
- 2026-10-29实测 `/f100/api/search_api/rent` 的offset=0可直接返回20条万科璞悦湾房源，total=23，全部小区ID一致且房源ID唯一；count=50仍返回20条。
- 列表已有租金/单位/整租类型/小区ID，面积和户型需解析展示文字；6300元/月、89㎡的抽查样本与详情一致。列表缺楼层。
- statistics._exclusion_reason当前排除detail_fetched=false，需增加明确的列表证据契约，不能伪造详情核验标记。

## 要求
1. 只处理当前已收录且已关联幸福里的小区。直接列表API首屏及分页，不请求列表HTML或逐套详情。
2. 检查小区归属、整租类型、元/月单位、有效正值租金/面积和可解析户型；排除合租、疑似隔断、重复ID及现有疑似重复规则认定的记录。不加面积门槛，按API返回顺序抽样。
3. 按统一统计过滤后的数量凑够最多10套即停，不合格记录不占配额；不够则翻页至列表耗尽或现有10页上限。真实不足10套保存实际数量；各统计分组仍至少3套才出参考。
4. 样本显式标记幸福里列表API证据，detail_fetched保持false；只对符合此契约的样本开放统计，其他旧未核验样本继续排除。旧详情核验快照仍可读且如实显示原证据。
5. 页面说明“列表抽样：最多10套整租，未经逐套详情核验”。任务详情请求数如实为0，抽样有效数另行统计。
6. 保留分页推进检查、错小区拒绝、结构失败/验证/限流冷却、取消、任务互斥、发布前资格复查和原子发布。无法证明归属的空列表不得直接当成该小区零房源；失败保留旧快照。
7. 幸福里真实请求默认及最低间隔统一3秒，覆盖搜索/探查/匹配/采集，共用原限速槽和一小时冷却；Fang间隔不变，离线假客户端仍允许零延迟。

## 验收
- 首屏足量小区只需1次列表API，无详情/列表HTML请求。
- 无效及重复候选补位、满10早停、不足10、分页失败、错归属和冷却有回归覆盖。
- 新列表证据可统计且不伪造detail_fetched，未知证据不可统计；旧快照兼容，摘要/详情数量一致。
- 前端展示准确抽样说明；3秒间隔及共享限速/取消回归通过。
- 后端回归及前端lint/typecheck/tests/build通过，真实小批只读验证不发布测试快照。

## 不包含
详情API接入、详情缓存、取消断点恢复、全面逐请求日志、新定时任务、生产部署或启动全量采集。
