# 小区审核筛选缓存与来源索引提速

## Goal

减少审核筛选等待。用户已批准资料不变复用结果、变化才重算，并纳入来源索引优化。

## Requirements

- inventory/auction_tasks 按数据版本缓存，资料或迁移标记变化后下次读取更新。规则部署重启清空缓存。
- 来源按小区 ID 分组，避免逐小区遍历全部来源。
- 统计和列表独立加载，翻页和非搜索筛选不重查统计。
- 保留现有规则、API结构、取消请求与分页保护；保留已有未提交 UI 修正。

## Acceptance Criteria

- [ ] 重复读取只构建一次；并发、安全拷贝、有界容量、异常不缓存。
- [ ] 数据库写入（含外部 SQL/WAL）和依赖文件修改/原子替换立即失效。
- [ ] 原有筛选、人工决定和数据覆盖率回归通过。
- [ ] 记录冷热耗时对比，前后端完整检查通过。

## Notes

- 线上基线：444小区、991来源；summary约0.49s、catalog约0.39s，前端串行加200ms。
- 不改业务规则、不迁移业务数据、不引入外部缓存服务。
