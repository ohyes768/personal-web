# NAS 服务管理台 V1

## 目标

集中管理 NAS 上通过 Docker Compose 部署的服务，让使用者能找到入口和部署位置，理解端口、域名和容器的关系，发现运行或证书异常，并阅读上游新版动态后自行决定是否升级。

## 背景与确认范围

用户采用 Docker Compose 部署，已接受以记录、自动读取和检查为 V1 边界。2026-11-11 授权完成规划，尚未要求实现或部署。版本动态的价值是了解新特性，由使用者自行决定是否升级。

仓库已有独立前后端、NAS Compose 和 Nginx 路径路由。NAS 实测存在一个 Compose 项目包含多组应用、host 网络容器、缺失 Compose 标签的容器，以及多域名/多 HTTPS 端口入口。证据见 research/findings.md；技术选择与默认值见 design.md。

## 功能需求

| ID | 需求 |
|---|---|
| R1 服务台账 | 支持新增、编辑、移除业务服务，维护名称、用途、分类、标签、笔记；一个服务关联多个容器，支持手工录入无容器服务 |
| R2 发现和关联 | 发现运行和停止容器，按 Compose 项目筛选；选择后确认导入或关联；支持忽略临时容器。重建容器不丢已有业务关联 |
| R3 部署信息 | 展示工作目录、Compose 文件有序列表、bind/named volume 与容器挂载目录、读写模式；缺失信息可补录，标注人工或自动来源 |
| R4 端口与入口 | 维护内网、外网、管理入口完整 URL；展示发布端口和内部端口，支持人工端口记录、反代目标与路径前缀；端口重叠提示注明判断范围 |
| R5 域名与证书 | 按域名、端口、路径查看服务关系；检查 HTTPS 证书到期、主机名与信任链，显示被哪些入口共用，区分续期备注和实际检查 |
| R6 状态与检查 | 分别显示容器运行、Docker health、URL 可访问性；支持定时与手动检查、任务进度；失败保留上次成功结果并显示错误和时间 |
| R7 发布动态 | 服务可关联一个 GitHub 仓库；展示正式 Release 的版本、日期、原始更新说明与链接，支持明确标记已读。人工版本备注与运行镜像分开显示 |
| R8 查找与页面 | 服务首页、详情、候选导入、资源总览和设置；按名称/用途/标签/域名/端口/路径搜索，按分类和异常筛选；支持复制路径和打开入口 |
| R9 导出恢复 | 导出人工台账 JSON，恢复前展示校验和替换预览，经确认后原子恢复；不导出系统凭据或把台账导出称为应用数据备份 |
| R10 私密性与接入 | 管理员登录后访问台账；容器元数据不返回环境变量、命令或秘密。Docker/网络故障不阻断人工台账使用；按现有网站方式部署并提供返回首页入口 |

## 验收标准

| ID | 可验证结果 | 关联需求 |
|---|---|---|
| A1 | 无 Docker 连接时能登录、手工新增、编辑、搜索和移除服务；移除不调用 Docker 写操作 | R1/R10 |
| A2 | 同一 Compose 项目的前后端可合并为一个业务服务，也可保持不同服务；单个组件不能重复归属；忽略决定在重启后保留 | R1/R2 |
| A3 | project/service/instance 相同、容器 ID 改变时关联不变；成功扫描缺失才标 missing；扫描失败不清空组件；已停止与消失分开 | R2/R6 |
| A4 | 绝对/相对/缺失/多个 Compose 文件路径、bind/named volume 均按来源展示；没有文件读取或目录浏览入口 | R3 |
| A5 | 8097 同时为两个容器的内部 expose 时不报主机占用冲突；同端口不同协议/不同不相交 IP 不报潜在重叠；host 网络与 stopped 映射均有明确口径 | R4 |
| A6 | 同域名 `/a`、`/b` 与显式 9443 端口能分别定位服务和代理目标；登记不修改 Nginx/Caddy/DNS | R4/R5 |
| A7 | 200、401、404、超时、HEAD 不支持、TLS 错误各有正确状态；结果显示后端探测视角；localhost 目标不能误探测管理台自身 | R6 |
| A8 | 有效、距到期 30 天边界、已过期、主机名不符、自签/不可信和无法连接证书各有用例；同域名不同端口不混用证书 | R5 |
| A9 | Docker health 未配置不显示 healthy；检查失败保留旧结果并标错误/陈旧；手动重复刷新合并任务；重启可识别 interrupted | R6 |
| A10 | 正式 Release 与预发布分开，初次同步无历史未读轰炸；后续新发布未读且可标记；304、无发布、无正式版、404、429/限流都可区分；移动标签不自动推断升级必要性 | R7 |
| A11 | 服务、端口、域名和证书页能交叉定位并复用同一数据；375px 和 1440px 下可操作，键盘焦点、返回首页、复制反馈、失败重试可用 | R8 |
| A12 | 导出到空库恢复人工台账一致；schema 不支持、损坏 JSON、重复绑定、外键错误、超大文件、预览后数据变化均拒绝且不破坏原库；恢复不启动外部检查 | R9 |
| A13 | 未登录台账 API 为 401；环境变量/Token/私钥/原始 inspect 不出现在响应、导出或日志；proxy GET 可用，Docker 写请求和非授权 API 类别被拒绝 | R10 |
| A14 | `/services` 页面、静态资源、API rewrite、登录 cookie 和首页入口可用；新模块撤回后原有服务继续运行且台账卷保留 | R10 |

以上是后续实现的验收要求，当前规划阶段尚未执行功能验收。

## 不在第一版范围

容器启停、执行命令、Compose 编辑与部署、反代/DNS 修改、证书签发续期、自动升级、多主机管理、AI 摘要和主动通知。

## 约束

- 单 NAS、单管理员、单 Docker Engine；保留不完整元信息，不通过猜测补造公网 URL 或安装版本。
- 不将管理台台账恢复等同于容器数据/数据库恢复。
- 宿主机完整监听端口、外部用户访问视角与配置文件存在性不在自动检查保证范围。
- 本轮只改本任务规划文件，不改现有业务代码、NAS 配置或其他未提交文件。
