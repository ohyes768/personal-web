# kids-catalog 榜单与手动链接分 tab 展示

## 背景

`apps/kids-catalog` 目前有两个 tab：「本月精选」和「设备歌单」。「本月精选」把月度榜单采集的专辑（`source='chart'`）和用户手动粘贴链接导入的专辑（`source='manual'`）混在同一个列表里，仅用「手动添加」徽章区分，不够清晰。

后端 `backend/kids-catalog/src/main.py` 的 albums 表已有 `source` 字段（`chart` / `manual`），`GET /api/kids/albums` 无需改动即可支撑前端拆分。

设备歌单的候选（candidate）来自全部已下载合集，天然覆盖两个来源——此行为保持不变，只需验证确认。

## 需求

1. 「本月精选」tab 只展示 `source='chart'` 的专辑；月度标题（`N年N月精选`）与「更新于」时间戳仅依据 chart 来源计算（现有逻辑已如此，保持）。
2. 新增「手动添加」tab，只展示 `source='manual'` 的专辑，不显示月度标题/更新时间；手动导入表单（粘贴链接 + 获取按钮）移到该 tab，或两个 tab 都可用——以实现最清晰为准，导入成功后停留在手动 tab 并提示。
3. 手动添加专辑的下载/重试/管理（track-manager）能力在手动 tab 中保持可用。
4. tab 结构变为三个：「本月精选」「手动添加」「设备歌单」，URL `?tab=` 参数同步扩展（如 `tab=manual`）。
5. 设备歌单不变：候选仍从榜单 + 手动两个来源的已下载合集一起选择。
6. 空状态文案分别适配：本月精选提示点「获取最新」；手动添加提示粘贴链接导入。

## 验收标准

- [ ] 「本月精选」列表不含手动专辑，「手动添加」列表不含榜单专辑
- [ ] 手动导入流程（粘贴链接 → 导入 → 下载）在新 tab 下完整可用
- [ ] 手动专辑的下载状态刷新、重试、进入 track-manager 正常
- [ ] 设备歌单候选包含两个来源的已下载合集（回归验证）
- [ ] `pnpm build`（apps/kids-catalog）与后端 pytest 通过；后端逻辑未改动时跑既有测试确认无回归
