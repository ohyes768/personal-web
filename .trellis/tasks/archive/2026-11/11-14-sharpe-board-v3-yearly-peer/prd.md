# 夏普榜单 v3：年度同类排名门槛 + 历史回溯

## Goal

把 v2 的第三道门从「近 3 年**滚动**同类排名前 20%」改为
「最近 **3 个完整年度**（2023/2024/2025）中**至少 2 年**同类排名**前 25%**」。

换口径的直接收益：**年度排名是历史固定值，因此周榜历史可以回溯**。
v2 上线后榜单只有一个点（2026-11-09），回溯后能补出完整走势曲线。

## 背景：为什么换口径

### 接口事实（2026-11-14 实测）

`ak.fund_individual_achievement_xq(symbol=code)` 返回两类排名：

| 类型 | 示例 | 性质 | 能否回溯 |
|---|---|---|---|
| **年度业绩** | `2023: 3456/4165` | 该自然年的**最终**排名，历史固定 | ✅ 能 |
| **阶段业绩** | `近3年: 1635/3793` | 滚动窗口，标题是「截至今天」 | ❌ 不能 |

**关键验证**：库内 `peer_rank`（2026-09-09 写入）与今日接口实时值**逐字一致**
（000001 三年分别为 3456/4165、1900/4533、2029/5118）。证明年度排名确实是
已冻结的历史事实，不是每次重算的滚动值。

### v2 为什么只有一个点

v2 用的是滚动排名，历史上不存在 → 无法回溯 → 只能从 2026-11-09 那周开始积累。
换成年度排名后，**每一周的入选判定都能用同一份年度排名复现**，历史可补。

## Requirements

### R1. 门槛定义

- **年度窗口**：最近 3 个**已完成**的自然年度。当前 2026 年未结束，
  故取 2023 / 2024 / 2025。窗口随年份自动滚动（2027 年变为 2024/2025/2026）。
- **达标条件**：3 个年度中**至少 2 年**的同类排名**分位 ≤ 25%**（即前 25%）。
- **年度缺失**：某年无排名数据 → 该年不算达标；不足 2 年达标 → 不入选。
- **不再看 `as_of_date` 陈旧度**：年度排名是历史事实，不存在「过期」。
  v2 的 `PEER_STALE_DAYS = 90` 逻辑对本口径**取消**（滚动排名才需要）。

### R2. profile 版本升级 v3

- 新增 `(stock, v3)` / `(discovery-stock, v3)`，v1/v2 保留不删。
- `ALGORITHM_VERSION_V3 = "risk-3y-v3"`。
- 默认版本切 v3（周任务 / API / 聚合三处）。
- 参数命名体现口径变化：`min_yearly_top_pct`（阈值 25.0）+ `min_yearly_years`（2）。
  不再使用 `max_peer_pct`（那是滚动口径的名字）。

### R3. 历史回溯补算

把 v2 已上线的周（目前只有 2026-11-09）用 v3 重算，并**向前补算到 2025-01-06**，
让页面有约 45 个数据点。

- 补算产物写入 `profile_version='v3'` 的周批次与观测。
- **必须按周冻结当时的筛选证据**（夏普/IR/样本天数/年度排名），
  与真实性原则一致：夏普与 IR 用当周往前 3 年的净值窗口算，不用今天的值。
- 年度排名是历史固定值，直接复用库内数据（无需按周变化）。
- 幂等：重复执行先清理该 source/version 的补算行，再重建。

### R4. 前端

- 表格「同类分位」列改为展示**年度口径**：如 `2023-2025 前18%` 或 `2/3 年达标`。
- 规则说明文案同步（「近3个完整年度中至少2年前25%」）。
- 默认版本 v3。

### R5. 保留 v2 数据

v2 那 2 周（stock 7 只 / discovery-stock 29 只）保留在库里（版本隔离），
不删——它是 v2 口径的唯一证据。页面默认查 v3。

## Constraints

- 不改 v1 / v2 profile 定义（历史周行的 profile_json 是冻结快照）。
- 谓词组件的三个门仍走同一份 `entry_predicate`（新增年度参数）。
- 年度排名的取数必须批量（≤500 codes 分块），不得 per-code 查询。
- 回溯脚本默认 dry-run，`--apply` 才写库；写库前先备份。

## Acceptance Criteria

- [ ] AC1：v3 profile 存在，filters 含 `min_yearly_top_pct=25.0` / `min_yearly_years=2`；
      v1/v2 profile 一字未变。
- [ ] AC2：年度窗口计算正确——2026 年算出 2023/2024/2025；2027 年算出 2024/2025/2026
      （用可注入的年份参数测试）。
- [ ] AC3：达标判定正确——3 年中 2 年前 25% 通过；只有 1 年通过不入选；
      某年数据缺失按不达标计；分位恰好 25.0% 通过（含等号）。
- [ ] AC4：不再因 `as_of_date` 陈旧而排除（构造 as_of 为 2026-09-09 的数据仍入选）。
- [ ] AC5：回溯脚本产出 v3 周批次，从 2025-01-06 起连续覆盖到最新周；
      每周边界落在周一；重复执行结果一致（幂等）。
- [ ] AC6：回溯后 API 返回的 `weeks` 长度 > 40，`series` 有对应数量的非 null 点。
- [ ] AC7：v2 数据仍在库里且未被改写（周数与观测数不变）。
- [ ] AC8：前端「同类分位」列展示年度口径，规则文案同步；1440/390 无横溢出。
- [ ] AC9：后端 pytest 全绿（668 基线 + 新增）；前端 node --test + tsc + build 通过。

## Out of Scope

- 不改 v1/v2 历史数据
- 不做「近1年/近3年/近5年」其他滚动口径
- 不引入截面全市场排名（仍用东财给出的同类分位）

## Notes

- 阈值实测（当前 v2 成员 36 只）：前25%至少2年 → 剩 29 只（76%）；
  前20%至少2年 → 剩 18 只（48%）。用户选 25%，偏保守留量。
- 接口实测样本：000001 / 016452 / 110011 三只三年排名均稳定可得。
- 库内覆盖：1728 只基金 2023/2024/2025 三年齐全。
