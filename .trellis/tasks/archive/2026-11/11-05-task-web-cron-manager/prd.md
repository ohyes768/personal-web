# task-web 定时任务管理

来源：apps/task-web/HANDOFF.md（2026-11-05 交接）。状态：规划中。

## Goal

在 personal-web 中新增 task-web（前端 apps/task-web/，后端 backend/task-web/），用 Web 页面管理 Ubuntu NAS 上的定时任务：定时调度、任务管理、执行记录与日志查看，方便排查是否执行、何时执行、为什么失败。

用户已确定方向（HANDOFF 原话）：
> 不用 n8n 了，就只需要定时任务，然后管理，方便排查是否执行的功能

约束：
- 不使用 n8n；不用 AI agent / 模型 token 调度。
- 普通 Shell/Python 任务由程序调度执行。
- 第一版聚焦定时、任务管理、执行记录和日志，不做通用可视化工作流平台。

## Requirements（第一版）

### 任务管理
- 新建、修改任务：名称、说明、命令及参数、工作目录、cron 表达式、时区、超时、启停状态。
- 显示上次执行时间、上次结果、下次计划时间。
- 手动立即执行；记录触发来源（定时/手动）。
- 暂停只阻止自动触发，不终止正在运行的进程。
- 删除任务与历史记录的关系在设计阶段明确。

### 执行记录与日志
- 每次运行独立 run_id：task_id、计划时间、实际开始/结束时间、耗时、触发来源、状态、退出码。
- 状态区分：等待、运行中、成功、失败、超时、中断；互斥跳过也留记录及原因。
- 保存 stdout/stderr；执行中可看实时日志，结束后可回看。
- 列表按任务、状态、时间筛选。
- 漏执行识别：记录调度心跳与应执行时间，不把“到时未运行”混同成功。

### 最小可靠性
- 同一任务默认不并发；手动与定时共用互斥。
- 超时杀整个进程组。
- 服务重启后旧运行标记中断或核验，不留永久“运行中”。
- 单一有效调度实例，避免多副本重复执行。
- 停机期间漏掉计划是否补跑：默认策略写入 PRD/设计（倾向默认不补跑）。
- 日志轮转/按期限清理，保留策略可配置。
- 指定执行账号、工作目录、环境运行。

### 成功判定边界
- 退出码 0 只代表进程正常退出，不代表业务投递成功；页面需明确结果含义。
- 接入每个脚本前核对：获取失败/空数据/推送失败的退出码；空批次语义；异常吞掉仍返回 0 的情况；是否启动后台子进程。

## 验收标准

- [ ] 任务 CRUD 全字段可用，含启停、手动执行、下次计划时间展示。
- [ ] 运行记录含完整 run_id 字段与状态机；stdout/stderr 执行中可实时查看、结束可回看。
- [ ] 用无外发脚本验证成功、失败、长运行、超时四类记录与日志、互斥行为。
- [ ] 重启后状态恢复、漏执行识别、时区与下次运行时间正确。
- [ ] 首个正式任务（A 股新股）接入：先无外发测试 → dry-run → 确认后启用正式计划；默认导入禁用。
- [ ] 不出现双调度器同时发送；每个任务保留旧计划记录与回滚办法。
- [ ] 密钥/敏感环境变量不出现在页面或日志。

## Out of Scope（第一版不做）

- 多机器执行器、任务依赖图、可视化编排、脚本在线 IDE。
- AI 自动分析日志、自动修复。
- 替换所有 Hermes 定时任务。
- 自动重试（需先验证幂等性，不默认套用）。
