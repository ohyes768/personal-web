# 采集任务弹框信息精简改造

## Goal

收录采集任务 / 维护采集任务两个弹框当前把「说明性长文」「本轮产出指标」「历史状态」混在同一视觉层，每行都要逐字读才能判断该点哪个按钮。改造为紧凑任务行：每任务默认 1 行，状态用徽标表达，指标只留非零项，长说明收进可点击/悬浮的说明区。

用户价值：打开弹框即可扫视「哪个任务在跑、跑完了什么、下一步点哪个」，无需读完 600 字正文。

## Background

现状（`apps/housing-map/src/components/community/DirectoryFlowWorkspace.tsx:146-229`，`CollectionControls`）：

- 每个任务渲染 1 个 hint 长文 + 1~4 个 `directory-task-sub` 子行，正文约 610 字，弹框高度 3~4 屏
- 「更新全部 vs 继续」的按钮差异规则散落在 4 处重复子行（`:185` rentalMatch、`:191-192` amap、`:203` rent、`:74` tmsf hint），讲的是同一件事
- 指标行把零值也渲染出来：`已检查 0 · 已关联 0 · 待选择 0 · 未找到 0 · 查询失败 0 · 未查完 0 · 未查询 0`（`:196`）、`基本资料齐备 0 · 非住宅 0 · 待地点匹配 0 · 身份待核对 0 · 网络可重试 0 · 基本资料待取得 670`（`:197`）
- 状态是一条灰色小字（`:157`），与说明文字视觉权重相同
- `继续采集（—）`（`:174/177/180/182`）用 em dash 占位，暴露内部字段缺失
- ` · 上次结束：2026-10-12 08:01:33（UTC）`（`:159`）拼在 hint 句尾，UTC 直接甩给用户

原型已确认：`docs/prototypes/housing-map-collection-tasks.html`（含空闲态 / 有数据态两个场景切换，现有 vs 改造对照）。

## Requirements

### R1 任务行结构

每任务一行，列序固定：状态点 → 任务名 → 状态徽标 → 指标 → 操作按钮组 → 说明入口（?）。

任务名保持纯文本（非链接样式）。说明入口是任务名右侧的一个小圆圈 `?` 按钮。

### R2 状态徽标

用徽标替换现在的灰色小字，色调按 phase 归并：

| 徽标 | 覆盖 phase | 色调 |
|------|-----------|------|
| 尚未采集 / 尚未匹配 | idle | 灰 |
| 运行中 | running / crawling / publishing / checking_sources / cancelling | 暖橘 |
| 已完成 | succeeded / done | 绿 |
| 部分完成 | partial_failed / cooling_down / budget_exhausted | 黄 |
| 失败 | failed / error | 红 |
| 已取消 / 已中断 | cancelled / interrupted | 灰 |

徽标文案附进度（如 `已完成 · 120/120`、`运行中 · 40/61`），无进度时只出状态词。

### R3 指标只留非零

标题行指标只显示非零项，分隔号分隔，零值整项不渲染。全零则指标区为空。

明细统计（如 `已检查 45 · 已关联 38`）放说明展开区，与标题行的「本轮产出」语义区分：标题行放产出（已关联 / 待选择 / 未找到），明细区放总量（已检查 / 已关联）。

### R4 说明区

`?` 按钮：
- **点击** → 就地展开说明面板，展开内容 = 范围说明 + 「更新全部 vs 继续」差异规则 + 本轮明细统计（明细零值同样跳过）
- **悬浮** → 原生 `title` tooltip 显示一句摘要

说明正文原先散在多个 `directory-task-sub` 子行，现按任务归并为一份。归并后每任务的说明文本：

- tmsf：范围（重扫名单+更新用途+挂牌数，新房自动衔接主体匹配，可靠高德主体地址可用于收录）+ 继续（只补未完成及查询失败项，跳过已完成、身份冲突、待地点匹配、来源资料缺失项）
- amap：范围（仅已收录住宅，保留人工结果）+ 更新全部（重查所有符合条件的楼盘，保留人工确认结果）+ 继续匹配（只处理尚未查询、未完成及查询失败／不完整的项目，跳过已完成、未找到及待人工确认项）+ 不设每轮请求总量上限，请求间隔 2 秒
- use：核对用途缺失、其他、冲突、公寓商住等需核实项目及已定位住宅；已有人工决定、明确非住宅和区域异常项不重复查询，发现冲突后由你确认
- rentalMatch：范围（为缺来源的已收录小区匹配幸福里；有歧义的留待确认，不会采集租金）+ 全量匹配（重新查询所有缺来源小区）+ 继续匹配（只查剩余、新增及失败项，跳过已查完的待选择和未找到项，已关联及人工跳过的小区会保留）
- rent：范围（仅已收录住宅中已关联幸福里的小区；采集房源并更新租金统计，不会查找或关联来源）+ 继续采集（只补尚未采集、失败或未完成的小区；已查完但无房源的不重复采集，保留现有成功数据）
- auction：采集滨江法拍，匹配住宅，未匹配进入待关联

pipeline 模式下 `visibleTasks`（`:87-92`）会改写 tmsf/amap 的 label 与 hint，说明文案需跟随 pipeline 变体一致（pipeline 下 tmsf 标题为「采集楼盘名单与资料」、amap 为「匹配楼盘地点与类型」，其 hint 差异已由 `visibleTasks` 提供，说明区需采用同样的覆盖文案）。

### R5 按钮计数格式

`继续X（—）` 改为：数量已知时保留 `（N）`；数量未知或为 0 时不显示括号，文案仅 `继续X`，按钮禁用。

注意：现有测试断言 `继续采集（5）`/`继续匹配（13）`/`继续采集（7）`，说明「数量已知时保留括号」是必须维持的既有契约。

### R6 时间表达

` · 上次结束：2026-10-12 08:01:33（UTC）` 改为相对时间（如 `上次结束 3 周前`），移出正文流，放在指标位。

### R7 保留不动

- 6 个任务的划分、`tasks` 数组（`:73-80`）的 id/path/body/mode 参数
- 「租金流程」分组（表达两步互斥的真实顺序），组头文案压缩为「先匹配来源，再更新租金；两步互斥。」
- 全部按钮的 onClick 动作与禁用条件（`busy` / `!active` / `running` / `rentalBlocked` / `!job?.continuable` / `!job?.incremental_count`）
- 错误 `role=alert` 展示
- 已有 `<details>` 折叠块：`资料待核对`、`待人工确认地点`、`未找到主体地点`、`本轮未完成事项`
- 后端契约与 `Job` 字段

## Constraints

- **不改后端**。所有数据来自现有 `Job` 字段。
- **不用 `<details>` 实现说明区**。现有测试 `directory-flow.test.cjs:213-234` 断言 `<details>` 元素数量恰为 3；新增说明折叠会破坏该计数。改用 React state + `?` 按钮 + `aria-expanded`。
- **不用自定义 tooltip**。项目 community 组件的既有约定是原生 `title`（21 处），自定义 tooltip 仅地图图层使用（`globals.css:167`）。说明区悬浮用原生 `title` 保持一致。
- **相对时间需新增纯函数**。`src/lib/` 无现成工具函数；新增 `src/lib/collection-tasks.ts` 承载纯展示逻辑（徽标归并、指标过滤、相对时间），遵循 `rental-dashboard.ts` 的「纯函数 + node:test 覆盖」惯例。

## Acceptance Criteria

- [ ] 收录采集任务弹框收起状态下，3 个任务各占 1 行，弹框高度在 1 屏内
- [ ] 维护采集任务弹框收起状态下，租金分组内 2 个任务 + 法拍 1 个任务各占 1 行
- [ ] 状态以徽标呈现，phase 覆盖 idle/running/succeeded/partial_failed/failed/cancelled/cooling_down/budget_exhausted/interrupted，每种有确定文案与色调
- [ ] 指标行零值不渲染：`已检查 0 · 已关联 0 · …` 场景下指标区为空
- [ ] 明细统计区零值同样跳过
- [ ] `?` 点击展开/收起说明面板，`aria-expanded` 正确翻转；面板内容含范围说明 + 全量/继续差异 + 明细
- [ ] `?` 悬浮出原生 tooltip 摘要
- [ ] 数量未知时按钮文案无 `（—）`；数量已知时保留 `（N）`
- [ ] 上次结束时间显示为相对时间，不含 `UTC` 字样
- [ ] 6 个任务的按钮点击行为与禁用条件与改造前一致（对照现有测试断言）
- [ ] 「租金流程」分组保留，两任务同组
- [ ] `pnpm lint` 通过；`node --test tests/directory-flow.test.cjs` 全部通过（现有断言需同步更新为新文案）
- [ ] 新增测试覆盖：徽标 phase 归并、零值指标过滤、相对时间格式化

## Out of Scope

- 弹框外的采集入口齿轮按钮（`CollectionTasksButton`，`:232-246`）及其悬浮说明
- 名单列表页、地图侧、资料详情弹框
