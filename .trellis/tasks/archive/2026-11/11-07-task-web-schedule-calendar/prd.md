# task-web 排期日历视图

## Goal

为 task-web（定时任务管理）新增独立「排期日历」tab：按日历 / 每日排期查看执行记录，一眼看出每天任务是否正常、触发时间是否扎堆错开。

## Background

- 现有两个页面：`/tasks` 任务表、`/runs` 平铺记录表，无法按时间维度浏览。
- 数据层已具备条件：`runs` 表有计划时刻（`scheduled_at`）、漏执行补记（`missed_schedule_at`）、状态、`trigger`；APScheduler 可推算每个任务未来的触发时刻。无需改表。

## Requirements

1. 新 tab「排期日历」（`/tasks/schedule`），顶部导航变为：任务 | 排期日历 | 运行记录。
2. 月历总览（左）：周一起始；每格显示当天状态计数（成功 N / 失败 N / 漏 N）；底色优先级：有 failed/timeout → 红、有漏执行 → 紫、全部 success/skipped → 绿、未来日期 → 灰、今天描边；支持 ‹ 上月 / 下月 › 与"回到今天"。
3. 单日排期轴（右）：每个任务一行、0–24h 横轴（6h 主网格线），触发时刻画点：
   - 实心绿 / 红 / 紫 / 蓝 = 成功 / 失败 / 漏执行补记 / 运行中；
   - 空心灰 = 未来计划（cron 推算，不可点击）；
   - 蓝边方块 = 手动触发（不占计划槽）；
   - 红色细竖线 = 现在（仅今天）。
4. 扎堆提示：跨任务同一 `HH:MM` 有 ≥2 个任务触发 → 琥珀色竖带贯穿各行 + 顶部提示条列出任务名。
5. 交互：点月历格子切换右轴日期；点击实心点跳 `/runs/{run_id}`；悬停显示任务名 / 计划时刻 / 状态 / 耗时；分组过滤（全部 / 脚本 / AI）+「只看异常」开关；日期状态同步到 URL `?date=`。
6. 数据口径：
   - 漏执行 = `status=interrupted 且 missed_schedule_at 非空`；普通 interrupted（如重启中断）不算漏；
   - 计划槽来源：过去日期以 runs 记录为准（`scheduled_at` ∪ `missed_schedule_at`）；未来日期以 cron 推算为准；今天以"现在"为分界拼接。
7. 只读页面：不在日历上改 cron / 手动执行，跳转现有页面完成。

## Constraints

- 不改数据库表结构；只新增只读 API。
- 不引入第三方日历 / 组件库，纯 CSS grid + 绝对定位，风格与现有页面一致。
- 时间戳沿用现有 naive 本地字符串（Asia/Shanghai 单机部署），前端不做时区转换。
- 轮询节奏与现有页面一致：当日轴 5s、月聚合 30s。

## Acceptance Criteria

- [ ] `/tasks/schedule` 可用，导航含三个入口；`?date=` 同步选中日期，刷新 / 分享可还原
- [ ] 月历正确聚合当月每天成功 / 失败 / 漏执行计数；未来日期显示计划；可切月
- [ ] 当日轴按任务显示计划 / 实际点；手动 run 为方块且不占计划槽；禁用任务画历史、无未来计划；cron 非法任务行尾有提示
- [ ] 同一时刻 ≥2 任务触发时显示扎堆提示（含任务名）
- [ ] 点击实心点跳 `/runs/{run_id}`；「只看异常」与分组过滤生效
- [ ] 后端 pytest 通过：聚合口径（missed vs interrupted）、三种日期槽来源规则、手动 run 归类、disabled / 非法 cron
- [ ] `apps/task-web` `pnpm build` 通过；现有 `/tasks`、`/runs` 功能不受影响

## Out of Scope

- 周视图 7×24 网格（二期候选）。
- 日历上直接编辑 cron / 手动执行。
- 拖拽调整排期、第三方日历库。
