# service-manager 退役归属字段：列表平铺，归属交给标签

## 目标

台账里不再有「归属」这个独立概念：列表不分两个 tab，24 条服务平铺显示；「这条服务归谁管」这件事
由标签表达（用户已经给「我自己的」那批统一打了 `personal-web` 标签）。

## 背景

- 「归属」有两套说法在打架：字段 `services.ownership`（我维护的 / 别人的）+ 两个 tab，
  以及标签（用户手动打的 `personal-web`）。语义重叠 → 必然漂移：
  本次用户是手工给 11 条服务打了 `personal-web` 标签，如果 ownership 还留着，这 11 条得维护两遍。
- tab 还在**藏东西**：默认只显示「我维护的」那 11 条，另外 13 条要切 tab 才看得见。
  标签筛选是反过来的：默认全显示、按需过滤。

## 已确认的决策（2026-11-14）

| # | 决策 |
|---|------|
| Q1 | **ownership 字段彻底退役**（删列、删下拉、API 不再返回），语义全交给标签 |
| Q2 | 列表**全平铺，不默认过滤**；筛选链 = 搜索（后端）→ 标签（前端 AND） |
| Q3 | **不自动打 compose 项目名标签**：标签完全手动，导入不自动加任何东西 |

## 需求

| ID | 需求 |
|----|------|
| R1 列表平铺 | 列表页不再有「我维护的 / 别人的」两个 tab，24 条服务直接平铺；归属分组下拉（行内）与详情页的归属下拉全部移除 |
| R2 字段退役 | 后端不再接受也不再返回 `ownership`；人工表里该列删除 |
| R3 数据处置 | 旧库的 `ownership` 列**直接删除，不迁移成标签**——用户已手动打好 `personal-web`，迁移会造成重复标签 |
| R4 备份兼容 | 备份导出不再带 `ownership`；旧备份里的 `ownership` 键恢复时忽略，不报错 |
| R5 边界不动 | 不改任何检查口径、不碰 Docker 只读边界；标签体系本身（维护/筛选）行为不变 |

## 不在范围

- 标签体系本身的改动（药丸、弹窗、AND 筛选都保持现状）
- 默认按某个标签过滤（Q2 明确：不默认过滤）
- 导入时自动打 compose 项目名标签（Q3 明确：不要）

## 验收标准

| ID | 可验证结果 |
|----|------------|
| A1 | 列表页没有 tab，24 条服务平铺显示；底部计数显示全部 |
| A2 | 列表行与详情页都没有归属下拉；后端 API 响应里没有 `ownership` |
| A3 | 旧库升级后 `services` 表不再有 `ownership` 列；条数、标签、归属之外的一切不变 |
| A4 | 用升级前导出的旧备份恢复：流程正常，旧备份的 `ownership` 被忽略 |
| A5 | 标签的维护与筛选行为与改动前完全一致（药丸、弹窗、AND、清除标签都在） |
| A6 | e2e 全绿；后端 pytest 全绿；前端 tsc/eslint 0 问题 |
