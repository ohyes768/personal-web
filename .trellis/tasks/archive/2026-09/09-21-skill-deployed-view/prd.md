# skill-manager 右栏改为已部署视图

## Goal

右栏从"手动选择的发布队列"改为以**已部署视图**为主体：按 Hermes / OpenClaw 分组列出当前真实部署的 Skill，让"目标环境现在有什么"一目了然；发布队列保留为辅助流程（加入队列 → 生成计划 → 确认发布），计划预览中醒目区分**新增 / 更新**。

## 背景决策（用户已确认）

1. 右栏改为已部署视图（按 target 分组）——同意。
2. "重复就拒绝"不采纳：已部署 Skill 仍可加入队列并发布，语义是 `update`（更新已部署 Skill 的唯一通道，配套回滚快照）。改为在计划里更醒目地区分新增/更新。

## Requirements

### R1 已部署视图（右栏主体）

- 按 OpenClaw / Hermes 两个分组展示当前已部署的 Skill 条目。
- 数据源：现有 `GET /api/skills` 返回的 `deployments`（前端派生，**无后端改动**）。
- 判定口径：仅 `status === 'active'` 的部署算"已部署"；无记录或 `removed` 不展示。
- 每个条目显示：Skill 名称、revision 前 7 位（有则显示）、发布时间（`published_at`，本地可读格式）。

### R2 回滚 / 下架入口迁移到已部署视图

- 回滚、下架操作入口从左栏卡片行内**迁移**到右栏已部署条目上（单一入口，避免重复按钮）。
- 左栏卡片保留部署状态徽章（已发布/未发布/revision），只读展示。
- 操作流程复用现有 `ConfirmActionDialog` + 密码确认，逻辑不变。

### R3 发布队列保留为辅助区块

- 左栏选 target → 加入队列 → 右栏生成计划 → 确认发布的现有流程不变。
- 队列操作（移除单项/移除 target/清空）不变，仍为纯前端瞬时状态。

### R4 计划预览醒目区分新增/更新

- 计划头部显示汇总："新增 N 项 · 更新 M 项"（N/M 为 add/update 计数）。
- 单项的动作徽章（新增/更新/无需操作/已阻止）视觉权重提升，新增与更新用可区分的强样式。
- 确认发布对话框同步显示该汇总。

## 非目标

- 不做"重复加入队列/重复发布"的拒绝逻辑。
- 不新增后端端点；不扫描目标目录中 registry 之外的目录。
- 不改动发布/回滚/下架的后端语义。

## Acceptance Criteria

- [ ] 右栏顶部呈现按 OpenClaw / Hermes 分组的已部署列表，仅含 `active` 部署；每项有名称、revision、发布时间、回滚/下架按钮。
- [ ] 左栏卡片不再有回滚/下架按钮，部署徽章仍在；从右栏发起回滚/下架流程与原先一致（密码确认、成功后刷新）。
- [ ] 加入队列 → 生成计划 → 发布全流程回归正常；队列内重复添加同一 skill+target 仍静默忽略。
- [ ] 计划预览显示"新增 N / 更新 M"汇总；确认对话框同样显示。
- [ ] 空状态可读：某 target 无已部署 Skill 时显示占位文案。
- [ ] `pnpm build` 与 `pnpm lint` 通过；`queue.test.ts` 通过。
- [ ] 浏览器实测：已部署视图渲染、回滚/下架入口、计划汇总（开发环境验证）。
