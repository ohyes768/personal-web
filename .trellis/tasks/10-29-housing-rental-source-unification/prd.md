# 租金统一切换幸福里：匹配/更新拆分与全量补全上线

## 目标

把「已收录小区的租金来源」统一到幸福里，并把来源匹配与租金采集拆成两个互不越界的独立动作，然后把剩余验收与全量上线做完。

需求原文见 `research/migration-prd.md`（M1–M7 与验收清单），技术方案见 `design.md`，实施进度见 `implement.md`。

## 已完成的事实（不再重做）

- 代码主体已实现并推送 `origin/master`（`c614137` 等）：`/rentals/source-matching` 独立匹配 API、`/rentals/refresh` 改为 `xingfuli_only` 纯采集、旧 Fang 搜索/导入/确认写入口返回 410、两个按钮拆分与分别轮询、服务启动恢复在途任务。
- 后端相关套件 141 passed、前端全量 170 passed、`tsc --noEmit`、`npm run lint` 通过；NAS 生产镜像构建与健康检查通过（Windows 本地 standalone 构建受 symlink 权限限制未通过）。
- 线上 8 个小区试点已完成来源切换（Fang 关联全部解除，7 个关联幸福里，1 个「莱蒙水榭春天」因位置相距约 2.4 公里未绑定），21 条整租详情抽测全部通过但未发布快照。记录见 `research/online-eight-switch.md`。
- 当前线上租金合资格小区：Xingfuli=7、缺来源=148、Fang=0；资格外另有 2 个 Fang 历史关联未操作。

## 本任务要完成的工作

### R1 剩余验收（质量门补齐）

- 浏览器完整交互验收：匹配、待确认主页选择、更新、取消/继续、两个动作互斥按钮状态；桌面与 390px 窄屏布局；旧 Fang 快照不展示为幸福里数据。
- 补冷却到期恢复与真实进程重启恢复的集成回归（当前只覆盖用户取消后新实例继续，未模拟真实崩溃与长冷却）。
- 加固损坏任务文件对服务启动流程的影响。

### R2 断点粒度加固

当前断点粒度是小区：完成的小区不重跑，处理中的小区被中断后会重查。需要把进度持久化到「每个搜索通道 / HTTP 步骤」，使中断后从中断点续跑而不是重查。

### R3 独立迁移工具

原规划的独立批量 Fang 迁移预览/应用工具尚未新增。线上 8 个试点是手工通过既有 API 完成的。要补一个可只读预览、可显式应用、幂等、可按来源恢复、不整库覆盖后续人工操作的迁移工具。

### R4 全量补全上线

- 部署准备完成后核对当前服务任务，备份并执行来源迁移；上线验证无 Fang 网络请求、旧快照不展示、两个任务可启动。
- 小批真实链路验证通过后启动全量批次，报告真实的已检查 / 已关联 / 待确认 / 已采集 / 失败数。长时间运行需配置经用户要求的线程后续跟进，**不能以「启动成功」宣称全量完成**。
- 全量幸福里命中率、有效租金覆盖率，以及「莱蒙水榭春天」的位置冲突，需真实数据核对；离线测试不能替代。

## 验收标准

- [ ] A1/R1：桌面与 390px 浏览器实测通过，两个动作互斥、空状态文案与详情一致，旧 Fang 快照不展示为当前租金。
- [ ] A2/R1：冷却到期恢复、真实进程重启恢复、损坏任务文件不影响启动，三者有集成回归覆盖。
- [ ] A3/R2：中断后从通道级断点续跑，不重查已完成的小区与已完成通道；隔离样本可复现。
- [ ] A4/R3：迁移工具有只读预览、显式应用、幂等与按来源恢复清单；人工拒绝/跳过/排除决定不被清空；隔离生产副本验证迁移前后来源身份一致。
- [ ] A5/R4：线上无 Fang 网络请求、两个任务可启动、备份存在；小批真实链路验证后启动全量批次并如实报告计数。
- [ ] A6/R4：命中率、有效覆盖率与位置冲突以真实数据报告，不承诺 155 个全有来源或足量样本。

## 约束

- 不修改住宅准入、主小区坐标与统计口径。
- 不自动处理验证码，不引入其他搜索服务。
- 历史采集代码可保留作历史兼容，但不得进入当前租金运行路径。
- 生产迁移与全量首次运行必须在代码检查与隔离迁移验证通过之后执行。
- 失败不伪造零租金，不把历史 Fang 快照当当前租金展示。

## 边界

不承诺全量命中率；不做混合分区样本全覆盖；不自动替换既有来源；不提供人工粘贴链接；不做全网无界扫描；不新增定时任务；不做新的位置采集。
