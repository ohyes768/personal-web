# 股息率评级活动队列取消与调序

## Goal

评级弹框只展示正在分析与排队任务；运行中请求真正取消，排队项支持取消、置顶、上移和下移。

## Requirements

- R1：沿用“评级队列”按钮打开弹框，弹框只展示“正在分析”和“排队中”两组；顶部只展示运行、排队数量，没有活动任务时显示“暂无进行中的任务”。正在取消的任务仍留在正在分析组，直到确认结束。
- R2：正在分析项展示股票名称、代码、实际已分析分钟/秒及取消按钮。请求发出后显示“取消中…”，只有确认执行已停止才移出弹框并释放名额；请求失败保留实际状态并提示原因。
- R3：排队项展示股票名称、代码和连续排队序号，提供置顶、上移、下移、取消。首项不能上移/置顶，末项不能下移；取消确认成功后移出队列，其他项补位。
- R4：调序只作用于仍在等待的任务，不打断正在分析任务；新任务默认追加队尾。服务端顺序为准，刷新后仍展示当前实际顺序。
- R5：完成、失败、取消和中断项均不在此弹框展示，不增加历史、报告、重试、批量操作或历史清理入口。此要求仅缩减弹框范围，不删除已有评级结果或列表上的其他功能。
- R6：连续提交、活动项去重、并发上限、关闭弹框后继续运行和页面刷新后重新发现队列继续有效。取消与调序不能误操作同一股票后续重新提交的任务，也不能破坏财务/M120 任务。

## Acceptance Criteria

- [ ] AC1 / R1、R5：混合活动与终态数据时，弹框只出现两组活动任务及运行/排队数量，无终态记录、总进度、失败重试或批量入口；活动项清空后出现空态。
- [ ] AC2 / R2：运行项点击取消显示取消中，确认终止前不释放名额；确认取消后移除。取消请求失败时项仍可见并提示，不能仅因停止轮询而视为取消成功。
- [ ] AC3 / R3、R4：等待顺序 A/B/C 中将 C 置顶后为 C/A/B；A 上移后为 A/C/B；A 下移后为 C/A/B；取消 A 后为 C/B，序号连续。下一空闲名额按服务端最新等待顺序派发。
- [ ] AC4 / R3、R6：取消或调序与任务启动同时发生时，以服务端实际状态为准并刷新提示，不显示假成功、不重复执行、不影响同代码的新一轮任务。
- [ ] AC5 / R4、R6：调整后刷新页面顺序不恢复为受理时间顺序；关闭再打开弹框，实际分析耗时不重置；连续追加与去重仍正常。
- [ ] AC6 / R2、R5、R6：任务恰好先完成时保留有效结果且移出活动列表；旧报告不因取消或隐藏记录被删除。质量队列、刷新任务和筛选页回归通过。

## Confirmed evidence

- 用户明确缩减为正在分析、排队中两组，并授权新建 Trellis 规划任务；本轮仅规划。
- `apps/dividend/src/components/QualityQueuePanel.tsx` 已有按钮/弹框和实时计时，仍展示终态和失败重试；应在此收敛展示。
- `apps/dividend/src/lib/quality.ts:115` 当前按 queued_at 排序，无法反映人工调序；需要服务端等待序号。
- `backend/dividend-select/src/services/quality_service.py:191` 使用 deque；`_run_one:339` 的 Hermes run_id 仅是局部变量，无取消/调序入口。
- `backend/dividend-select/src/services/hermes_client.py:79、98` 只有提交与查询。识别 cancelled 终态并不能证明部署的 Hermes 支持取消请求。
- `backend/dividend-select/src/services/refresh_jobs.py:125` 当前进度是 success 布尔值，无取消计数，不能把取消当失败或遗留未处理数。

## Implementation prerequisite

核实实际部署的 Hermes run 取消能力、确认终止条件和取消后再次提交的幂等行为；记录可复核的接口证据。未核实前不承诺运行取消可用，不以停止轮询代替终止。此项是技术调查，不需要用户重复确认产品范围。

## Out of scope

历史记录、终态操作、报告查看、重试设计、批量操作、拖拽、暂停/恢复、并发配置界面、预估完成时间、服务重启自动续跑、生产部署。
