# 技术设计

- SQLite data/rental_sources.sqlite3 保存确认关联、候选和拒绝状态，事务保障一对一来源绑定。JSON 仅作为一次性迁移源；缺失时读取镜像只读 seed，初始化标记保证解除后不复活。
- 现有 load_verified_mappings 优先消费已初始化数据库，CLI/API刷新复用同一关联。未初始化时保持旧 JSON 契约。
- GET /rentals/sources 返回全量小区及关联；GET /communities/{id}/rental-source 返回当前关联与候选；POST .../search 获取来源候选（支持关键词和限定来源链接）；PUT ... 确认候选，DELETE ... 解除，DELETE .../candidates/{id} 拒绝。
- 搜索候选复用 FangClient 的域/重定向校验和公开页面链接；最多一次列表与一次详情验证。以真实 house-xm 链接提取来源编号，展示名称、地址及对比依据，绝不自动确认。访问异常返回可解释错误，不伪造空成功。
- 关联修改与刷新启动通过 service mutex 串行；修改时同时获取 CLI 发布锁，运行中拒绝修改。summary/detail 按当前关联的来源编号过滤快照，防改绑后沿用旧来源。
- 顶部统一更新入口和“租金来源”管理弹窗；弹窗选择小区，详情复用同一关联组件。无关联提示引导打开管理。任务完成广播事件使看板/详情重取。
- 默认不自动确认、不全量批量抓取。搜索不稳定时可粘贴房天下小区租房链接，程序读取页面验证后呈现候选。
- Docker 保留映射 seed；后端初始化负责一次性导入，不覆盖现有数据库。回滚应保留数据库，恢复旧 JSON 前需人工导出已维护记录。
