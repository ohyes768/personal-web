# 租金来源关联管理与顶部更新入口

## 目标
让用户在房产地图中找到租金更新入口，并通过页面建立、维护租金来源关联，降低逐小区手改 JSON 的维护成本。

## 背景与已确认事实
- 用户指出手写映射难以维护，要求创建任务改进此前讨论的方案。
- 当前更新按钮位于数据看板和小区详情，尚未进入地图与看板共用顶部 Header。
- 后端读取 data/rental_community_mappings.json，仅采集 source=fang、status=verified 的小区。
- 仓库已有风雅钱塘、璞悦湾、东方郡三条映射；运行环境缺失文件时刷新返回 422，页面仅显示“暂无已核验映射的小区可采集租金”。
- Docker 旧数据卷覆盖镜像 data，启动脚本目前未补齐租金映射文件；尚未验证线上是否因此缺失。
- 现有后台刷新、进度、取消、快照和统计模块可复用。

## 需求
R1. 在地图与数据看板共用顶部放置“更新租金”，与现有数据更新操作保持一致；展示任务进度、取消及最终结果。更新范围为全部已确认关联的小区。
R2. 无可采集关联时显示可操作的引导，提供查找来源/管理关联入口；不能仅显示术语报错。
R3. 在小区“租金与收益”中提供“查找租金来源”。程序搜索房天下候选，展示名称、地址、区域、来源链接与匹配依据；不凭名称相似直接确认。
R4. 初期由用户在页面确认候选。存在分期、苑区、重名或证据缺失时明确提示，支持拒绝候选。自动确认留待匹配准确性验证后另行决策。
R5. 关联持久化保存，支持查看、修改和解除；采集复用已确认结果，无需手工编辑文件。保留来源编号、内部编号、证据与确认时间。
R6. 迁移现有三条映射，部署到已有数据卷时可用；启动重复执行不覆盖用户维护结果。解除或改绑后不得展示旧关联租金到新小区。
R7. 明确区分未关联、待确认、已关联未采集、已有数据、采集失败。来源查找失败不得影响地图和其他数据展示。
R8. 实施前验证房天下搜索/访问的可行性；若候选自动发现不可稳定运行，记录证据和替代方案，不以未经验证的结果承诺全量覆盖。

## 验收标准
- 地图和数据看板顶部均能启动同一个租金后台任务；进度、取消和重挂载恢复正常。
- 无关联时可从提示直接进入来源查找流程。
- 用户能在页面完成候选查看、确认、改绑、解除；刷新页面及服务重启后结果保留。
- 覆盖别名、重名、分期和证据不足案例，未经确认的候选不进入采集范围。
- 三条旧关联迁移后可采集；旧数据卷缺文件和重复初始化均有回归验证。
- 关联变更不串小区、不误用旧快照；保持现有统计、部分失败保留旧数据和互斥契约。
- 相关后端测试、前端 lint/type-check 和关键交互验证通过。

## 范围外
全量自动确认、绕过来源访问限制、新增定时采集、净收益/按揭测算、自动部署。

## 实施决定与来源限制
- 用户已要求开始实施，关联持久化选择 SQLite；现有三条 JSON 记录仅一次性迁入。
- 2026-10-12 实测：关键词查询会返回全市房源，页面搜索表单接口返回 404、候选提示接口回到首页。自动查找必须校验关键词实际应用，否则明确失败；可用路径为网页搜索后粘贴小区租房页，后台读取来源候选，用户确认后保存。
- 已用真实璞悦湾来源页面验证名称、地址提取及页面确认流程；不承诺全量自动发现。
- 本地未配置高德密钥时原页面会整页崩溃，本任务补充降级提示，保障来源管理和看板可使用。
