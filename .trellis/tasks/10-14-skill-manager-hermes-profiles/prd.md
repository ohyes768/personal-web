# Skill Manager 支持 Hermes 多 profile

## 目标与用户价值

用户在一个 Skill Manager 服务中，将同一份自研或 GitHub Skill 按需安装到 Hermes 默认环境、命名 profile 或同时安装到多个 profile，并独立查看各目标的安装情况和执行下架。

## 已确认背景与决定

- 用户当前有两个实际 skills 目录：`~/.hermes/skills/`、`~/.hermes/profiles/ohyes768/skills/`。这些是宿主机路径，实施时配置其实际绝对路径。
- 用户已同意一份 Skill 注册表和源库、每个 profile 独立安装记录的服务方案。
- 2026-10-14 用户选择「配置登记」：首版配置上述两个目标，新增 profile 时增加服务配置与目录挂载并重启，不自动发现。
- 当前配置、安装预览/执行和 UI 固定为单目标 Hermes；SQLite deployment 已按 `(skill_id, target)` 区分部署。证据：`backend/skill-manager/src/config.py:28`、`src/services/install.py:41`、`src/services/install.py:149`、`src/db.py:38`、`apps/skill-manager/src/lib/targets.ts:1`。
- 当前 GitHub 同仓库成员共用缓存并直链登记目录，缓存更新立即影响所有链接；自研文件修改立即生效。当前行为以源码及 `.trellis/spec/guides/skill-manager-github-cache.md` 为准，早期任务中的 staging 描述已过时。

## 需求

### R1 配置登记多个安装目标

- 通过受控服务配置定义目标 ID、名称、Hermes profile 名称与 skills 目录；目标清单由服务端返回。
- 首版支持默认环境和 ohyes768，也支持按同一配置格式增加其他 profile，无需修改业务源码。
- ID 表示稳定安装身份，名称可改。更换目录不得静默把现有安装指向另一环境；不可用或移出配置的目标保留既有台账与历史，并明确不可操作原因。
- Skill Manager 管理 skills 安装位置，不创建、删除、重命名 Hermes profile，也不编辑其凭据和运行配置。

### R2 按目标选择和展示

- 管理和安装看板可选择 profile；安装徽章、已安装/未安装筛选、合集安装计数和下架动作均按当前目标计算。
- 单 Skill、合集全部或 GitHub 多选安装在统一确认弹窗中可选择一个或多个目标，展示各目标的新增/更新/跳过/冲突明细；目标切换后重新生成预览。
- 明示所选 profile 名称及目录；默认只选当前目标，用户主动选择才向多个目标安装。搜索不改变「合集全部」的完整成员范围。
- 登记不绑定 profile；「仅登记」不创建任何目标链接。登记后可供所有目标选择安装。

### R3 多目标安装与失败恢复

- 一个确认和一次密码校验可安装到多个目标；登记与仓库准备按 Skill/仓库复用，不能按目标重复登记或无谓重复更新缓存。
- 执行与结果以 `(skill_id, target_id)` 为单位，部分成功保留成功项，冲突或错误不阻止其他目标；只重试失败组合。
- 保留过期计划检测、确认内容指纹、request_id 幂等、后台任务进度和重启后任务丢失提示。
- 目标配置、目录身份或目标链接变化使旧预览失效；不得沿用旧计划把操作转移到新目录。

### R4 独立安装集合与共享内容

- 每个 profile 独立决定安装哪些 Skill；对一个目标下架只移除该目标的受管链接。
- 多 profile 共享同一源版本。更新 GitHub 缓存时，预览说明同仓库所有已链接 Skill 与受影响 profile，包含本次未选中的 profile；更新后统一刷新实际版本与更新提示。
- 「安装成功」代表服务确认目标链接正确，不等于已经验证 Hermes 的技能发现、运行能力或各 profile 独立版本隔离。

### R5 存量与分类兼容

- 旧 `hermes` 目标 ID 和部署/历史原样保留，按现有配置根保持安装身份；上线前核对该根对应的实际环境，不得为显示名称而转移链接位置。升级不要求重新登记或安装，也不把旧安装自动复制到 ohyes768。
- Windows 等 ZIP 导出目标保持原有语义；未配置/不可用的 Hermes profile 记录不能误判为导出记录或清除。
- 任何 Hermes profile 仍有有效安装台账时，登记/缓存删除必须提示对应目标并阻止源被误删；无法访问目标时不能推断其安装已解除。
- 启动兼容迁移只处理已记录且目标可用的安装，不自动在新增 profile 建链接，不联网更新仓库。

### R6 文件系统与运行环境

- 请求仅传目标 ID；后端从受控配置解析目录并保持源库、缓存、目标路径边界。普通文件/目录、非受控链接占位继续明确阻止。
- 宿主机、管理容器和 Hermes 执行环境均可解析链接源路径；沿用同路径挂载，只增加所需 skills 目录，不挂载整份 profile 凭据目录。
- 缺目录/无权限时按目标显示不可用，不自动创建 profile 目录。错误密码、非法/未知目标、无效参数不产生登记或安装副作用。

## 验收标准

- AC1 / R1：服务配置两个及三个目标均无需改源码；返回准确名称、目录与可用状态。缺失一个目标不影响其他目标和导出。
- AC2 / R2：相同 Skill 在默认已装、ohyes768 未装时，切换后的徽章、筛选、合集计数正确；多目标确认明确显示实际写入位置。
- AC3 / R3：同 Skill 安装到两个目标只登记一次，两条链接指向相同受控源；目标 A 成功、B 冲突时能只重试 B，A 不重复执行。
- AC4 / R3：重复提交不重复执行；目标根、链接或来源在预览后变化时报计划失效；任务重启丢失后引导刷新真实状态。
- AC5 / R4：仓库更新预览包含所有已链接 profile；共享缓存更新后各 profile 的直链读取新版，单目标下架不影响其他目标及源文件。
- AC6 / R5：旧库升级保留 `hermes` 台账/审计和原链接，ohyes768 不自动获装；移除配置的 profile 仍显示历史且阻止错误源清理；导出与退役 OpenClaw 行为不回退。
- AC7 / R6：非法目标、普通目录占位、逃逸链接、目录替换、错误密码可诊断；同路径挂载确保宿主机链接可解引用。
- AC8 / R1-R6：实施阶段完成针对性后端/前端检查与模拟交互验收；真实 Hermes 的 profile 发现与读取另列部署验收，记录实际版本和执行环境，不用模拟结果代替。

## 范围外

自动发现 profile、网页编辑任意服务器路径、自动给新 profile 安装、profile 创建/删除/重命名、反向导入 Hermes 自建 Skill、逐 profile 固定版本/复制快照、定时更新、真实 NAS 部署或清理。
