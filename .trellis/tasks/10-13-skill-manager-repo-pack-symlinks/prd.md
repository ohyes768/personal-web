# Skill Manager 整包仓库软链安装与更新

## Goal

用户只添加、安装、更新和卸载 GitHub 仓库包，不选择、登记或逐个发布子 skill。Hermes 和 OpenClaw 各通过一条包软链读取同一份本地 Git 仓库；更新后链接不变，不生成 GitHub 发布快照，也不需要再次发布。

## Background / Confirmed Facts

- 用户已明确选择“软链直接指向仓库”，随后授权实施；最新指示仅做 Windows 测试，不再做 WSL 验证。
- 当前缓存已按 repository 共享，但登记、发布和部署状态按单个 skill。证据：backend/skill-manager/src/models.py:85、src/services/git_cache.py:457。
- 当前 Publisher 要求源顶层有 SKILL.md，GitHub 发布依赖 staging/<skill-id>/<rev12>；不能只把登记 path 改为点号。证据：src/services/publisher.py:79、:150。
- 当前 fetch + checkout --force revision 可留下 detached HEAD；直链后不能沿用逐子 skill 的强制 checkout。证据：src/services/git_cache.py:457。
- 前端要求候选/shared_paths 多选，卡片与队列按 skill_id。证据：apps/skill-manager/src/components/RegisterGithubDialog.tsx:20、SourceWorkspace.tsx:74。
- 当前 Hermes 上游支持递归扫描并跟随目录软链；OpenClaw 支持分组目录，但工作区外部软链有信任配置要求。NAS 实装版本尚未核实；来源和实施验证项见 research/findings.md。
- ai-berkshire 依赖仓库根 tools/、AGENTS.md 和其他参考文件，须保留原始布局并验证工具执行路径。文件发现成功不代表所有工作流已适配。

## Requirements

### R1 整包添加与展示

- 一个规范化 repository 对应一个包，同源重复添加返回已有包；根没有 SKILL.md 但内部有有效技能的仓库可添加，零技能明确报错。
- 输入 URL 后系统准备仓库并发现技能；包卡片显示名称、来源、技能数量、标签和目标状态；详情中的子技能清单只读。
- 删除子技能选择、逐项登记与共享资源勾选步骤；数量来自文件发现而非 README 或写死 22/13。
- 添加与安装分开：添加登记整包，安装选择 Hermes、OpenClaw 或两者；保留现有密码边界与后台任务进度/失败恢复。

### R2 一包一目标一条软链

- 每包在每个目标目录仅创建一条包软链，realpath 直接指向同一完整仓库根；共享资源保持上游目录关系。
- 安装不复制技能、不生成 staging/版本目录、不生成根级包装 SKILL.md；包链名避免与其他包/自研目录冲突，内部 skill.name 保持上游值。
- 目标可独立安装/卸载；未知链接、普通目录、同名内部技能冲突必须可诊断，不能直接覆盖。

### R3 仓库级手动更新

- 检查更新只读远端信息；“更新仓库”后台同步所跟踪默认分支，成功后所有已链接目标读取新版，无再次发布步骤。
- checkout 路径、软链名称及目标保持不变；commit 仅为系统状态/审计，用户不管理版本号。
- 同仓库写操作互斥；旧子 skill API/启动重发布不得再对包仓库执行固定 revision checkout。
- 本地修改、分叉、网络失败、超时、工作树落地失败分别报告；禁止强制覆盖/静默 reset，不伪报成功。
- UI 明示更新同时影响已安装此包的目标；工作树就地更新不承诺运行中调用得到一致快照。

### R4 Agent 兼容与可用性

- 验收两个 Agent 的真实包级软链、递归发现、全文读取和更新后的内容；管理台扫描成功不能代替 Agent 清单验收。
- 核实实际版本/profile/目标根；OpenClaw 必要时仅信任受控仓库目录，不扩大到整个 HOME。
- 宿主机、管理容器和 Agent 工具执行环境均能访问仓库与工具路径，遵守现有同路径挂载契约。
- ai-berkshire 至少验证一次共享工具路径及调用；多 Agent/API 能力不等价单独报告，不宣称全工作流已兼容。
- 不支持整包软链的目标应报告不兼容；不得偷偷退回逐子技能软链。

### R5 存量转换

- 按 repository 合并旧 GitHub 登记为包，保留标签、历史和旧 ID 映射，数据迁移幂等。
- 启动只做数据归并，不联网、不更新、不自动把旧部分安装扩成整包；显示“旧安装待转换”。
- 用户在包上一次转换目标，预览说明将安装全部技能，不要求勾选子项；新链验证与旧链替换可恢复，失败不破坏旧安装。
- 缓存缺失、旧版本不一致、仅单目标安装、未知路径冲突分别处理；快照有引用时保留，解除引用后才能清理。
- 重启不得由旧迁移逻辑重建 staging 或恢复已转换的子 skill 软链。

### R6 生命周期与边界

- 有 active/旧安装引用的包不可直接删除仓库；清理仅限可确认归属的受控目录。
- 自研 skill 保持单技能管理，导航、标签、动态导出目标及旧导出台账不丢失。
- 本任务不新增整包 ZIP/Windows 安装；包卡片不挂尚未实现的整包导出按钮，旧导出数据/API 保留兼容。
- 保留 URL 校验、密码不进任务/日志、任务轮询和缓存缺失修复能力。

## Acceptance Criteria

- [ ] AC1 / R1：两示例各一包卡片，无子技能/资源选择；离线 fixture 22/13，实仓按验收 HEAD 重算；重复 URL 不重复登记。
- [ ] AC2 / R2：每包每目标恰一条链，realpath 为同一仓库根；根无 SKILL.md 可安装，无新 staging/rev 目录。
- [ ] AC3 / R3：上游修改/新增/删除技能后更新一次，已链接目标读到新版；readlink 内容及链接 inode 不变，不需再次发布。
- [ ] AC4 / R3：检查不改工作树；dirty/diverged/并发/网络错误/默认分支变化/旧 detached HEAD 有明确结果；旧接口不得改变包仓库版本。
- [ ] AC5 / R4：Linux/NAS 两实际 Agent 均发现并读取示例技能，信任设置和工具路径验证；不兼容有明确原因而非成功徽章。
- [ ] AC6 / R5：旧多登记、多目标/版本、部分安装、缺缓存、冲突、转换中断、重复迁移及重启可验证，不丢历史、不重复发现。
- [ ] AC7 / R6：单目标卸载不影响另一目标；引用阻止误删，未知目录不覆盖；自研发布与旧导出回归通过。
- [ ] AC8 / R1-R6：后端 Windows 测试、前端 lint/typecheck/test 通过，spec/部署说明更新；依用户最新要求停止 WSL，权限限制产生的真软链跳过明确记录。

## Constraints / Out of Scope

- 无定时自动更新、版本选择/锁定、新快照/回滚功能、强制 reset/clean；不修改上游技能名。
- 无未决产品选择；Agent 实际版本与兼容性是实施门槛。不兼容时记录事实，不能自行替换已确认方案。
- 当前工作区有其他任务改动，不得覆盖；当前任务已进入实施，不提交或部署用户未要求的外部变更。
