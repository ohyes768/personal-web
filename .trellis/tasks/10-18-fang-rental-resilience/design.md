# 设计：共享请求策略与增量租金采集

## 方案选择

推荐保留 curl_cffi，增加共享请求策略与磁盘详情缓存。只延长 sleep 无法消除重复请求和跨入口访问；浏览器方案增加依赖且未证明需要，暂不引入。

## 模块与数据流

- 新增 src/services/fang_request_policy.py：负责同源互斥、5 秒间隔、可取消等待、超时有限重试和持久风控状态。DATA_DIR/rentals 下保存版本化状态；测试注入时钟和临时目录。
- 新增 src/services/fang_detail_cache.py：缓存成功验证的静态详情。键包含来源、房源 ID、来源小区；记录 detail_verified_at，7 天过期。缓存仅合并 address/property_type 等允许字段，不保存动态价格作为缓存来源。
- fang_rentals.py 的请求统一经过策略，重定向每跳独立验证和限速；详情滑块不能再被普通异常分支吞掉。缓存命中仍满足 detail_fetched 统计契约，验证时间不改写。
- refresh.py 先抓已有来源，后做有限发现；新绑定来源下一轮采集。6 小时内当前来源匹配的 complete/empty_ok 快照归入复用集合。
- sources.py、association.py、directory_collection.py 与 CLI 共用策略和缓存，防止其他入口绕过冷却。
- rental_routes.py 与现有租金更新 UI 增加可选诊断字段，兼容旧任务，不单方面改变 phase 枚举。

## 请求、冷却与重试

同源跨入口单并发，前一次结束到下一次开始至少 5 秒。使用稳定的 OS 锁路径协调多进程，状态 JSON 原子替换不改变锁身份；锁等待、限速和重试等待均可取消。冷却期立即返回暂停信息，不让线程休眠数小时。

冷却状态包含 version、challenge_level、cooldown_until、last_request_at（UTC）。挑战按 1h/6h/24h 升级；仅完整成功的真实租金更新重置等级，冷却到期或单次列表成功不重置。超时最多一次重试，退避至少 30 秒，连续两次超时暂停本轮但不冒充滑块冷却。非法跳转继续拒绝，仅记录安全的主机/路径诊断。

## 缓存与发布

缓存只保存已识别的成功详情；损坏或过期视为未命中，定期清理过期条目。详情年龄与本轮列表 captured_at 独立。列表成员由当次列表确定，缓存不能复活已下架房源。

小区复用必须核对当前 matched 来源、目录成员资格和完整成功状态，不使用失败轮次或目录待审样本代替。全部复用不调用发布、不改 last_success_at。混合发布需显式传入保留集合：现有 publish_run 仅遍历本轮 batches，直接省略复用小区会造成快照丢项。保留条目的 captured_at 不变；部分详情、截断、失败仍不作为完整新数据发布。

## 兼容、风险与回滚

新增缓存文件缺失可从空开始；冷却文件损坏要有诊断和短暂保守暂停，不能静默绕过。API 新字段缺失按零或空值兼容，缓存复用不计入真实采集成功。保留已有编辑互斥、发布锁和发布前来源重查。回滚代码保留原快照，不反向改写租金数据；上线和 Git 提交另行授权。

## 验证

假时钟、注入 HTTP 与临时目录覆盖请求数/顺序、取消、冷却重启、跨入口互斥、缓存字段、来源更换和混合发布；前端验证旧响应和暂停提示。真实烟测限少量列表与一条详情，不以全量访问验证抗风控。
