# 幸福里来源匹配改用小区资料 API 与按需租房入口

## 目标
为“匹配租金来源”及单小区探查使用已验证的小区 JSON 接口替代主页 HTML。搜索候选先核对身份，只有自动确认或用户选择的目标才获取租房入口，减少无关候选的数据获取。不得承诺仅替换为 API 即减少请求或固定倍数提速。

## 已确认事实
- 搜索已使用 API；当前 `homepage()` 从一页 HTML 同时解析身份与租房种子。
- `GET /f100/api/neighborhood/info?neighborhood_id=...` 已在万科璞悦湾、欣盛东方郡只读验证成功，返回真实 ID、名称、地址、城市、区域、GCJ02 坐标；璞悦湾与主页身份字段完全一致。
- `GET /f100/api/same_neighborhood_rent?neighborhood_id=...&city_id=1853&offset=0&count=10` 已在璞悦湾成功，返回 total=24、10个种子，均与主页一致。该接口条目没有明确 neighborhood_id，不可据此省略归属核验。
- 新接口是网页使用的公开接口，未验证长期或全量稳定性；拆成两个请求可能比原一页更多。

## 范围与要求
1. 批量来源匹配、继续匹配、单小区探查、候选选择与重试共用同一资料/入口实现，避免仅优化某个入口。
2. 搜索阶段只获取候选资料并执行现有名称、地址、坐标、分期和行政区域判断，不为每个候选预取租房种子。有歧义仍待人工选择。
3. 自动唯一强候选或用户明确选择后再取租房入口；恢复和选择必须重新取得新鲜身份/入口，并按当前目录重算判断，保留详情与同小区列表双重归属核验。
4. 所有真实 HTTP 继续经过共享限速、冷却、取消和请求预算；每次请求分别计数，不能把组合方法内的两次请求只计一次。遵循共享传输层当前间隔，不在本任务重复修改3秒设置。
5. 资料成功步骤复用已有SQLite断点体系；身份、版本变化、过期或损坏须重查。缓存不保存绑定授权，错误与冷却不伪装成功空结果。
6. 保留人工拒绝/跳过、现有来源、完整性判定、任务互斥与重启恢复。非租金来源拒绝不能影响租金匹配。
7. 资料失败、租房入口失败、真实无入口与未尝试获取入口必须区分；资料API只返回HTTP200不算身份成功。名称/ID/城市不一致或字段异常不可自动绑定。
8. 当前前端/API业务状态契约保留；入口未查询时不能误显示“无房源”。默认走新接口，不额外设计配置开关或静默HTML降级。

## 验收
- 两个已验证小区的资料字段与主页证据一致；对有效/错ID/错城市/缺字段/冷却/错误数据建立回归。
- 多候选待选择阶段只查资料，无租房入口/详情归属请求；选择目标后仅为该目标查新鲜资料/入口并双核验。
- 唯一强候选能成功绑定；竞争候选、不完整搜索、冲突候选保持现有保护。
- 缓存重启复用、版本迁移、预算边界（含入口API）、取消与互斥有回归；旧缓存不可被当成新鲜授权。
- 记录同等输入下旧/新真实请求数、等待与HTTP耗时；唯一强候选可能新增一次入口请求，必须如实报告，不宣传必然提速。
- 后端相关及全量测试通过；小批只读验证不修改生产关联或发布租金快照。

## 不包含
