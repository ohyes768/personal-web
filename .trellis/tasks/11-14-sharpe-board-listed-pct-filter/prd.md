# 夏普榜单在榜占比筛选 + 精简时间范围

## Goal

把榜单的展示筛选从「至少上榜 N 周（整数）」改成**「在榜占比 ≥ N%」**（默认 60%，可手动修改），
并去掉时间范围里与「近一年(52周)」完全等价的「近 1 年」选项。

## 背景与动机

- 「至少上榜 1 周」这个下限几乎不过滤（窗口内 53 只基金全部通过），用户看不出这个筛选器在做什么；
  真正想表达的是「这只基金在榜是否稳定」。
- v4 口径引入「可评周数」（该基金有有效样本的周数）后，表格已经直接显示 `在榜/可评` 分数，
  筛选条件理应与这个分数同源：**在榜占比 = 在榜周数 ÷ 可评周数**。
- 时间范围里 `all`（近一年 52 周）与 `1y`（近 1 年）在 v2 之后**完全等价**（`_RANGE_WEEKS`
  两个都是 52 周），下拉里两个选项是重复的。

实测（生产库 v3，source=all，53 只命中）：

| 占比下限 | 通过只数 |
|---|---|
| 0%（= 不限） | 53 |
| 50% | 41 |
| **60%（新默认）** | **32** |
| 80% | 22 |

## Requirements

### R1. 在榜占比筛选（替代 min_weeks）

- 参数：`min_listed_pct`（百分比，0~100，默认 **60**）。
- 判定：`listed_weeks / evaluable_weeks × 100 >= min_listed_pct`（含等于）。
- **硬门槛保留**：窗口内在榜 0 周的基金任何下限都看不到（沿用旧 API `min_weeks≥1` 的语义，
  避免「0/52」的噪声行）。
- `min_listed_pct=0` ≡ 不限（等价旧 `min_weeks=1`）。
- 旧参数 `min_weeks` **下线**（API 与 URL 都不再接受）；旧链接 `?min_weeks=3` 落到默认值 60%。

### R2. 前端可手动修改

- 筛选条上「至少上榜 [60] %」是**可编辑数字输入**（0~100，步长 1），不是固定值也不是只能选预设。
- 表头/输入框要说明分母口径：在榜占比 = 在榜周数 ÷ 可评周数。

### R3. 时间范围精简

- `RANGE_OPTIONS` 去掉 `1y`（与 `all` 等价），保留「近一年(52周)」「近 6 个月」「近 3 个月」。
- 旧链接 `?range=1y` → 回落到默认（52 周视图），**行为不变**。
- 下拉顺序改为按时长升序（3 个月 → 6 个月 → 近一年）。

### R4. 不改动

- 入选规则、profile、发布流程、排序、图表、表格列口径（`在榜/可评`）均不变。
- `range` 仍只裁图、不改统计。

## Acceptance Criteria

- [ ] AC1：后端 `GET /api/funds/sharpe-board?min_listed_pct=60` 只返回占比 ≥60% 的基金；
      003598（51/51=100%）在列、012124（51/52=98%）在列、210002（10/52=19%）不在列。
- [ ] AC2：`min_listed_pct=0` 返回全部「曾在榜」基金（等价旧 min_weeks=1）；越界参数 422。
- [ ] AC3：前端筛选条显示「至少上榜 60 %」，可改成任意 0~100；改后 URL 带 `min_listed_pct`。
- [ ] AC4：时间范围下拉只有 3 项，无「近 1 年」；`?range=1y` 的旧链接仍显示 52 周曲线。
- [ ] AC5：后端 pytest 全绿、前端 node 测试 + tsc + build 通过；spec 文档同步。
