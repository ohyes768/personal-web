# kids-catalog 手动链接导入下载新合集

## Goal

在宝宝音频库（kids-catalog，服务哆咪音箱）加一个手动导入入口：用户粘贴喜马拉雅/蜻蜓 FM 的**专辑链接**，点「获取」，系统解析链接、校验可下载性、加入目录并自动开始下载；下载完成后走现有歌单生成流程，在设备上形成新合集。

## Background

现有目录只来自月度榜单采集（`collector.collect_latest()`，0-1 岁年龄筛选、每平台 10 张、全量替换）。
用户偶尔会自己看到想给宝宝的专辑，榜单覆盖不到，需要一个直达入口。

## Requirements

### 入口交互

- 前端页面头部提供输入框 +「获取」按钮
- 支持的链接格式（专辑维度）：
  - 喜马拉雅：`www.ximalaya.com/album/{id}`、`m.ximalaya.com/album/{id}`（容忍尾斜杠/查询参数）
  - 蜻蜓：`www.qingting.fm/vchannels/{id}`、`m.qingting.fm/vchannels/{id}`
- 单曲链接（如 `sound/{id}`、`radio/{id}`）不支持，报错并提示需要专辑链接
- 点「获取」后**一步到位**：解析 → 预检 → 入目录 → 自动开始下载（用户拍板，不走两步确认）

### 预检与拒绝规则（延续策略 A：只下免费）

- 整张付费专辑：拒绝导入，明确提示「付费专辑不支持下载」（免费接口拿不到直链，平台限制）
- 已下架专辑：拒绝导入，透出平台原因（喜马拉雅 ret=924 等）
- 链接无法识别 / 非上述两平台：报错，不入目录
- 免费专辑内的部分受限曲目：允许导入，下载时逐条跳过，最终呈现「部分完成」（与现有榜单专辑行为一致）

### 目录与生命周期

- 手动专辑在 albums 表标记来源 `manual`，与榜单来源 `chart` 区分
- **月度榜单刷新只清理 chart 来源**；手动专辑及其下载记录跨月保留
- 手动专辑不做年龄筛选（用户自主判断）：新导入行 `age_evidence` 记「手动添加」；
  若该专辑同时也在当月榜单中，保留平台给的年龄依据，来源仍以 `manual` 标记为准
- 重复导入幂等：已在目录 → 返回当前状态；已下载完成 → 不重复下载
- 列表中手动专辑展示「手动添加」标记，与「本月精选」榜单专辑可区分

### 下载与合集（零新逻辑，复用现有链路）

- 下载复用 `Downloader.download_album`（喜马拉雅 mobile 接口 / 蜻蜓 capi 接口）
- 下载 done 后进入 `DeviceCollections` 现有校验/生成流程，生成歌单后即成为设备新合集
- 手动专辑与榜单专辑同名导致目录冲突时，沿用现有 `CollectionError` 提示

## Acceptance Criteria

- [ ] 输入喜马拉雅免费专辑链接点「获取」：目录出现该专辑（手动标记），自动开始下载，完成后生成歌单含该合集
- [ ] 输入蜻蜓免费专辑链接：同上
- [ ] 付费专辑链接：入口处明确报错，不入目录不建 job
- [ ] 已下架专辑链接：报错并透出平台原因
- [ ] 非法/不支持链接：报错提示支持的范围
- [ ] 触发月度刷新（`POST /api/refresh`）后，手动专辑及其下载状态仍在
- [ ] 同一专辑重复导入：幂等，不产生重复行/重复下载
- [ ] 后端 pytest 覆盖：链接解析、预检拒绝分支、refresh 保留 manual、import 幂等
- [ ] 前端 build 通过

## Out of Scope

- 单曲链接导入、其他平台（荔枝 FM 等）
- 付费内容下载（会员凭据/破解不在范围）
- Music Assistant / 设备端协议改动
