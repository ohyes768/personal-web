# 技术设计（已实施）

## 方案
推荐统一小区目录＋来源原始记录＋持久人工决策，SQLite 保存。备选：仅扩展租金弹窗（难以容纳四来源、无地图小区）；多份 JSON 映射（并发和留痕分散）。按用户确认，只维护现有部署的一份目录；现有数据一次整理，不建设新部署初始化或多版本兼容体系。

## 页面
主导航新增“小区数据管理”。搜索标准名/别名/来源名，按区域、来源、待关联/已关联/忽略状态筛选；列表展示名称、地址、来源 ID、关联及地理状态。详情侧栏展示来源证据与人工关联/解除/编辑/合并/删除。已删除列表可恢复。独立管理 API，不复用被地图过滤的列表，不依赖 Amap 成功加载。

## 数据维护
建议 data/community_registry.sqlite3：communities（稳定 ID、标准名、区域、地址、分期、状态、版本）；aliases；source_records（source/source_kind/source_id 联合唯一、原始名/地址/坐标系/链接/发现时间）；associations（有效主记录、auto/manual 方法、依据）；decisions（忽略身份、删除主记录、拒绝关联对、恢复、合并等事件及原因/时间）；collection_runs（进度、数量、错误、截断）。
既有 TMSF 内部 ID 保持不变，新主记录使用独立命名空间。来拍 source_kind 为 asset/auction，不伪造来源小区 ID。别名可对应多个真实小区。人工决策和有效状态同事务保存，原始名不被标准名覆盖。
将现有 TMSF JSON、Fang SQLite 映射与拒绝候选、来拍映射一次整理入统一目录，整理前备份。随后采集、页面和业务查询统一使用这一份；旧映射不再作为维护入口或启动导入来源，不建设旧版本适配层。现有调用方随功能一起调整。合并通过保留 ID/重定向解析历史，价格按 TMSF 身份查询，无身份时为空。

## 采集与关联
来源列表 → 稳定身份忽略检查 → 幂等保存 → 名称候选 → 证据评估 → 自动关联/待确认。TMSF 复用名录脚本；Fang 区域分页结构化小区链接，不依赖已知失效关键词；来拍复用拍卖观察；Amap 复用 POI/坐标并补名称发现适配。实际入口及完整分页需实施前小样本核验，不能把已有文件导入当成新发现全区采全。
归一只处理空白和字符形式，保留南北区/分期等语义。新自动关联要求完整名或人工别名一致、候选唯一、同区且地址一致或统一坐标系后位置吻合、无分期冲突。位置阈值实施前依据本地样本校准。模糊名称只排序候选。人工关联、拒绝/解除和忽略优先；自动重跑不得恢复被人工解除的组合。
来源失败独立报告；取消/截断明确状态。采集与人工编辑并发采用版本检查，发布前重新读有效决策，避免采集中删除被复活。已知忽略身份尽早过滤，阻止独立详情抓取；共享区域列表仍会请求。源 ID 变化时保留疑似忽略提示，不全局按名称删除。

## 删除语义（用户已确认）
删除已归一的小区时，在同一事务软删除主记录并忽略所有当前绑定来源，停止详情采集与业务展示；不提供将同一删除按钮解释成只删除一个来源的行为。解除/拒绝关联是独立操作，仅改变关联组合。未关联候选删除只能记录已知来源身份，不以名称扩大到其他小区。历史样本不物理删除。显式恢复主记录及本次删除联动的来源，保留其他独立忽略决策；记录恢复事件。页面清楚展示整小区删除影响。

## 目录来源
现有 TMSF 名录一次整理入统一目录，后续接受四来源并集，不以是否存在 TMSF ID 为准入条件。Fang 结构化租房小区链接、Amap 住宅小区 POI、来拍标的中的小区名与地址均可产生来源候选；自动或人工核验后关联已有主记录或建立新的主记录。来拍观察不视为独立的小区名录；POI 楼栋/出入口和道路不可直接当真实小区。售价、租金和地理信息的字段来源分别保留，不因某来源缺失丢弃整个小区。

## API、业务接入与备份
使用现有 /api（外部 /api/map）前缀及 success/data 包装。提供分页目录/来源/详情、编辑、关联/解除、合并、忽略/删除/恢复、采集/自动关联运行与取消；具体路由和类型实施前冻结。参数错误422、未知404、版本冲突/互斥409、存储故障503；来源故障写运行报告。
价格、租金、法拍刷新与查询都需尊重有效目录决策，保留现有统计口径和部分失败旧快照契约。改绑/解除后旧来源快照立即不可用。名称采集独立于人工映射，样本关联后可重算。更新 rental-sources.md 中“始终人工确认”的旧契约。
整理前备份并验证数据完整性，目录持续持久化保存，可从备份恢复。不设计双写、自动种子导入或旧版本读取切换流程。本次不新增边界绘制数据模型。
