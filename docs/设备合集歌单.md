# 设备合集目录

在 `/kids` 下载当月合集后，点击“生成歌单”。web 从这些合集的 NAS 文件统计曲目数，按从少到多生成编号与专辑名称清单。设备显示这份清单；播放方取得专辑名称后，再交给 MA 查找和播放。

## 生成规则

- 来源仅为 kids 当前页面中下载状态为 done 的当月合集；其他 NAS 专辑和 cache/tmp/download 等目录不参与。
- 生成与编号查询不需要 MA 地址或 token，也不检查 MA 专辑关联、曲目展开或500首限制。目录生成成功不代表实际播放已经验证。
- 保留下载完成依据及 NAS 校验：正式 MP3/M4A 可读取且非空，排除封面、附件、临时下载、损坏文件、链接和嵌套目录。文件名不必带曲序，标签不必提前整理。
- 当前来源缺少完成依据时，核对完整后点击确认，再生成。确认其他历史目录不能绕过当月来源限制。
- 按实际音频文件数升序，同数保持确定顺序，编号1-N。只有手动生成成功才更新；新下载不会自动改变编号。
- 生成失败、无可发布项或容量超限时保留旧清单。候选榜单刷新不会删除已发布目录；下次生成才采用新的当月来源。
- 并发生成互斥。目录最多500个合集、单名称256 UTF-8字节、JSON 128 KiB；不静默截断。单个合集曲目数不受 MA 的500首查询限制。

## 设备与名称查询接口

经 nginx/Next 代理访问；直接访问后端时将 `/api/kids/` 换成 `/api/`。

```http
GET /api/kids/device/v1/collections
```

```json
{"schema_version":1,"revision":"opaque-version","generated_at":"2026-10-20T01:00:00+00:00","items":[{"number":1,"title":"小妃摇篮曲","track_count":8}]}
```

设备显示“1. 小妃摇篮曲（8首）”。开机及周期读取，完整合法响应整体替换，失败保留内存旧目录。选择时携带当前展示的版本：

```http
GET /api/kids/device/v1/collections/by-number/1?revision=opaque-version
```

```json
{"revision":"opaque-version","number":1,"title":"小妃摇篮曲","track_count":8}
```

播放方使用 `title` 对接 MA。查询不检查或开始播放，也不返回 MA URI。旧接入方需停止读取原 `media_type`/`ma_media_uri` 字段，改为名称流程。

错误 `detail` 含 `code` 和 `message`：未生成目录404 directory_missing、未知编号404 number_missing、旧版本409 revision_expired。旧版本必须刷新后重新选择，不能自动换成新版本同编号。名称查询不因 NAS/MA 暂不可达而失败。

## 管理与存储

- GET `/api/kids/collections` 返回 snapshot 与 generation；二者来自同一数据库读快照。
- POST `/api/kids/collections/generate` 返回202；生成中重复请求返回409。
- POST `/api/kids/collections/confirm` 接收 `{"folder":"直属合集目录名"}`；无效文件、路径或下载中返回422。
- 完成依据和当前目录保存在 `/app/data/device_collections.sqlite3`。现有数据库无需删除；旧 targets 字段留作结构兼容，新发布写空对象，查询忽略旧MA映射。
- 现有 `.env` 中的 MA 配置可保留供后续播放接入，生成目录不读取它们。此流程不修改音频或 MA 曲库。

本仓库交付目录服务及管理页面。ESP32、HA按名称查找播放、重名处理与播放完整性属于关联接入工作，不能用目录测试代替实机验收。
