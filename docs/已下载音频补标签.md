# 已下载音频补标签：让 MA 按合集生成专辑

工具位于 backend/kids-catalog，入口为 `python -m src.tag_audio`。仅处理现有文件；新下载流程尚未接入自动标签。

## 规则

- 音频根目录的直接子目录视为合集，目录名作为专辑名。例如 `/music/宝宝巴士/001-小兔子乖乖.m4a` → album=宝宝巴士、title=小兔子乖乖、tracknumber=1。
- 仅支持真实 MP3/M4A，文件名必须为 `正整数-标题.扩展名`；编号可不连续，但同合集不能重复。不推测无编号文件的顺序，不处理 `.part`。
- 只补缺失。已有专辑、标题或曲序与推导值冲突时整文件跳过。`1/20` 与推导的第 1 首一致，保留原值。
- 专辑艺术家优先复用同合集唯一的已有专辑艺术家；没有时复用唯一的已有艺术家；仍无法确定时用“哆咪音频”（本地整理标识，不代表真实创作者）。同合集出现多个不同专辑艺术家时整体报告冲突。
- 艺术家缺失时补为选定的专辑艺术家，已有艺术家保留。现有流派、封面等交给 Mutagen 保留；不写虚构 MusicBrainz ID。
- 不跟随 symlink/junction，不重命名、不移动、不重新下载、不转码。暂不支持多碟嵌套目录或同目录多个专辑的自动整理。

## NAS 执行：先一个合集

以下命令在 NAS 的 personal-web 仓库目录执行。先确保当前代码和镜像含 Mutagen；镜像重建会更新正在运行的 kids-catalog 后端，选择空闲时段操作：

```bash
docker compose -f docker-compose.nas.yml build kids-catalog-backend
docker compose -f docker-compose.nas.yml up -d --no-deps kids-catalog-backend
```

现有 Compose 将主机 `KIDS_MUSIC_HOST_PATH` 挂到容器 `/music`。MA 应挂载/访问同一主机目录；MA 内部路径可不同。不要误填宿主机路径给容器命令。

1. 预览（将示例名称替换为 `/music` 中真实存在的合集目录名）：

```bash
docker compose -f docker-compose.nas.yml exec -T kids-catalog-backend python -m src.tag_audio --root /music --album '宝宝巴士'
```

输出 JSON，`current` 为现有标签，`proposed` 为推导值，`changes` 为待补字段。状态：

| status | 含义 |
|---|---|
| needs_change | 可以补齐，预览没有改文件 |
| unchanged | 标签已齐全 |
| conflict | 标签冲突/合集曲序重复，未修改 |
| skipped | 编号/结构不符合规则，未修改 |
| error | 损坏、权限、同步或发布失败；检查 error 及备份记录，必要时恢复 |
| applied | 已备份并成功补标签 |

2. 检查预览符合预期后，应用到这一个合集：

```bash
docker compose -f docker-compose.nas.yml exec -T kids-catalog-backend python -m src.tag_audio --root /music --album '宝宝巴士' --apply --backup-dir /app/data/tag-backups
```

`/app/data` 已通过 kids-catalog-data named volume 持久化，而且在 MA 音频扫描目录 `/music` 之外。不需要新增挂载。备份完整复制音频，需要的额外空间约为本次实际修改文件总大小，加上一个最大音频临时副本。空间不足会报告失败并保留原文件。

返回 `run_dir`，例如 `/app/data/tag-backups/tag-run-xxxxxxxx`。记录这个路径，目录中包含原始文件及 `manifest.jsonl`。文件处理为单文件事务，不是整批全成功或全回滚。退出码 0=全部正常，1=存在错误，2=存在冲突/跳过；应同时检查 summary 和每条文件结果。

3. 在 MA 的本地文件来源执行重新扫描；已入库的旧条目如仍未更新，刷新对应条目。确认专辑页面分组、曲序和实际播放。MA 的“仅收藏”过滤可能隐藏未收藏的本地专辑。不要因为暂未显示就反复改标签。

4. 这个合集验收后，去掉 `--album` 可预览全部合集；全量应用同样需要 `--apply --backup-dir /app/data/tag-backups`。先确认扫描目录里都是要整理的 /kids 合集，避免混入其他音乐。

## 恢复原文件

使用本次输出的真实 run_dir；`--root` 必须与应用时相同（容器内保持 `/music`）：

```bash
docker compose -f docker-compose.nas.yml exec -T kids-catalog-backend python -m src.tag_audio --root /music --restore /app/data/tag-backups/tag-run-xxxxxxxx
```

恢复前检查备份 SHA256 和当前文件 SHA256：当前仍等于补标签后版本才恢复；已是原版本则返回 already_restored；文件后来又被人工编辑时拒绝覆盖。恢复不删除备份。未验证 MA 和后续编辑前，不要清理备份。

操作期间暂停向同一合集下载或使用其他标签编辑器。原子替换与哈希检查不能代替外部程序之间的全局锁。工具尚未在用户真实 NAS 音频上批量执行；本机测试不代表 MA 实际扫描验收已完成。

## 本机开发验证

```powershell
Set-Location 'F:\personal-projects\personal-web\backend\kids-catalog'
uv sync --dev
uv run python -m src.tag_audio --help
uv run python -m pytest tests -q
```

固定测试夹具位于 tests/fixtures，是 FFmpeg 生成的 0.15 秒 440Hz 合成音，不包含第三方录音。FFmpeg 仅用于验证压缩音频包未变，工具运行无需 FFmpeg。
